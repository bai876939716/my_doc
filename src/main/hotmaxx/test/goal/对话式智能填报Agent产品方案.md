# 设备报修 AI 智能填报产品方案

版本：V1.1｜日期：2026-10-30｜范围：报修表单中截图可见的门店与联系信息

## 1. 核心点

**在设备报修页面新增独立的 AI 智能填报入口。进入即确定为设备报修，先通过常用门店卡片或门店编号确定门店，再逐项补齐联系信息，最后由用户确认。**

| 项目 | 产品设计 |
| --- | --- |
| 入口 | 设备报修页面并列提供「AI 智能填报」「原表单填写」，进入 AI 后不再选择业务类型 |
| 数据隔离 | 两个入口各自维护填写状态，不共享草稿，不读取、覆盖或回填对方的未提交内容 |
| 首屏卡片 | 有可查询的常用门店数据时，展示真实门店卡片；同时提供「输入门店编号」。卡片选择直接对应门店编号，不增加业务字段 |
| 自动预填 | 查询门店资料，带出门店名、门店属性；大区、联系人、手机号码有可靠来源时预填，最终由人确认 |
| 追问条件 | 必填缺失、信息冲突、识别不确定、用户输入和枚举不匹配；格式错误或门店查询无结果时也需纠正 |
| 问答方式 | 一次只问一项；大区只能从真实枚举中选择；已知有效信息不重复问 |
| 最终确认 | 填写完成后，在聊天中展示一次确认卡，支持修改 |

### 设计原则

1. **新增入口、独立填写**：保留原表单，两端填写状态隔离，不同步、不回填。
2. **AI 预填、人确认**：来源可靠才预填，用户确认后才进入后续处理。
3. **能查不问、只问该问**：先查询再补缺，可选字段不强制追问。
4. **一次一问、枚举只能选不能编**：只展示系统合法选项；输入不匹配时引导重选。
5. **业务已确定、卡片辅助起步**：进入即为设备报修；在现有字段范围内，用常用门店卡片减少输入。
6. **确认前可修改、提交前做校验**：修改门店编号后重新查询关联信息，防止前后不一致。

## 2. 字段分类与模块归属

模块是产品整理分组；字段名称、必填标记及输入形式以截图为准。查询和预填属于产品设计，相关数据源是否可用需接入时验证，不能由截图推定已经具备接口。

| 模块 | 原字段 | 截图中的要求 / 形式 | 获取方式 | 什么时候问用户 |
| --- | --- | --- | --- | --- |
| 门店信息 | 大区 | 必填，下拉选择 | 真实大区字典；门店档案存在明确映射时可预填合法值 | 无法带出、与门店不一致，或用户输入与枚举不匹配时，展示真实选项让用户选择 |
| 门店信息 | 门店编号 | 必填，文本输入 | 常用门店卡片带入，或提取用户输入；再查询门店档案校验 | 未提供且不能确定门店时问；查不到或存在歧义时让用户纠正，不猜编号 |
| 门店信息 | 门店名 | 无必填星号，只读展示样式 | 根据门店编号查询带出 | 不让用户自行编填；查询失败先核对门店编号 |
| 门店信息 | 门店属性 | 无必填星号，只读展示样式 | 根据门店编号查询带出 | 不新增属性选择题；缺失时保留缺失状态，按原系统校验处理，不推断属性 |
| 联系信息 | 联系人 | 必填，文本输入；提示最好在店，便于对接维修师傅 | 有可靠的门店联系资料可预填，否则问用户 | 缺失或需要更换时问；登录人不直接等于现场联系人，预填也需确认 |
| 联系信息 | 手机号码 | 必填，带国家 / 地区码的手机输入；截图默认 +86 | 从对应联系人资料查询，或由用户输入 | 缺失、格式不合法或联系人变更导致号码待核实时问；不能生成号码 |
| 联系信息 | 营业时间（可不填） | 可选，文本输入 | 门店资料存在时带出，或提取用户主动提供的文本 | 不主动设为必答步骤；用户可在最终确认时补充，也可留空 |

分类汇总：

- **系统带出为主**：门店名、门店属性；有明确映射时带出大区。
- **枚举选择**：大区。手机号码的国家 / 地区码沿用现有控件选项，不另造取值。
- **按需问用户**：门店编号、联系人、手机号码；营业时间仅自愿补充。
- **AI 的作用**：从用户表达中提取上述字段，解释问题、推荐合法候选；不生成门店档案、联系人信息或枚举项。

## 3. 产品流程

**设备报修 AI 入口 → 常用门店卡片 / 输入编号 → 查询门店资料 → 补齐或纠正大区 → 补齐联系人 → 补齐手机号码 → 最终确认。**

所有已知且有效的字段直接跳过。若用户一次提供多个字段，一次提取，不要求重新逐项回答。

### 3.1 首屏：直接进入设备报修

页面标题：**设备报修 · AI 智能填报**。

有真实常用门店数据时：

> 请选择本次报修的门店。
>
> `[〈常用门店名〉 · 〈门店编号〉] [〈另一常用门店名〉 · 〈门店编号〉] [输入门店编号]`

没有可用门店数据时：

> 本次报修的门店编号是多少？

卡片内容只能来自授权范围内的实际门店数据。截图未提供故障分类，本版不设置「空调故障」「电脑故障」等卡片。门店编号按文本保存，不擅自删除前导零或改写编号。

### 3.2 查询和补缺

1. **确定门店**：从所选卡片或用户输入获取编号，查询门店名、门店属性及可用关联资料。
2. **核对大区**：存在明确映射且值属于当前字典时预填；否则展示合法选项供选择。若接口要求先选大区才能查门店，则先问大区，再查询编号。
3. **补齐联系人**：可查询到可靠信息则预填，并在最终确认中核对；没有时询问本次联系人。截图的“最好在店”是提示，不增加“必须在店”的硬性限制。
4. **补齐手机号码**：优先查询对应联系人资料；缺失才问。用户更换联系人后，原号码需重新核实。
5. **处理营业时间**：用户已提供或资料可靠则预填；否则留空，不阻塞流程。
6. **最终确认**：仅展示本次 7 个字段及修改入口；用户确认后，进入实际原业务规则要求的后续步骤。

### 3.3 追问与异常处理

| 触发条件 | AI 处理方式 |
| --- | --- |
| 必填缺失 | 每轮补一项，例如「本次联系人是谁？」 |
| 信息冲突 | 指出冲突并让用户纠正，例如所选大区与编号查询结果不一致时，先核对门店编号，再按需重选大区 |
| 识别不确定 | 只澄清不确定部分，例如「门店编号最后一位是 0 还是字母 O？」；候选须来自实际输入歧义 |
| 用户输入和枚举不匹配 | 明确提示未匹配到合法大区，展示真实候选供选择；不将近似说法自动写入大区 |
| 门店编号查询无结果 | 请用户检查编号；仍无法查询时可打开原表单，不能自造门店名或属性 |
| 手机号码格式不合法 | 按所选国家 / 地区码的规则提示重新输入，不猜缺失数字 |
| 用户更换门店编号 | 重新查询门店名、属性和大区；原门店资料带出的联系信息及营业时间失效后需更新；用户自己提供的值若仍适用可保留 |
| 用户打开原表单 | 跳转前提示「AI 填写内容不会带入原表单，请在原表单单独填写」；原表单已有内容保持原状 |

### 3.4 确认与系统边界

- AI 端仅维护自身会话填写状态；原表单状态独立。两端可调用同一套门店档案、枚举及业务校验服务，共用基础数据不代表共享填写状态。
- 最终确认卡是一次确认动作，不建设常驻草稿展示功能。用户点「修改信息」后选择要修改的字段，再逐项修改。
- 校验必填项、合法大区、门店编号有效性、大区与门店一致性、手机号码格式。业务约束以原系统实际规则为准。
- 本版剧本以「截图内信息已确认」结束。接入完整流程时，只有实际业务接口返回成功才能显示「报修提交成功」；若存在截图外必填项，应按完整表单另行补充设计，不能跳过。

## 4. 模拟对话剧本

### 4.1 主流程：门店与联系信息填写

说明：截图未提供实际取值，以下 `〈…〉` 均为运行时替换的真实查询结果或用户输入，不是新增枚举。为展示按需追问，假设门店资料可查询，但联系人及手机号码尚未获得。

**AI 首屏**：这里是设备报修智能填报，请选择本次报修的门店。  
`[〈真实常用门店名〉 · 〈门店编号〉] [输入门店编号]`

**用户**：选择常用门店卡片。

**AI**：已找到〈门店名〉，门店属性为〈系统返回的门店属性〉，大区已带出为〈合法大区名称〉。本次联系人是谁？建议填写方便在店对接维修师傅的人。

**用户**：〈联系人姓名〉。

**AI**：〈联系人姓名〉的手机号码是多少？  
`[国家 / 地区码：默认 +86，可通过原有选项调整] [手机号码输入]`

**用户**：〈有效手机号码〉。

**AI 最终确认卡**：请核对本次填写的信息。

| 原表单字段 | 本次内容 |
| --- | --- |
| 大区 | 〈系统带出的合法大区名称〉 |
| 门店编号 | 〈所选门店编号〉 |
| 门店名 | 〈系统返回的门店名〉 |
| 门店属性 | 〈系统返回的门店属性〉 |
| 联系人 | 〈用户提供的联系人姓名〉 |
| 手机号码 | 〈国家 / 地区码及用户提供的号码〉 |
| 营业时间（可不填） | 未填写 |

`[确认信息] [修改信息] [补充营业时间]`

**用户**：确认信息。

**AI**：门店与联系信息已确认。

> 本段仅覆盖截图所示信息，不表示完整报修已提交。若已有可靠联系人及号码，直接预填并进入最终确认，无需重复上述问题。正式交互中的确认与修改按钮为本方案设计，不声称截图中已存在这些按钮。

### 4.2 分支：用户输入与大区枚举不匹配

触发前提：门店资料无法明确带出大区，需要用户选择。

**AI**：请选择门店所属的大区。  
`〈展示现有系统返回的大区选项〉`

**用户**：〈不在大区字典中的说法〉。

**AI**：这个说法没有匹配到系统中的大区，请从以下选项中选择。  
`〈再次展示真实选项；列表较长时支持搜索〉`

**用户**：点击〈合法大区选项〉。

**AI 处理**：记录所选枚举 ID，检查与门店编号是否一致；通过后继续询问下一个缺项。没有匹配项时不编造「其他」选项，也不强行选择最接近的值。

### 4.3 分支：自愿补充营业时间

**用户**：点击「补充营业时间」。

**AI**：门店的营业时间是什么？这项可不填。  
`[文本输入] [跳过]`

**用户**：〈营业时间文本〉。

**AI**：已补充营业时间，请再次核对。  
`〈重新展示包含更新值的最终确认卡〉`

营业时间按原字段保存为文本，不改造成预约上门时段，也不新增开始时间、结束时间字段。
