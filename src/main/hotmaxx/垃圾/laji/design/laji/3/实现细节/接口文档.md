# 接口文档 · H5 ↔ Agent 服务

> **版本**：v1.1（2026-11-04 · 新增 §5 场景示例）｜**协议变更规则**：本文档是 H5 ↔ Agent 消息契约的唯一真值，新增/修改字段或 type 须前后端双方确认后同步本文档；type 只描述「手势/消息种类」，与前端组件实现解耦。
> 上线前 TODO：真实域名、token 签发方式（复用 App 登录态）。

## 0. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | `https://{gateway-host}/agent/repair/v1`（经公司网关转发；网关按 `/agent/**` 路由到 Agent 服务，是否 StripPrefix 与平台组确认） |
| 版本 | `/v1` 属于业务（报修技能包）：各业务独立升版（报销为 `/agent/expense/v1`）；仅 H5 ↔ Agent 消息协议破坏性变更时升版本号，字段新增一律 v1 内兼容 |
| 内容类型 | 请求/响应 `application/json; charset=utf-8`；SSE 响应 `text/event-stream` |
| 鉴权 | `Authorization: Bearer <token>`（App 登录态，网关校验后注入 `HTM-HEADER`） |
| 时间格式 | `yyyy-MM-dd'T'HH:mm:ss+08:00` |
| 并发 | 同一会话**不做多端并发控制**（后写覆盖先写，属已知简化；单用户单会话场景）；防重复提交由服务端 order_key 幂等保证 |

**错误响应体**（所有非 2xx 统一结构）：

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 业务错误码，见 §3 |
| message | string | 人话描述，前端可直接 toast |

## 1. 接口总览

| # | 接口 | 方法 | 用途 |
|---|---|---|---|
| 1 | `/agent/repair/v1/sessions` | POST | 建会话 / 恢复入口 |
| 2 | `/agent/repair/v1/sessions/{id}/messages` | POST | 用户消息（响应 = SSE 流） |
| 3 | `/agent/repair/v1/sessions/{id}/upload` | POST | 附件上传（multipart） |
| 4 | `/agent/repair/v1/sessions/{id}` | GET | 会话内刷新 / SSE 断线重连 |
| 5 | `/agent/repair/v1/sessions/{id}/submit` | POST | 确认提交 |
| 6 | `/agent/repair/v1/sessions/{id}/exit` | POST | 主动退出 |

## 2. 接口明细

### 2.1 建会话 / 恢复入口 —— `POST /agent/repair/v1/sessions`

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| store_no | string | 否 | 门店编号；默认取登录人绑定门店，督导多店时显式指定 |

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| session_id | string | 会话 ID（`rp_` 前缀），后续接口路径参数 |
| is_resumed | boolean | true=复用了活跃会话（前端弹「继续上次报修」卡片） |
| context | object | 系统带出字段：`store`(string 门店名含编号) / `reporter`(string 报修人) / `date`(string 报修日期) / `phone_masked`(string 掩码电话) |
| messages | array | 首屏消息序列，**按 seq 顺序渲染**；元素结构见 §2.2 服务端消息 |

```json
{ "session_id": "rp_9f3k2m", "is_resumed": false,
  "context": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "date": "2026-11-04", "phone_masked": "138****1234" },
  "messages": [
    { "seq": 1, "type": "status_bar", "data": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "phone_masked": "138****1234" } },
    { "seq": 2, "type": "text", "data": { "content": "白云翔你好！直接说哪儿坏了就行，比如「冷柜不制冷了，今天早上开始的」" } },
    { "seq": 3, "type": "quick_cards", "data": { "cards": [ { "id": "c_cool", "icon": "❄️", "title": "冷柜/空调不制冷" } ] } }
  ] }
```

### 2.2 发消息 —— `POST /agent/repair/v1/sessions/{id}/messages`（响应 = SSE 流）

**请求公共字段**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| type | string | 是 | 手势类型，六种（见下）；只有 `text` 走 LLM，其余为结构化事件 |
| （其余字段） | — | — | 按 type 见下表 |

**用户消息 type 6 种**（`submit` 走独立接口 §2.5，不经 messages）：

| type | 附加字段 | 类型 | 说明 |
|---|---|---|---|
| `text` | content | string ≤500 | 一切打字：描述 / 补充 / 改字段 |
| `card` | card_id | string | 高频卡片 ID（B 路径，类别直锁） |
| `enum_pick` | value | string | 枚举点选值（必须字典内）；**CONFIRM 态收到 = 确认单重选类别**，状态机按 recat 回跳 |
| `seg_pick` | field / value | string / string | field ∈ `expect_visit`｜`impact_business`；同一手势复用，状态机按当前状态解释 |
| `upload_done` | media_ids | array\<string\> | 上传完成通知（先调 §2.3 拿 media_id） |
| `phone` | use_default 或 phone | boolean / string | 二选一：用本人号码 / 提交新号码（11 位正则校验） |

**SSE 事件规范**：

| event | data 结构 | 说明 |
|---|---|---|
| typing | `{}` | 收到请求立即下发，前端显示"输入中" |
| message | `{ "seq": int, "type": string, "data": object }` | 0..n 条；data 按 type 见下表 |
| done | `{ "state": string }` | 终止事件；state 见 §4 枚举 |
| （注释行） | `: ping` | 每 15s 一条心跳，防中间层掐连接 |

**服务端消息 type 10 种（message.data 结构）**：

| type | data 字段 | 类型 | 说明 |
|---|---|---|---|
| `status_bar` | store / reporter / phone_masked | string ×3 | 顶部状态条 |
| `text` | content | string | 对话气泡（模板话术） |
| `quick_cards` | cards[].id / icon / title | string ×3 | 高频卡片墙 |
| `enum_card` | mode / options[] / preselect | string / array\<string\> / int | mode ∈ `top3`｜`full`；preselect=预选下标（-1 无）；**仅限点选** |
| `photo_guide` | need_count / tips[].text / tips[].level / warning | int / string / `info`｜`warn` / string? | 拍摄清单；warning 非空时红色警示（如购物袋拍袋底供应商标识） |
| `system_tip` | content / level | string / `info`｜`warn`｜`error` | 系统提示条（非对话语气） |
| `seg_card` | field / question / options[].value / options[].label | string ×4 | 二选一卡（期望上门/影响营业复用） |
| `phone_confirm` | phone_masked / use_default | string / boolean | 电话确认卡 |
| `confirm_card` | groups[].group_name / groups[].items[].field·label·value·editable·source / missing[] | — / string ×5 / array\<string\> | 10 字段确认单；source ∈ `system_default`｜`ai_filled`｜`user_edited`；missing=缺失字段提示 |
| `result` | order_no / status / tip | string ×3 | 结果卡（单号/状态/跳记录页提示文案） |

### 2.3 上传附件 —— `POST /agent/repair/v1/sessions/{id}/upload`

**请求**：`multipart/form-data`，字段 `files[]`（image/* 或 video/*，单文件 ≤10MB，单会话 ≤5 个）。

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| media_ids | array\<string\> | 附件 ID，供 `upload_done` 消息引用 |
| urls | array\<string\> | 预览地址（OSS 临时链接） |

### 2.4 恢复会话 —— `GET /agent/repair/v1/sessions/{id}`

**响应 200**：结构同 §2.1，另增：

| 字段 | 类型 | 说明 |
|---|---|---|
| state | string | 当前状态机状态（§4 枚举），前端据此渲染当前步骤 |
| collected | object | 已采集槽位（含 source），确认单/回显用 |

404 = 会话不存在 / 已过期 / 已废弃 → 前端静默开新会话。

### 2.5 提交 —— `POST /agent/repair/v1/sessions/{id}/submit`（仅 CONFIRM 态接受）

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| order_no | string | 报修单号（明道云返回） |
| status | string | 工单状态（如「已提交 / 待派单」） |

服务端流程：10 字段必填校验（B 路径描述自动补默认值）→ `create_repair_order`（order_key 幂等）→ 清 Redis 草稿 → MySQL 归档。

### 2.6 主动退出 —— `POST /agent/repair/v1/sessions/{id}/exit`

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| mode | string | 是 | `keep`=保存草稿（7 天可续）｜`abandon`=放弃本次报修 |

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| result | string | 固定 `ok` |
| draft_expired_at | string | keep 时返回，草稿过期时间；abandon 不返回 |

## 3. 错误码

| code | HTTP | 场景 | 前端行为 |
|---|---|---|---|
| 40101 | 401 | token 无效/过期 | 引导重新登录 |
| 40401 | 404 | 会话不存在/过期/废弃 | 静默开新会话 |
| 42201 | 422 | 提交字段校验失败 | 收 confirm_card，高亮 missing 字段 |
| 42901 | 429 | 当日 LLM 配额用尽 | 收 system_tip，降级卡片向导 |
| 50301 | 503 | LLM 不可用 | 降级卡片向导 / 引导回表单 |

## 4. 枚举字典

**会话状态 state（12）**：`INIT` / `A_DESC` / `A_ENUM` / `B_LOCK` / `PHOTO` / `EXPECT` / `IMPACT` / `PHONE` / `CONFIRM` / `DONE` / `EXITED` / `FALLBACK`

**seg_pick.field（2）**：`expect_visit`（期望上门）｜`impact_business`（影响营业）

**enum_card.mode（2）**：`top3`（AI 候选）｜`full`（FALLBACK 全量）

**槽位 source（3）**：`system_default`｜`ai_filled`｜`user_edited`

## 5. 场景示例

> 按 H5 真实交互时序串联的完整报文流，字段与 §2/§4 枚举一一对应。
> 通用约定：`seq` 全会话单调递增；SSE 三事件 `typing / message / done`，每 15s 一条 `: ping` 心跳（注释行，前端忽略）；出参手机号一律掩码。
> URL 已定稿：服务前缀 `/agent` + 业务二级 `/repair` + 版本 `/v1`（版本随业务技能包独立演进，报销为 `/agent/expense/v1`）。

### 5.3 场景三 · 断点恢复（杀 App 后重进 / 主动退出 keep 后重进）

统一入口 `POST /agent/repair/v1/sessions`（不带本地 session_id，恢复不依赖前端缓存）：

```json
{
  "session_id": "rp_9f3k2m",
  "is_resumed": true,
  "context": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "date": "2026-11-04", "phone_masked": "138****1234" },
  "messages": [
    { "seq": 12, "type": "confirm_card", "data": { "...": "会话内已产生的消息按 seq 重放" } },
    { "seq": 13, "type": "text", "data": { "content": "检测到未完成的报修（工程类 - 制冷设备/冷柜），继续上次填写？" } }
  ]
}
```

前端弹「继续上次报修」卡片；用户确认后按快照渲染界面。

会话内刷新 / SSE 断线重连：`GET /agent/repair/v1/sessions/rp_9f3k2m`——结构同上，另含 `state`（当前状态机状态）与 `collected`（已采集槽位含 source）；404（code 40401）时前端静默开新会话：

```json
{ "state": "PHOTO", "collected": { "category": "工程类 - 制冷设备/冷柜", "photos": ["m_001"] } }
```

### 5.4 场景四 · 随时可改（任意状态打字，状态不变）

在 EXPECT 态打字改电话：

```json
{ "type": "text", "content": "电话换成店长的 13900005678" }
```

```
event: typing
data: {}

event: message
data: {"seq":13,"type":"text","data":{"content":"已把联系电话更新为「139****5678」，继续当前的步骤就行。"}}

event: done
data: {"state":"EXPECT"}
```

> `done.state` 与改前相同——改普通字段原地覆盖槽位、**不回退流程**；快照已更新（先存再推）。

CONFIRM 态重选类别（例外，回跳）：发 `{"type":"enum_pick","value":"工程类 - 照明/招牌"}` → 状态机按 recat 处理 → `done` 返回 `{"state":"PHOTO"}`（照片要求可能变化，联动重校验）。

### 5.5 场景五 · 异常与降级

**提交缺字段（422）**——`POST /submit` 时照片缺失：

```json
HTTP/1.1 422
{ "code": 42201, "message": "还有 1 项没填：现场照片" }
```

前端留在 CONFIRM 态高亮缺失项（或按 §3 错误码表收 confirm_card.missing）。

**会话 LLM 次数超限（429 → 降级卡片向导）**——打字消息仍返回 SSE，但不再调 LLM：

```
event: message
data: {"seq":14,"type":"system_tip","data":{"content":"AI 手速有点慢，先用卡片点选填，一样能交单","level":"warn"}}

event: message
data: {"seq":15,"type":"enum_card","data":{"mode":"full","options":["（全量类别列表，来自字典）"],"preselect":-1}}

event: done
data: {"state":"FALLBACK"}
```

**LLM 服务不可用（503）**：

```json
HTTP/1.1 503
{ "code": 50301, "message": "AI 暂时不可用，已切换为卡片填报" }
```

**明道云提交失败（待发表机制）**——❗错误码 50302 建议新增（明道云提交失败-已转待重试），评审确认后补入 §3 表：

```json
HTTP/1.1 503
{ "code": 50302, "message": "提交暂时失败，已记录自动重试；紧急请联系客服 400-xxx-xxxx" }
```

### 5.6 场景六 · 主动退出

keep（保存草稿）：

```json
POST /agent/repair/v1/sessions/rp_9f3k2m/exit
{ "mode": "keep" }
→ 200 { "result": "ok", "draft_expired_at": "2026-11-11T09:41:00+08:00" }
```

abandon（放弃）：

```json
{ "mode": "abandon" }
→ 200 { "result": "ok" }
```

abandon 后再 `GET /agent/repair/v1/sessions/rp_9f3k2m` → 404 `{"code":40401,"message":"会话不存在或已废弃"}`，前端静默开新会话。

### 5.7 前端联调自查清单

| 检查项 | 口径 |
|---|---|
| seq 连续性 | 每条 message.seq 严格递增；重连后从快照重放不重不漏 |
| SSE 事件 | 只有 typing / message / done 三种 event；`: ping` 心跳按注释行忽略 |
| 状态一致性 | 每条 done.state 与前端当前步骤对应；改字段消息的 done.state 不变 |
| 手机号 | 任何出参不出现完整手机号（掩码 138\*\*\*\*1234）；入参 phone 走 11 位正则 |
| 枚举值 | enum_card.options / seg_pick.value 全部来自服务端字典，前端不自持枚举 |
| 幂等 | submit 重复点击只产生一个 order_key；重试返回同一单号 |
