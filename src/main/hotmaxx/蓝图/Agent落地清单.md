## 一、落地清单（按重要程度排序 · M1 → M10）

### M1 Agent 核心引擎（最核心，区分 Demo 与落地的关键）

| # | 子项 | 说明（贴合报修填表） | 是否完成 |
|---|---|---|---|
| M1.1 | 状态管理 ⭐ | 业务状态机为主：字段级状态（未收集/已收集/待确认/校验失败）、字段值、来源、修改记录；LLM 只做语言理解，不掌控流程 | ☐ |
| M1.2 | 解析器 | 自然语言 → 结构化字段；一句话同时填多个字段（描述→现象/时间/影响范围） | ☐ |
| M1.3 | 校验器 | 基础校验（类型/长度/正则/必填/枚举白名单）+ 业务校验（门店编码存在性，调接口）；不通过生成澄清话术 | ☐ |
| M1.4 | 人工确认 HITL | 确认卡片必须人工点【确认提交】才入库；支持暂停、驳回、修改 | ☐ |
| M1.5 | 规划器 Planner | 报修填表用规则化规划（字段依赖顺序）；复杂场景预留 ReAct / Plan-and-Execute | ☐ |
| M1.6 | 自省复核 Self-Check | 收集完自查：矛盾字段、推测值、不确定项标出给用户确认 | ☐ |

## 二、实施顺序计划

> 原则：**先跑通核心链路（MVP）→ 再生产加固 → 再运营化 → 最后演进**。不是 10 个模块平均用力：LLM/提示词 ≈ 30%，业务对接/状态机/校验/幂等 ≈ 40%，监控/权限/审计/运维 ≈ 30%。

| 阶段 | 目标 | 涉及条目 | 出口标准 |
|---|---|---|---|
| **P0 方案定稿** | 产品 + 技术方案冻结 | 前置：FA.md 定稿、技术方案评审通过 | 11.5 评审通过 |
| **P1 核心链路 MVP** | 端到端可演示 | M1.1~M1.5（自省 M1.6 除外）；M2.1、M2.2、M2.3；M3.1；M4.1、M4.2（最小网关）；M5.1、M5.2；M6.1；M7.1、M7.2 | 对话 → 预填确认 → 提交入库走通（11.16） |
| **P2 生产加固** | 稳定可上线（灰度形态一） | M1.6；M2.4；M3.2；M4.3、M4.4（照片 OCR）；M5.3；M6.2；M8.1、M8.2、M8.3；M9.1、M9.2、M9.3 | 灰度放量、指标稳定 |
| **P3 运营化** | 不改代码可运营 | M10.1、M10.2、M10.3；M6.3、M6.4；M8.4；M9.4；M7.3 | 运营可自主改话术/字段/提示词 |
| **P4 演进** | 对应 FA.md §十路线 | 报销表单接入（M10.1 加配置）→ 对话查询闭环 → 其他智能体 → 多智能体 | 报销智能体上线 |

**勾选节奏建议**：P0 结束后先把 P1 条目全部过一遍评审口径；P1 期间清单每周勾一次；P2 上线前 M8/M9 相关条目必须全部 ✅ 才允许放量。
