#  门店报修 


## 一、背景与目标

### 1.1 背景

- 显示器的报修目前不在 App 里。
- App 现有「我要报修」已覆盖三大类 30 项，并已上线 AI 智能填报，但没有 IT 类。


### 1.2 痛点
#### 门店
- 群太多， 反馈不方便  消息内容不好跟踪 
- 填一个比较重的表单，字段多，手填容易出错
- 群是内咨询、催办、核对身份、报价全在群里靠人肉匹配。
#### 运维
- 处理用户抱怨情绪，信息、序列号填不对，要沟通指导
- 群身份要和表单对、消息内容不清晰 缺少带身份的入口 
- 门店问题并发上来，太多忙不过来，没办法及时回复

### 1.3 目标

| # | 目标                                     | 衡量方式                 |
|---|----------------------------------------|----------------------|
| 1 | 门店在**同一个报修入口**完成 IT 设备报修，不再用独立表单、不在群里报 | IT 类报修 100% 从 App 提交 |
| 2 | IT 报修门店只多填项（设备序列号），其余沿用现有报修            | 门店手填字段数；单次填写时长       |
| 4 | IT 单进入统一的状态流转，运维有审核依据，门店能看到进度          | 状态回填                 |

## 二、核心设计点

| # | 原则                 | 落地方式                                                        |
|---|--------------------|-------------------------------------------------------------|
| 1 | **入口不变、tab 不变**    | 不新增「IT 报修」入口。首页「我要报修」卡片、表单页、AI 对话都是现有的，只把描述里的类别说明补上「IT 设备类」 |
| 2 | **一个新的大类**         | 报修类别字典新增「IT设备类」，下面三项：电脑、手机、显示器                              |
| 3 | **切类别加字段**         | 表单页选到 IT 类别，才在「报修类别」下方带出 设备序列号； AI 对话选到 IT 类别才多问          |
| 4 | **非 IT 完全不变**      | 其他三大类的表单、对话话术、追问顺序与现在逐项一致，回归测试按此验证                          |
| 5 | **IT 单走运维审核**      | 明道云工作流新增分支：大类 = IT设备类 → 运维审核节点 → 派单给供应商                     |

## 四、交互流程


### 关键环节

1. **首页**：「我要报修」卡片不动。
2. **表单页**：
    - 选到 IT 类别，在「报修类别」这一行正下方带出：「设备序列号」 。
    - 改回其他类别，两行收起，已填内容清空。
3. **AI 对话首屏**：开场白不变，高频卡片从 6 张增加到 7 张。
4. **类别确认**：沿用现有规则，自由描述给 Top3，识别不出给全量列表；点卡片即类别。
5. **IT 追加一步**： → 序列号。然后回到现有的电话确认。
6. **确认单**：IT 单比普通单多一行，都可以点开修改。

### 4.1 高频卡片怎么放 IT

现有 6 张是按线上全量 2.8 万单的频次定的（照明灯 17%、门头字 8%、开关插座 6%、冷柜 6%、摄像头 3%、灭火器 3%），**不动**。在后面新增一张：

| 卡片   | 对应类别         | 说明                 |
|------|--------------|--------------------|
| IT设备 | 电脑 、 手机、 显示器 | 点卡像 灯类一样 二次确认 |


显示器不单独占卡，量小，走打字或在全量类别里选。卡片墙从 3 行变 4 行，首屏多出约 130 像素。

IT 类的实际单量占比目前没有数据【待确认】。上线后看两张卡的点击量：合计占比低于 3% 的话，考虑合并成一张「电脑 / 手机」卡，点开再选设备。

## 五、页面规则明细

### 5.1 表单页

| 场景 | 行为 |
|---|---|
| 未选类别 | 与线上一致，没有额外字段 |
| 选 IT 类别 | 在「报修类别」正下方带出「故障现象」「设备序列号」两行 |
| 故障现象 | 点开底部选择器，选项随设备类型变化，单选 |
| 设备序列号 | 直接输入。下方两个文字入口：「怎么找？」按设备类型给出查看方法并可手动输入；「找不到序列号」点击后标记，输入框禁用，再点取消 |
| 从 IT 改成其他类别 | 两行收起，现象与序列号清空 |
| 提交校验（从上到下） | 类别必选；IT 时现象必选、序列号必填或已标记找不到；描述必填；照片至少 1 张；期望上门、影响营业、联系电话必填 |

### 5.2 AI 对话

**追问顺序**：类别 →（IT：现象）→ 照片 →（IT：序列号）→ 电话 → 确认单。非 IT 类别跳过括号里的两步，顺序与现在一致。

## 八、兜底与异常

| 场景         | 处理 |
|------------|---|
| 序列号填了但格式不对 | 前端即时提示「看着不像序列号，请核对标签」；允许勾选「找不到」继续 |
| 运维驳回(todo) | 门店收到原因，单据回到「待补充」，修改后重新提交 |
| AI 服务不可用   | 沿用现有处理：提示并引导回表单，表单路径照常可提交 IT 单 |
| 明道云控件未就绪   | IT 类别在前端隐藏，字典不发布；不出现「能选但提交失败」 |

## 九、度量指标

在现有指标基础上增加：

| 指标 | 定义 |
|---|---|
| IT 报修单量与占比 | 按设备类型分；与高频卡点击量对照 |
| IT 入口渗透率 | IT 单中 AI 填报占比、表单填报占比 |
| 序列号一次通过率 | 提交后未被运维因序列号驳回或补录的单占比 |
| 序列号「找不到」占比 | 标记找不到的单 / IT 单总数 |
| 故障现象选「其他」占比 | 过高说明选项需要调整 |
| 两张 IT 卡的点击率 | 点击量 / 对话首屏曝光；用于判断是否合并 |
| 审核响应时长 | 按表单「影响营业」是否分开统计 |
| 群消息量 | 门店报修群里与 IT 报修相关的消息数，对比上线前后 |

## 十一、验收标准

- [ ] 首页卡片、表单页布局、tab 与现在一致，没有新增入口
- [ ] 类别选择器出现「IT设备类」及电脑 / 手机 / 显示器
- [ ] 表单页面与线上一致（两张卡片、字段、底部「提交」）；选 IT 类别后在报修类别下方出现两行；改回其他类别后两行消失且内容清空
- [ ] 表单校验符合 5.1；缺项时有明确提示
- [ ] 「期望上门」「影响营业」「联系电话」对所有类别的行为与现在一致
- [ ] AI 对话首屏 8 张卡，原 6 张内容与行为不变
- [ ] 一句话报电脑：类别 Top3 首位是 IT；现象推荐命中原话
- [ ] 非 IT 类别的对话剧本逐句与现状一致；对话全程不出现「影响营业」
- [ ] 从 IT 改成非 IT 后，确认单不再出现两个 IT 字段
- [ ] 标记「找不到序列号」可以提交，单据上有待补录标记
- [ ] 提交后明道云单据里故障现象、设备序列号有值且正确，类别落在「IT设备类」
- [ ] IT 单进入运维审核节点；非 IT 单的工作流不受影响
- [ ] 报修记录和详情能看到设备、现象、序列号
- [ ] AI 服务不可用时，表单路径可以完成 IT 报修

## 十二、灰度与后续规划

**灰度**：先在 1–2 家门店加运维团队内部试用一周，核对明道云字段和工作流，再按现有报修的放流节奏扩大。

**后续**（按依赖顺序）：

1. 序列号拍照识别：依赖标签照片样本和多模态识别，识别结果仍需用户确认
2. 运维审核工作台：待办列表、一键通过、驳回原因、超时提醒
3供应商回写与报价确认线上化：接单、完成、报价由供应商或运维更新，门店在 App 内确认费用
