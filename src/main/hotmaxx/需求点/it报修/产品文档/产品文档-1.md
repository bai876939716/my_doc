#  门店报修 

## 一、背景与目标

### 1.1 背景

- 显示器的报修目前不在 App 里。
- App 现有「我要报修」已覆盖三大类 30 项，并已上线 AI 智能填报，但没有 IT 类。


### 1.2 痛点
#### 门店
- 群太多， 反馈不方便  消息内容不好跟踪 
- 填一个比较重的表单，字段多，手填容易出错
- 群内咨询、催办、跟踪进度（爬楼）全在群里。
#### 运维
- 处理用户抱怨情绪，信息、序列号填不对，要沟通指导
- 群身份要和表单对、消息内容不清晰 缺少带身份的入口 
- 门店问题并发上来，太多忙不过来，没办法及时回复

### 1.3 目标

| # | 目标                                     | 衡量方式                 |
|---|----------------------------------------|----------------------|
| 1 | 门店在**同一个报修入口**完成 IT 设备报修，不再用独立表单、不在群里报 | IT 类报修 100% 从 App 提交 |
| 2 | IT 报修门店只多填项（设备序列号），其余沿用现有报修            | 门店手填字段数；单次填写时长       |
| 3 | IT 单进入统一的状态流转，运维有审核依据，门店能看到进度          | 状态回填                 |

## 二、核心设计点

| # | 原则                 | 落地方式                                                        |
|---|--------------------|-------------------------------------------------------------|
| 1 | **入口不变、tab 不变**    | 不新增「IT 报修」入口。首页「我要报修」卡片、表单页、表单页顶部的「AI 智能填报」入口卡都是现有的，只把描述里的类别说明补上「IT 设备类」 |
| 2 | **一个新的大类**         | 报修类别字典新增「IT设备类」，下面三项：电脑、手机、显示器                              |
| 3 | **切类别加字段**         | 表单页选到 IT 类别，才在「报修类别」下方带出「设备序列号」；AI 对话选到 IT 设备，才多问「故障情况」「设备序列号」两步 |
| 4 | **非 IT 完全不变**      | 其他三大类的表单、对话话术、追问顺序与现在逐项一致，回归测试按此验证                          |
| 5 | **IT 单走运维审核**      | 明道云为 IT 单新增三个状态：待运维审核 → 待供应商维修 → 已完结（不通过进「被驳回」）。运维在流程节点上推进；费用环节不进状态 |

## 三、字段：IT 类别带来的增量

> 现有报修的字段及获取策略不变。线上表单一共 7 项：门店名称、报修类别、报修人员、报修日期、描述具体故障、现场照片、联系电话。「期望上门」「影响营业」已全链路取消，所有类别都不再采集。

| 字段 | 表单页 | AI 对话 | 必填 | 规则 |
|---|---|---|---|---|
| **报修类别** | 类别选择器最下面多一个大类「IT设备类」（原表单这一行不变） | 高频卡墙里「灭火器」那张换成「电脑/手机/显示器」（下称 IT 卡），点开三选一；打字后给出的候选卡和全量类别列表里出现 IT 项 | 是 | 取值 `IT设备类 - 电脑` / `手机` / `显示器`。原话含「电脑」「手机」「显示器」且唯一命中时按现有规则直接登记，免点选 |
| **故障情况**（现有字段，IT 多问一步） | 不变，仍是「描述具体故障」 | 【新增】点 IT 卡、选完设备后追问一句，给 4 个常见现象按钮，下面另留一条通栏的「其他」；点常见现象等于替用户说这句话，原文进「故障情况」；点「其他」不填内容，光标回到输入框，用户自己说。打字路径沿用现状，原话照抄 | 是 | ≤100 字，逐字照抄用户原话。非 IT 类别点高频卡不问（现状：系统默认填“类别，详见现场照片”） |
| **设备序列号** | 选到 IT 类别后带出的一行，行首「?」看怎么找，行尾「找不到」做标记 | 序列号卡：右上角「怎么找」、填写序列号、找不到，继续 | 是（仅 IT；可标记找不到） | 去掉首尾空格，6–40 位字母、数字、连字符【待确认：两家供应商的序列号格式】。同一序列号 7 天内有未完结单时提示，可选继续。标记「找不到」可以提交，单上带标记，运维审核时补录 |

三个名字指同一个东西，不改名：表单上叫「描述具体故障」，对话确认单上叫「故障情况」，明道云控件叫「报修详情」。

### 3.1 常见现象按钮（原「故障现象选项」）

不做单选字典，只是把用户最常说的几句话做成按钮。每种设备取 4 个（加粗），两行排开；最下面固定留一条通栏的「其他」——四个都对不上时点它，光标回到输入框，用户自己说一句，这句话原文进「故障情况」。其余说法作为候选，上线后按真实单量调整【待确认：IT 历史单量与故障分布】。

| 电脑 | 手机 | 显示器 |
|---|---|---|
| **开不了机 / 自动关机** | **碎屏 / 屏幕显示异常** | **不亮 / 黑屏** |
| **蓝屏、报错** | **无法开机** | **花屏、闪屏、线条** |
| **卡顿、死机** | **充不进电、耗电快** | **颜色异常** |
| **无法联网** | **系统卡顿、闪退** | **接口松动、无信号** |
| 黑屏、无显示 | 无法联网 | |
| 键盘鼠标失灵 | 声音、听筒异常 | |
| 软件问题（收银系统等） | | |

通栏一行，三种设备相同：✎ 其他（自己描述）

## 四、交互流程

现状流程图：[diagrams/01-现状流程图.puml](diagrams/01-现状流程图.puml)

### 关键环节

1. **首页**：「我要报修」卡片不动。
2. **表单页**：
    - 选到 IT 类别，在「报修类别」这一行正下方带出「设备序列号」。
    - 改回其他类别，这一行收起，已填内容清空。
    - 底部「提交」不动。
3. **AI 对话首屏**：顶部状态条（📍 门店 ｜ 报修人 · 电话）、开场白都不变；高频卡片仍是 6 张、两列三行：「灭火器」换成「电脑/手机/显示器」，首屏高度不变。
4. **选设备**：点 IT 卡后出三选一（电脑 / 手机 / 显示器），用的是线上现成的子选项机制（和照明灯分两档一样）。
5. **故障情况**【新增】：选完设备追问一句，带 4 个常见现象按钮和一条通栏「其他」（点了直接打字）。
6. **照片**：沿用现有拍照引导，IT 类别的建议拍摄清单不同。
7. **序列号**【新增】：序列号卡，卡头右上角「怎么找」（按设备给两步查看方法），卡上一行写在哪找，可以填、可以标记找不到。
8. **电话**：回到现有的电话确认。
9. **确认单**：IT 单比普通单多一行「设备序列号」，每一项都可以点开修改。提交后出结果卡。

### 4.1 高频卡片怎么放 IT

现有 6 张是按线上全量 2.8 万单的频次定的（照明灯 17%、门头字 8%、开关插座 6%、冷柜 6%、摄像头 3%、灭火器 3%）。这次把第 6 张「灭火器」换成 IT，卡片仍是 6 张、两列三行，样式和首屏高度都不变：

| 卡片   | 对应类别         | 说明                 |
|------|--------------|--------------------|
| 💻 电脑/手机/显示器 | IT设备类：电脑、手机、显示器 | 点后出三选一，点设备即定类别；用户气泡记「🖱 电脑/手机/显示器」 |

一张卡就够：子选项卡最多放 3 项，三种设备正好。卡片文案直接写设备名，不加「IT设备-」前缀，和旁边几张卡的长短一致。

灭火器不再占卡位，但仍能报：打字带「灭火器」会直接登记类别，也可以从全量类别列表里点选。IT 类的实际单量占比目前没有数据【待确认】。

## 五、页面规则明细

### 5.1 表单页

| 场景 | 行为 |
|---|---|
| 未选类别 | 与线上一致，没有额外字段 |
| 选 IT 类别 | 在「报修类别」正下方带出「设备序列号」一行 |
| 设备序列号 | 直接输入。行首「?」弹出两步查看方法（按设备）；行尾「找不到」点击后标记，输入框换成“已标记找不到，运维协助核对”，再点取消标记 |
| 从 IT 改成其他类别 | 这一行收起，序列号与标记清空 |
| 提交校验（从上到下） | 类别必选；IT 时序列号必填或已标记找不到；描述具体故障必填；照片至少 1 张；联系电话必填 |

各设备查看序列号的方法【待确认：与运维核对口径，电脑型号只有两种，可以直接写具体位置】。表单页「?」和对话里「怎么找」弹出的是同一份内容，按设备写两步（表单页弹窗底部按钮是「知道了」）：

| 设备 | 一行位置提示（写在卡上 / 填写框里） | 弹窗里的两步 |
|---|---|---|
| 电脑 | 在主机侧面或底部的标签上 | ① 看主机侧面或底部 ② 找到贴在那里的标签，抄下序列号 |
| 手机 | 在设置的设备信息里 | ① 打开手机设置，进入设备信息 ② 查看序列号；开不了机时，看机身背面或包装盒 |
| 显示器 | 在背面的铭牌上 | ① 看显示器背面 ② 找到铭牌抄下序列号，注意别抄成主机的 |

弹窗末尾固定一句：标签脱落或看不清？关掉这个窗口，点「找不到，继续」，运维会协助核对。是否配实拍示意图【待确认】。

### 5.2 AI 对话

**两条进入路径**（线上已有，不改）：

| 路径 | 怎么进来 | 经过哪些步骤 |
|---|---|---|
| 点卡路径 | 点首屏的高频卡 | 高频卡 →（带子选项的先选细分/设备）→【IT：故障情况】→ 照片 →【IT：序列号】→ 电话 → 确认单 |
| 打字路径 | 自己打字描述故障 | 一句话 → 故障情况记下、类别给出 Top3 或直接登记 → 照片 →【IT：序列号】→ 电话 → 确认单 |

括号里的两步只在 IT 类别出现，非 IT 类别跳过，顺序与现在一致。

**对话里线上已有的行为，IT 单同样适用**：

| 场景 | 行为 |
|---|---|
| 原话带设备名（“收银电脑开不了机”） | 字典词唯一命中，直接登记类别并复述，不用点选 |
| 说的不是字典词（“机器开不了机”） | 出 Top3 卡让用户点；完全没把握就给全量类别列表。类别只能点选，AI 不替用户定 |
| 确认单上改类别 | 弹两级联动重选；照片不删，只提示自查；换成 IT 类别会补问故障情况和序列号，换回其他类别这两项作废 |
| 跑题、问进度 | 应和一句并拉回报修，然后把当前该做的事（卡片）重新放到屏幕最下面 |
| 连续点不出选项 | 连续 15 轮没进展降级成纯点卡向导，照样能交单 |
| 点返回 | 三选一：继续填写 / 存草稿离开（保留 7 天）/ 放弃本次 |
| 提交失败 | 提示“单子没递上去，稍等一下再点次提交”，确认单留着可重试 |
| AI 服务不可用 | 沿用现有处理；表单路径照常可提交 IT 单 |

**【新增】故障情况追问卡**（只在 IT 的点卡路径出现）：气泡问一句「{设备}出什么问题了？点下面的常见现象，或者直接说。」，卡上 4 个常见现象按钮两行排开，最下面一条通栏「其他」。点常见现象 = 替用户说这句话，用户气泡显示按钮文字，原文进「故障情况」；点「其他」不填内容、不回发服务端，助手回一句「用一句话说说故障情况，我来整理成报修描述。」并把光标放到输入框，之后打字的内容按现有 text 消息处理，常见现象按钮照常可点。

**【新增】序列号卡**：气泡问一句「能找到{设备}的序列号吗？找不到也没关系。」，卡上从上到下：

| 位置 | 内容 | 行为 |
|---|---|---|
| 卡头左侧 | 🏷 设备序列号 | 只展示 |
| 卡头右侧 | ? 怎么找 | 点开弹窗，按设备给两步（内容见 5.1）。底部按钮看来路：从卡片点开是「去填写」，从填写框点开是「返回填写」（已输入的内容保留） |
| 卡头下一行 | 位置提示，如「电脑 · 在主机侧面或底部的标签上」 | 只展示 |
| 两个动作 | 填写序列号 / 找不到，继续 | 填写：弹输入框，框里再写一遍设备和位置、可点「怎么找」，打开即可直接输入。找不到：标记后直接进下一步 |

填的内容不像序列号时提示核对，仍可点「找不到，继续」。

## 六、明道云与流程

### 6.1 IT 单的状态【新增】

只对 IT 单生效，其他三大类的状态不变。报修单状态这个字段是只读的，接口写不进去，只能由明道云流程节点推进，所以每多一个状态就要多配一个节点。

| 状态 | 谁推进 | 运维在这一步做什么 | 门店在 App 里看到的含义 |
|---|---|---|---|
| 待运维审核 | 提交后自动进入 | 核对信息和序列号（找不到的在这里补录）；小问题直接远程指导门店处理 | 运维会尽快核实，小问题会直接远程处理 |
| 待供应商维修 | 运维审核通过 | 按序列号确认供应商（易点租 / 小熊U租）并登记，联系供应商 | 供应商会联系门店安排维修 |
| 已完结 | 运维 | 远程解决，或供应商修好后 | 处理完成 |
| 被驳回 | 运维 | 填驳回原因：信息不符、不是门店 IT 设备、手机超过三年建议换新（走 IT 申请） | 单上能看到驳回原因 |

远程解决的问题在「待运维审核」直接完结，不经过供应商。门店自己损坏设备的报价和收费**本期不进系统**，照现状由运维线下和门店沟通，所以 IT 单不经过「待结算费用」。

运维要改的不只是状态，还需要几个字段【待确认：是否都建】：

| 字段 | 谁填 | 用途 |
|---|---|---|
| 设备序列号（文本） | 门店填；找不到的由运维补录 | 核对设备归属、找供应商 |
| 供应商（下拉：易点租 / 小熊U租） | 运维 | 记录派给了谁 |
| 处理方式（下拉：远程解决 / 供应商维修） | 运维 | 统计远程解决占比 |
| 驳回原因（文本） | 运维 | 门店可见 |

### 6.2 明道云侧需要的配合

| 项           | 内容 | 备注                                    |
|-------------|---|---------------------------------------|
| 分类字典        | 新增大类「IT设备类」及 3 个子项 | 大类名称【待确认】。字典要先发布，否则高频卡不会出现 |
| 新增控件        | 设备序列号（文本），及 6.1 的几个字段 | **可写性必须实测**：现有「紧急程度」控件是只读的，接口写入会被悄悄丢弃 |
| 报修单状态        | 新增 3 个选项：待运维审核、待供应商维修、（已完结、被驳回沿用现有） | 现有选项：待提交、待接单、待维修、待结算费用、已完结、被驳回 |
| 维修部门        | 新增「IT」选项，用于工作流分流 | 现有只有 营建、运营【待确认】 |
| 工作流         | 新增 IT 分支：三个节点，节点负责人是运维；通过进下一状态，驳回进「被驳回」 | 节点怎么配需要明道云管理员确认 |

### 6.3 派单与后续

- 运维在「待运维审核」核对序列号，确认供应商后推进到「待供应商维修」并登记供应商。
- 供应商联系门店实施维修。
- 修好后由运维更新为「已完结」。门店在 App 的报修记录里查到的就是明道云的状态【待确认：App 对新增的三个状态是否原样显示】。

## 八、兜底与异常

| 场景         | 处理 |
|------------|---|
| 序列号填了但格式不对 | 提示「看着不像序列号，请核对设备标签」；允许点「找不到，继续」 |
| 点了「其他」又想点常见现象 | 常见现象按钮不置灰，照常可点。「其他」只是把光标放回输入框，不产生内容 |
| 标记了找不到序列号 | 正常提交；单上带标记，运维在「待运维审核」补录 |
| 运维驳回 | 单据进入「被驳回」，门店在报修记录里能看到原因；门店修改后重新提交，生成新单 |
| AI 服务不可用   | 沿用现有处理：提示并引导回表单，表单路径照常可提交 IT 单 |
| 明道云控件或工作流未就绪   | IT 类别在前端隐藏，字典不发布；不出现「能选但提交失败」 |
