#  门店报修 

## 一、背景与目标

### 1.1 背景

- 显示器的报修目前不在 App 里。
- App 现有「我要报修」已覆盖三大类 30 项，并已上线 AI 智能填报，但没有 IT 类。


### 1.2 痛点
#### 门店
- 群太多， 反馈不方便  消息内容不好跟踪 
- 填一个比较重的表单，字段多，手填容易出错
- 群内咨询、催办、跟踪进度（爬楼）全在群里。
#### 运维
- 处理用户抱怨情绪，信息、序列号填不对，要沟通指导
- 群身份要和表单对、消息内容不清晰 缺少带身份的入口 
- 门店问题并发上来，太多忙不过来，没办法及时回复

### 1.3 目标

| # | 目标                                     | 衡量方式                 |
|---|----------------------------------------|----------------------|
| 1 | 门店在**同一个报修入口**完成 IT 设备报修，不再用独立表单、不在群里报 | IT 类报修 100% 从 App 提交 |
| 2 | IT 报修门店只多填项（设备序列号），其余沿用现有报修            | 门店手填字段数；单次填写时长       |
| 3 | IT 单进入统一的状态流转，运维有审核依据，门店能看到进度          | 状态回填                 |
| 4 | IT 的小问题门店先按指引自查，能自己解决的不用建单            | 自助解决率                 |

## 二、核心设计点

| # | 原则                 | 落地方式                                                        |
|---|--------------------|-------------------------------------------------------------|
| 1 | **入口不变、tab 不变**    | 不新增「IT 报修」入口。首页「我要报修」卡片、表单页、表单页顶部的「AI 智能填报」入口卡都是现有的，只把描述里的类别说明补上「IT 设备类」 |
| 2 | **一个新的大类**         | 报修类别字典新增「IT设备类」，下面三项：电脑、手机、显示器                              |
| 3 | **切类别加字段**         | 表单页选到 IT 类别，才在「报修类别」下方带出「设备序列号」；AI 对话选到 IT 设备，才多出「故障情况」「设备序列号」两步；常见现象里能自查的，点完先给自助排查 |
| 4 | **非 IT 完全不变**      | 其他三大类的表单、对话话术、追问顺序与现在逐项一致，回归测试按此验证                          |
| 5 | **IT 单走运维审核**      | IT 单有三个自己的状态：待运维审核 → 待供应商维修 → 已完结（不通过进「被驳回」），由运维在流程节点上推进，费用环节不进状态。状态加在现有表还是一张新表上，见 6.0 |
| 6 | **先自查再报修** | IT 的常见现象里门店能自己排查的，点完先给 2–3 步；解决了就不建单，没解决带着「门店自查」标记继续报。对应运维现在「先看能不能远程解决」的做法 |

## 三、字段：IT 类别带来的增量

> 现有报修的字段及获取策略不变。线上表单一共 7 项：门店名称、报修类别、报修人员、报修日期、描述具体故障、现场照片、联系电话。「期望上门」「影响营业」已全链路取消，所有类别都不再采集。

| 字段 | 表单页 | AI 对话 | 必填 | 规则 |
|---|---|---|---|---|
| **报修类别** | 类别选择器最下面多一个大类「IT设备类」（原表单这一行不变） | 高频卡墙里「地砖/踢脚线破损」那张换成「电脑/手机/显示器」（下称 IT 卡），点开三选一；打字后给出的候选卡和全量类别列表里出现 IT 项 | 是 | 取值 `IT设备类 - 电脑` / `手机` / `显示器`。原话含「电脑」「手机」「显示器」且唯一命中时按现有规则直接登记，免点选 |
| **故障情况**（现有字段，IT 多问一步） | 不变，仍是「描述具体故障」 | 【新增】点 IT 卡、选完设备后追问一句，给 4 个常见现象按钮，下面另留一条通栏的「其他」；点常见现象等于替用户说这句话，原文进「故障情况」，其中配了排查方法的先给一张「自助排查卡」（见 3.2）；点「其他」不填内容，光标回到输入框，用户自己说。打字路径沿用现状，原话照抄 | 是 | ≤100 字，逐字照抄用户原话。非 IT 类别点高频卡不问（现状：系统默认填“类别，详见现场照片”） |
| **设备序列号** | 选到 IT 类别后带出的一行，行首「?」看怎么找，行尾「找不到」做标记 | 序列号卡：右上角「怎么找」、填写序列号、找不到，继续 | 是（仅 IT；可标记找不到） | 去掉首尾空格，6–40 位字母、数字、连字符【待确认：两家供应商的序列号格式】。同一序列号 7 天内有未完结单时提示，可选继续。标记「找不到」可以提交，单上带标记，运维审核时补录 |
| **门店自查**（新增标记） | 不涉及 | 走过自助排查卡、点了「没解决，继续报修」后自动带上；确认单上只展示、不能改 | 否（自动） | 随单带给运维：这几步门店已经试过。怎么存【待拍板：运维 / 明道云管理员】 |

三个名字指同一个东西，不改名：表单上叫「描述具体故障」，对话确认单上叫「故障情况」，明道云控件叫「报修详情」。

### 3.1 常见现象按钮（原「故障现象选项」）

不做单选字典，只是把用户最常说的几句话做成按钮。每种设备取 4 个（加粗），两行排开，其中门店能自己排查的点完先给自助排查卡（见 3.2）；最下面固定留一条通栏的「其他」——四个都对不上时点它，光标回到输入框，用户自己说一句，这句话原文进「故障情况」。其余说法作为候选，上线后按真实单量调整【待确认：IT 历史单量与故障分布】。

| 电脑 | 手机 | 显示器 |
|---|---|---|
| **开不了机 / 自动关机** | **碎屏 / 屏幕显示异常** | **不亮 / 黑屏** |
| **蓝屏、报错** | **无法开机** | **花屏、闪屏、线条** |
| **卡顿、死机** | **充不进电、耗电快** | **颜色异常** |
| **无法联网** | **系统卡顿、闪退** | **接口松动、无信号** |
| 黑屏、无显示 | 无法联网 | |
| 键盘鼠标失灵 | 声音、听筒异常 | |
| 软件问题（收银系统等） | | |

通栏一行，三种设备相同：✎ 其他（自己描述）

### 3.2 自助排查卡（2026-11-27 评审新增）

门店点了带排查方法的常见现象后，先别急着往下走：助手给出 2–3 步不拆机的自查步骤，门店试完再选「没解决，继续报修」或「已解决，不报修」。这一步对应运维现在的做法——先在群里看能不能远程解决（内存满了这类小问题），解决不了再让门店提交表单。

| 设备 | 常见现象 | 排查步骤（初稿）【待确认：运维】 | 约用时 |
|---|---|---|---|
| 电脑 | 开不了机 / 自动关机 | ① 检查电源线和插排，换个插座再按电源键 ② 看主机和显示器的指示灯亮不亮 ③ 长按电源键 10 秒，松开后再开一次 | 1 分钟 |
| 电脑 | 蓝屏、报错 | ① 拍下蓝屏或报错的画面 ② 长按电源键 10 秒关机，等 1 分钟再开 | 2 分钟 |
| 电脑 | 卡顿、死机 | ① 关掉用不上的软件和窗口 ② 重启一次电脑 ③ 桌面和 C 盘快满了，先清理一下 | 2 分钟 |
| 电脑 | 无法联网 | ① 看路由器和网线的指示灯 ② 网线两头拔插一次 ③ 重启路由器，等 1 分钟再连 | 2 分钟 |
| 手机 | 无法开机 | ① 用原装充电器充 10 分钟 ② 长按电源键 10 秒以上 | 2 分钟 |
| 手机 | 充不进电、耗电快 | ① 换一根充电线或充电头 ② 清理充电口的灰尘，重启一次 | 2 分钟 |
| 手机 | 系统卡顿、闪退 | ① 重启一次手机 ② 关掉后台应用，清理存储空间 | 1 分钟 |
| 显示器 | 不亮 / 黑屏 | ① 检查电源线和视频线，两头插紧 ② 按一下显示器的电源键，看指示灯 ③ 换一根视频线试试 | 2 分钟 |
| 显示器 | 花屏、闪屏、线条 | ① 把视频线两头拔插一次 ② 换一根视频线，或换个接口 | 1 分钟 |
| 显示器 | 接口松动、无信号 | ① 把视频线两头拔插一次 ② 换主机上另一个接口，或换一根线 | 1 分钟 |

- 没列在表里的现象（手机「碎屏 / 屏幕显示异常」、显示器「颜色异常」）没有可自助排查的办法，点了不出这张卡，流程和原来一样直接进拍照。
- 步骤只做不拆机、不改系统设置的检查；哪些现象配、每条写什么、约用时，都要运维确认。
- 两个出口：**没解决，继续报修**（主按钮）照常往下走，确认单多一行「门店自查：已排查，未解决」，随单带给运维；**已解决，不报修**会话结束、不建单，只留「再报一单」，不留记录给运维，只记埋点。
- 排查卡挂着时不点按钮、直接打字：说了「好了」「解决了」按已解决结束；其他内容按「没解决，继续报修」处理，这句话补进「故障情况」。
- 打字路径（原话描述故障、点「其他」自己描述）不触发排查卡：没点过具体现象，不知道该给哪套步骤。
- 从 IT 改成其他类别，「门店自查」标记作废。

## 四、交互流程

现状流程图：[diagrams/01-现状流程图.puml](diagrams/01-现状流程图.puml)

### 关键环节

1. **首页**：「我要报修」卡片不动。
2. **表单页**：
    - 选到 IT 类别，在「报修类别」这一行正下方带出「设备序列号」。
    - 改回其他类别，这一行收起，已填内容清空。
    - 底部「提交」不动。
3. **AI 对话首屏**：顶部状态条（📍 门店 ｜ 报修人 · 电话）、开场白都不变；高频卡片仍是 6 张、两列三行：「地砖/踢脚线破损」换成「电脑/手机/显示器」，首屏高度不变。
4. **选设备**：点 IT 卡后出三选一（电脑 / 手机 / 显示器），用的是线上现成的子选项机制（和照明灯分两档一样）。
5. **故障情况**【新增】：选完设备追问一句，带 4 个常见现象按钮和一条通栏「其他」（点了直接打字）；点了带排查方法的现象，先给自助排查卡，门店试完再决定报不报（见 3.2）。
6. **照片**：沿用现有拍照引导，IT 类别的建议拍摄清单不同。
7. **序列号**【新增】：序列号卡，卡头右上角「怎么找」（按设备给两步查看方法），卡上一行写在哪找，可以填、可以标记找不到。
8. **电话**：回到现有的电话确认。
9. **确认单**：IT 单比普通单多一行「设备序列号」，每一项都可以点开修改；走过自助排查的再多一行「门店自查」。提交后出结果卡。

### 4.1 高频卡片怎么放 IT

线上现有 6 张按全量 2.6 万单的频次定（照明灯 17%、门头字 8%、开关插座 6%、摄像头 6%、空调 3%、地砖/踢脚线 3%）。冷柜、灭火器这类「门店自修」的类别 2026-11-26 起不进卡、也不给报单，对话里提到只告知。这次把第 6 张「地砖/踢脚线破损」换成 IT，卡片仍是 6 张、两列三行，样式和首屏高度都不变：

| 卡片   | 对应类别         | 说明                 |
|------|--------------|--------------------|
| 💻 电脑/手机/显示器 | IT设备类：电脑、手机、显示器 | 点后出三选一，点设备即定类别；用户气泡记「🖱 电脑/手机/显示器」 |

一张卡就够：子选项卡最多放 3 项，三种设备正好。卡片文案直接写设备名，不加「IT设备-」前缀，和旁边几张卡的长短一致。

地砖/踢脚线不再占卡位，但仍能报：打字描述会给出候选类别，也可以从全量类别列表里点选。IT 类的实际单量占比目前没有数据【待确认】。

## 五、页面规则明细

### 5.1 表单页

| 场景 | 行为 |
|---|---|
| 未选类别 | 与线上一致，没有额外字段 |
| 选 IT 类别 | 在「报修类别」正下方带出「设备序列号」一行 |
| 设备序列号 | 直接输入。行首「?」弹出两步查看方法（按设备）；行尾「找不到」点击后标记，输入框换成“已标记找不到，运维协助核对”，再点取消标记 |
| 从 IT 改成其他类别 | 这一行收起，序列号与标记清空 |
| 提交校验（从上到下） | 类别必选；IT 时序列号必填或已标记找不到；描述具体故障必填；照片至少 1 张；联系电话必填 |

各设备查看序列号的方法【待确认：与运维核对口径，电脑型号只有两种，可以直接写具体位置】。表单页「?」和对话里「怎么找」弹出的是同一份内容，按设备写两步（表单页弹窗底部按钮是「知道了」）：

| 设备 | 一行位置提示（写在卡上 / 填写框里） | 弹窗里的两步 |
|---|---|---|
| 电脑 | 在主机侧面或底部的标签上 | ① 看主机侧面或底部 ② 找到贴在那里的标签，抄下序列号 |
| 手机 | 在设置的设备信息里 | ① 打开手机设置，进入设备信息 ② 查看序列号；开不了机时，看机身背面或包装盒 |
| 显示器 | 在背面的铭牌上 | ① 看显示器背面 ② 找到铭牌抄下序列号，注意别抄成主机的 |

弹窗末尾固定一句：标签脱落或看不清？关掉这个窗口，点「找不到，继续」，运维会协助核对。是否配实拍示意图，方案见 5.4【待拍板】。

### 5.2 AI 对话

**两条进入路径**（线上已有，不改）：

| 路径 | 怎么进来 | 经过哪些步骤 |
|---|---|---|
| 点卡路径 | 点首屏的高频卡 | 高频卡 →（带子选项的先选细分/设备）→【IT：故障情况】→【IT：自助排查，有排查方法的现象才出】→ 照片 →【IT：序列号】→ 电话 → 确认单 |
| 打字路径 | 自己打字描述故障 | 一句话 → 故障情况记下、类别给出 Top3 或直接登记 → 照片 →【IT：序列号】→ 电话 → 确认单 |

括号里的几步只在 IT 类别出现，非 IT 类别跳过，顺序与现在一致。

**对话里线上已有的行为，IT 单同样适用**：

| 场景 | 行为 |
|---|---|
| 原话带设备名（“收银电脑开不了机”） | 字典词唯一命中，直接登记类别并复述，不用点选 |
| 说的不是字典词（“机器开不了机”） | 出 Top3 卡让用户点；完全没把握就给全量类别列表。类别只能点选，AI 不替用户定 |
| 确认单上改类别 | 弹两级联动重选；照片不删，只提示自查；换成 IT 类别会补问故障情况和序列号，换回其他类别这两项和「门店自查」作废 |
| 跑题、问进度 | 应和一句并拉回报修，然后把当前该做的事（卡片）重新放到屏幕最下面 |
| 连续点不出选项 | 连续 15 轮没进展降级成纯点卡向导，照样能交单 |
| 点返回 | 三选一：继续填写 / 存草稿离开（保留 7 天）/ 放弃本次 |
| 提交失败 | 提示“单子没递上去，稍等一下再点次提交”，确认单留着可重试 |
| AI 服务不可用 | 沿用现有处理；表单路径照常可提交 IT 单 |

**【新增】故障情况追问卡**（只在 IT 的点卡路径出现）：气泡问一句「{设备}出什么问题了？点下面的常见现象，或者直接说。」，卡上 4 个常见现象按钮两行排开，最下面一条通栏「其他」。点常见现象 = 替用户说这句话，用户气泡显示按钮文字，原文进「故障情况」；点「其他」不填内容、不回发服务端，助手回一句「用一句话说说故障情况，我来整理报修表单。」并把光标放到输入框，之后打字的内容按现有 text 消息处理，常见现象按钮照常可点。

**【新增】自助排查卡**（只在 IT 的点卡路径、且点的现象配了排查方法时出现）：助手先说一句「先按下面的步骤试一下，能解决就不用报修。」，卡上从上到下：

| 位置 | 内容 | 行为 |
|---|---|---|
| 卡头 | 🔧 自助排查　〔约 N 分钟〕 | 只展示 |
| 步骤 | 2–3 步，编号排开（内容见 3.2） | 只展示 |
| 底部一句 | 只做不拆机的检查，解决不了再报修 | 只展示 |
| 两个动作 | 没解决，继续报修 / 已解决，不报修 | 继续报修是主按钮：标记「门店自查」后进下一步（照片 → 序列号 → 电话 → 确认单）。已解决：会话结束、不建单，助手回「好的，这次就不建单了。问题再出现随时来报。」，只留「再报一单」一个按钮 |

主按钮放「没解决，继续报修」是有意的：门店习惯顺手点主按钮，点错了只是多建一张单；反过来会把没修好的单点了结。

**【新增】序列号卡**：气泡问一句「能找到{设备}的序列号吗？找不到也没关系。」，卡上从上到下：

| 位置 | 内容 | 行为 |
|---|---|---|
| 卡头左侧 | 🏷 设备序列号 | 只展示 |
| 卡头右侧 | ? 怎么找 | 点开弹窗，按设备给两步（内容见 5.1）。底部按钮看来路：从卡片点开是「去填写」，从填写框点开是「返回填写」（已输入的内容保留） |
| 卡头下一行 | 位置提示，如「电脑 · 在主机侧面或底部的标签上」 | 只展示 |
| 两个动作 | 填写序列号 / 找不到，继续 | 填写：弹输入框，框里再写一遍设备和位置、可点「怎么找」，打开即可直接输入。找不到：标记后直接进下一步 |

填的内容不像序列号时提示核对，仍可点「找不到，继续」。

### 5.3 类别里找不到要报的东西【方案待拍板，2026-11-27 评审提出】

评审意见：表单页选类型时，有些东西不在分类里，要给个友好的提示。

现状：表单的「报修类别」是两级联动（大类 → 子项）的底部弹层。字典里只有工程类带一个「工程-其他（不含调改）」，营运用具类、购物袋没有兜底项；IT设备类下也只有电脑、手机、显示器，打印机、键盘鼠标、耳机这类不在里面。门店找不到时，要么随便选一个（单子归错类，运维再改），要么放弃、回群里问。

范围先确认【待确认】：「不在分类中」指的是 IT 里没列的办公设备，还是所有大类都可能找不到。下面两种都覆盖。

| | 方案 A：只指路 | 方案 B：加「其他」兜底项 | 方案 C：A + B |
|---|---|---|---|
| 入口 | 弹层里两列列表的下方、取消/确定按钮的上方，加一行居中小字「找不到要报的类别？」 | 不加入口；IT设备类下多一个子项「其他设备」 | 用 A 的入口，点开后能选到 B 的「其他设备」 |
| 门店看到什么 | 一段说明：① 打印机、键盘鼠标这类办公设备，选最接近的一项（「IT设备类 › 电脑」），并在「描述具体故障」第一句写明设备，如「打印机无法进纸」② 实在不属于任何大类的，联系门店运维群 | 和选别的类别一样；序列号一行照常带出，可以点「找不到」 | 说明的第一条改成「选 IT设备类 › 其他设备」，并给「去选择」按钮 |
| 能不能提交 | 能，但落在一个不准确的类别上 | 能，类别就是「其他设备」 | 能 |
| 运维要做什么 | 审核时看描述改类别 | 审核时归类 | 同 B |
| 改动 | 前端：弹层加一行 + 一个说明弹层；后端、明道云都不动 | 明道云分类表加 1 个子项并发布，App 选择器自动出现。AI 对话里它进全量类别列表，IT 卡仍是三选一（子选项卡最多 3 项），打字说「打印机」由模型提名；它没有常见现象按钮和序列号位置提示，按打字路径走 | 两边都做 |
| 能否量化 | 只能埋点「点开了几次」 | 能看到「其他设备」的单量，反推字典缺什么 | 能 |
| 风险 | 指了路，门店还是得选一个不对的类别 | 「其他设备」可能被当成偷懒的选项，运维归类量上升 | 同 B |

建议 C，分两步：先上 A 的入口（纯前端，改动最小），同时给 IT设备类加「其他设备」——IT 单本来就要过运维审核，在审核节点顺手归类成本最低。营运用具类、购物袋要不要也加「其他」，等「其他设备」的量跑出来再定。

文案（待润色）：

| 位置 | 文案 |
|---|---|
| 入口 | 找不到要报的类别？ |
| 说明标题 | 列表里没有要报的设备？ |
| 说明正文 | 打印机、键盘鼠标这类办公设备，选「IT设备类 › 其他设备」，并在「描述具体故障」第一句写明设备名称。运维审核时会按实际设备归类，不影响报修。 |
| 兜底一句 | 实在选不了的，联系门店运维群。 |
| 按钮 | 知道了 / 去选择 |

对话页要不要加同样的提示【待定】：AI 对话找不到类别时现在是「这个我没把握归类，从下面选一个吧」+ 全量列表，可以在全量列表底部放同一行入口、复用同一份说明。

### 5.4 序列号示例图【方案待拍板，2026-11-27 评审提出】

评审意见：对话里索取序列号的时候，给个图片示例提示。

现状：序列号卡上只有一行位置提示（「电脑 · 在主机侧面或底部的标签上」）和「怎么找」弹窗里的两步文字。痛点里的原话是「序列号不知道是什么」——文字说"标签"，门店想象不出标签长什么样、该抄哪一行。

目标：看一眼就知道找什么、在哪找、抄哪一行。

图片放哪里（三个位置，可以叠加）：

| | ① 序列号卡上带缩略图 | ② 「怎么找」弹窗里配图 | ③ 填写框里带小图 |
|---|---|---|---|
| 长什么样 | 位置提示那一行的右侧放一张小图（约 96×64，圆角），图上用橙框标出标签位置；点开看大图 | 两步文字各配一张图：第一步「看哪里」是设备侧面/背面 + 橙框，第二步「抄哪一行」是标签放大 + 橙框圈住序列号那一行 | 顶部「电脑 · 在主机侧面或底部的标签上」这一条的右边放同一张小图，点开放大 |
| 什么时候看到 | 助手一问序列号就能看到，不用点 | 主动点「怎么找」才看到 | 点了「填写序列号」才看到 |
| 优点 | 曝光最大，正对着「不知道序列号是什么」的人 | 图可以大、带标注，和现有两步文字一一对应 | 边找边填，不用来回切 |
| 缺点 | 对话里多占约 50px 高度；图小，标注看不清 | 不点看不到，而最需要看的人往往不知道要点「怎么找」 | 同 ① |
| 建议 | 做，图只负责「在哪」，不带文字 | 必做，主位置 | 做，复用 ① 的小图 |

建议：三个位置用同一组图，② 是主位置（大图 + 标注 + 两步文字），① 和 ③ 放同一张缩略图负责引流，点缩略图直接进「怎么找」弹窗的大图。

图怎么做：

| 设备 | 需要的图 | 说明 |
|---|---|---|
| 电脑 | 主机侧面标签、主机底部标签各 1 张 | 电脑型号只有两种，按型号各拍一套；标签上的序列号打码或换成示例值 |
| 手机 | 「设置 › 设备信息」页的截图 1–2 张 | 序列号那一行用橙框圈出；开不了机时要看机身背面，补 1 张背面图 |
| 显示器 | 背面铭牌 1 张 | 铭牌用橙框圈出，步骤里已经有一句「别抄成主机的」 |

- 形式：实拍图 + 橙色标注框，不画示意图。门店要找的是自己手上那台机器，实拍才对得上。
- 规格：缩略图 3:2；大图宽不超过 1080，JPG 或 WebP，单张不超过 200KB；图上不放文字，文字放在步骤里。
- 来源：运维按型号拍，产品加标注；图片地址按设备配置，和「怎么找」两步文案放在同一份配置里。
- 兜底：图加载失败或某个设备没图，只显示文字，流程不受影响。

连带：表单页「?」弹窗和对话里的「怎么找」共用同一份内容，加了图两边同时有。

度量（接九里已有的「怎么找」使用率）：打开「怎么找」之后填写了序列号的比例；「找不到」占比有没有降下来。

待确认：图由谁拍、什么时候能给；电脑是不是按两种型号各一套；手机截图要不要按品牌区分；标签上的序列号要不要打码。

| 门店端 | 入口、表单、对话都不变 | 同左 |

| 适合 | IT 单量小、想最快上线 | IT 流程和工程单差异大、要独立演进 |

代码事实（2026-11-27 核对）：

- 表单路径：`WorkOrderShopReportServiceImpl.submitShopApply` 做两件事——经 provider-data-sync 写明道云（工作表名 `shopReport` 配在 data-sync 的 MSE 配置里），再经 provider-base-shop-manager 在本地落一条记录。App 的报修记录列表和详情读的是本地这条记录，状态取工单表。
- 对话路径：`create_repair_order` 直接调明道云 v3 新建行，工作表 id 是 Nacos 配置 `MDY_WORKSHEET_ID`，字段映射在 `fields.py`，换表只改这两处。仓库里没看到对话路径往 base-shop 落记录的代码。
- 报修类别是级联选择控件，选项来自分类表「报修问题分类分级」。两个方案都要先把「IT设备类」加进分类表并发布，表单的选择器和 AI 的类别字典都读它。
- provider-data-sync、provider-base-shop-manager 不在本地仓库，同步机制核实不了，要找对应团队确认。

结论：两边都能做，差别集中在「门店在 App 报修记录里能不能查到 IT 单」。要走 B，得同时定三件事：① 报修记录要不要显示 IT 单；② 要显示的话，新表的状态由谁同步到记录接口；③ 新表是在现有的「门店IT设备报修申请表」上改，还是新建。定下来之前，下面 6.1–6.3 先按方案 A 写。

### 6.1 IT 单的状态【新增】

只对 IT 单生效，其他三大类的状态不变。报修单状态这个字段是只读的，接口写不进去，只能由明道云流程节点推进，所以每多一个状态就要多配一个节点。

| 状态 | 谁推进 | 运维在这一步做什么 | 门店在 App 里看到的含义 |
|---|---|---|---|
| 待运维审核 | 提交后自动进入 | 核对信息和序列号（找不到的在这里补录）；带「门店自查」标记的单，排查卡上的步骤门店已经试过，不用重复教；其他小问题直接远程指导门店处理 | 运维会尽快核实，小问题会直接远程处理 |
| 待供应商维修 | 运维审核通过 | 按序列号确认供应商（易点租 / 小熊U租）并登记，联系供应商 | 供应商会联系门店安排维修 |
| 已完结 | 运维 | 远程解决，或供应商修好后 | 处理完成 |
| 被驳回 | 运维 | 填驳回原因：信息不符、不是门店 IT 设备、手机超过三年建议换新（走 IT 申请） | 单上能看到驳回原因 |

远程解决的问题在「待运维审核」直接完结，不经过供应商。门店自己损坏设备的报价和收费**本期不进系统**，照现状由运维线下和门店沟通，所以 IT 单不经过「待结算费用」。

运维要改的不只是状态，还需要几个字段【待确认：是否都建】：

| 字段 | 谁填 | 用途 |
|---|---|---|
| 设备序列号（文本） | 门店填；找不到的由运维补录 | 核对设备归属、找供应商 |
| 供应商（下拉：易点租 / 小熊U租） | 运维 | 记录派给了谁 |
| 处理方式（下拉：远程解决 / 供应商维修） | 运维 | 统计远程解决占比 |
| 驳回原因（文本） | 运维 | 门店可见 |
| 门店自查（标记） | 系统写入（门店点了「没解决，继续报修」） | 这几步门店已经试过，不用重复教；怎么存【待拍板】 |

## 八、兜底与异常

| 场景         | 处理 |
|------------|---|
| 序列号填了但格式不对 | 提示「看着不像序列号，请核对设备标签」；允许点「找不到，继续」 |
| 点了「其他」又想点常见现象 | 常见现象按钮不置灰，照常可点。「其他」只是把光标放回输入框，不产生内容 |
| 自助排查卡出现后不点按钮、直接打字 | 说了「好了」「解决了」按已解决结束；其他内容按「没解决，继续报修」处理，这句话补进「故障情况」 |
| 点了「已解决，不报修」 | 会话结束，不建单、不进报修记录，只留「再报一单」；记一次自助解决埋点 |
| 点了「已解决」之后问题又出现 | 点「再报一单」回到首屏重新报，上一轮的排查结果不带过来 |
| 标记了找不到序列号 | 正常提交；单上带标记，运维在「待运维审核」补录 |
| 运维驳回 | 单据进入「被驳回」，门店在报修记录里能看到原因；门店修改后重新提交，生成新单 |
| AI 服务不可用   | 沿用现有处理：提示并引导回表单，表单路径照常可提交 IT 单 |
| 明道云控件或工作流未就绪   | IT 类别在前端隐藏，字典不发布；不出现「能选但提交失败」 |

## 九、度量指标

在现有指标基础上增加：

| 指标 | 定义 |
|---|---|
| IT 报修单量与占比 | 按设备类型分；与 IT 卡点击量对照 |
| IT 入口渗透率 | IT 单中 AI 填报占比、表单填报占比 |
| 序列号一次通过率 | 提交后未被运维因序列号驳回或补录的单占比 |
| 序列号「找不到」占比 | 标记找不到的单 / IT 单总数 |
| 常见现象按钮使用率 | 点按钮填故障情况的 IT 单 / 对话路径的 IT 单；点「其他」后打字的单独计，这些说法用于调整按钮 |
| 「怎么找」使用率 | 打开过「怎么找」的 IT 单 / IT 单总数；打开后仍点「找不到」的比例偏高，说明提示没用，先改文案或配示意图 |
| IT 卡的点击率 | 点击量 / 对话首屏曝光 |
| 地砖/踢脚线单的入口分布 | 地砖/踢脚线单里打字、全量列表点选各占多少；和换卡前对比，看少一个卡位有没有影响 |
| 自助解决率 | 点了「已解决，不报修」的会话 / 出过自助排查卡的会话，按设备和现象分 |
| 排查后继续报修的占比 | 出过排查卡、最后仍然报修的会话占比。某个现象一直很高，说明这几步没用，先改内容或者撤掉这张卡 |
| 运维审核时长 | 提交到离开「待运维审核」的时长 |
| 远程解决占比 | 处理方式为远程解决的单 / IT 单总数 |
| 驳回率与原因分布 | 被驳回的 IT 单占比，按驳回原因分 |
| 供应商维修时长 | 进入「待供应商维修」到「已完结」的时长 |
| 群消息量 | 门店报修群里与 IT 报修相关的消息数，对比上线前后 |

## 十一、验收标准

- [ ] 首页卡片、表单页布局、tab 与现在一致，没有新增入口
- [ ] 类别选择器出现「IT设备类」及电脑 / 手机 / 显示器
- [ ] 表单页面与线上一致；选 IT 类别后在报修类别下方出现设备序列号；改回其他类别后这一行消失且内容清空
- [ ] 表单和对话全程不出现「期望上门」「影响营业」
- [ ] 表单校验符合 5.1；缺项时有明确提示
- [ ] AI 对话首屏仍是 6 张卡、两列三行：「地砖/踢脚线破损」换成「电脑/手机/显示器」，其余 5 张内容与行为不变；点 IT 卡出电脑 / 手机 / 显示器三选一
- [ ] 地砖/踢脚线仍能报：打字描述会给出候选类别，全量类别列表里能点到；冷柜、灭火器这类门店自修类别照旧不进卡，提到只告知
- [ ] 选完设备后追问故障情况，带 4 个常见现象按钮和通栏「其他」；点按钮和打字都能填入「故障情况」，点「其他」后光标在输入框、可以直接打字
- [ ] 点了带排查方法的常见现象，先出现自助排查卡（步骤、约用时、两个按钮）；点「没解决，继续报修」后流程照常往下走，确认单多一行「门店自查」；点「已解决，不报修」后不建单、会话结束
- [ ] 没配排查方法的现象（如碎屏）点了不出排查卡，直接进拍照
- [ ] 一句话报电脑：原话带设备名时直接登记并复述；不带设备名时 Top3 首位是 IT
- [ ] IT 对话路径依次出现照片、序列号、电话；序列号卡右上角能点开「怎么找」，可填、可标记找不到
- [ ] 非 IT 类别的对话剧本逐句与现状一致，不多问任何一步
- [ ] 从 IT 改成非 IT 后，确认单不再出现设备序列号和门店自查
- [ ] 标记「找不到序列号」可以提交，单据上有待补录标记
- [ ] 提交后明道云单据里设备序列号有值且正确，类别落在「IT设备类」
- [ ] IT 单提交后状态为「待运维审核」；运维可推进到「待供应商维修」「已完结」或「被驳回」；非 IT 单的工作流不受影响
- [ ] 门店在 App 报修记录里能看到 IT 单的最新状态和驳回原因
- [ ] AI 服务不可用时，表单路径可以完成 IT 报修

## 十二、灰度与后续规划

**灰度**：先在 1–2 家门店加运维团队内部试用一周，核对明道云字段和工作流，再按现有报修的放流节奏扩大。

**后续**（按依赖顺序）：

1. 序列号拍照识别：依赖标签照片样本和多模态识别，识别结果仍需用户确认
2. 设备台账：序列号与设备、门店、供应商对应起来，审核时自动带出供应商
3. 门店确认修好：新增「待门店确认」，由门店在 App 里确认后完结
4. 门店损坏的费用线上化：报价、核价、门店确认
5. 运维审核工作台：待办列表、一键通过、驳回原因、超时提醒
6. 自助排查扩到打字路径：模型按门店的描述匹配排查步骤；按「排查后继续报修的占比」调整步骤内容
