## 一、全景

### 1.1 主线：货怎么走

把八张单据放到一条货流上看。实线是货真的在走，虚线是货不进出仓库、只挪库位或调账。

货流主线：[01-单据主线-货怎么走.puml](../diagrams/01-单据主线-货怎么走.puml)

从左往右是正向：采购入仓，再配货出库到门店。从右往左是逆向：门店退货回仓，仓库退供。采购和退供都由采购在 CRM 发起。笔记里带「回传」字样的只有五条流程（1、2、4、7、8）；仓间调拨（6）停在「下发通知单」，库位转移（5）和门店库存调整（3）没有记流程。

换成人的视角：把供应商、采购员、中台、仓库、司机、门店放在同一张时序图里，按单据分成 8 段。各单据小节里的「流转图」链接都指向它。

流转总图：[02-单据流转总图.puml](../diagrams/02-单据流转总图.puml)

### 1.2 参与方

| 参与方 | 类型 | 在流转里做的事 | 涉及单据 |
|---|---|---|---|
| 采购 | 角色 | 在 CRM 里发起采购单、退供单（笔记原记：「采购（采购 +退供）」） | 1、8 |
| 中台 | 角色 + 系统 | 创建和审核单据，下发 WMS，生成物流单 | 1、2、4、6、7、8 |
| 仓库 | 角色 | 收货、出库，并通过 WMS 回传结果 | 1、2、4、5、6、7、8 |
| 司机 | 角色 | 到仓取货、到店交接；上门取退货 | 2、4 |
| 门店 | 角色 | 录入到货、提交收货；退货；门店库存调整 | 2、3、4 |
| CRM | 系统 | 采购、退供的发起端 | 1、8 |
| 大数据中间表 | 系统 | 承接计划配货单的数据，定时任务据此生成配货单 | 2 |
| WMS | 系统 | 仓库的执行系统，负责回传结果 | 1、2、4、7、8 |
| 司机端 | 系统 | 司机签到、取货 | 2 |
| PDA | 设备 | 司机到店交接时用 | 2 |

「涉及单据」一列是按每条流转步骤归的。另外，笔记里的「中台」既指创建、审核的人（业务中台），也指系统，本文保留原词，没有区分。

| # | 单据 | 笔记里的说明 | 发起 | 货怎么动 | 结果节点 |

### 1.5 笔记里出现的状态和规则

状态只出现了四个：

| 状态 | 单据 | 什么时候变 |
|---|---|---|
| 已通过 | 退货单（4） | 中台审核之后 |
| 退仓中 | 退货单（4） | 中台生成物流单、推送门店和 WMS 之后 |
| 完成（笔记原话「单据变更完成」） | 配货单（2） | 门店收货提交，且核对无差异 |
| 关单 | 采购单（1） | WMS 回传实收之后；分「指令关单」和「条件关单」 |

规则记了这几条：

| 规则 | 单据 |
|---|---|
| 不允许超收 | 采购单（1） |
| 门店收货后核对差异：有差异生成差异单，无差异配货单变更完成 | 配货单（2） |
| 中台通知退货单由中台发起，只能退指定商品，门店不可提交其他商品 | 退货单（4） |
| 普通退货单不限制商品范围 | 退货单（4） |
| 多张退货单可以合成一个物流单 | 退货单（4） |
| 库位转移只在同一仓库的不同库位之间进行，变动的是 SKU 数量 | 库位转移单（5） |
| 调拨时给发货仓下发发货通知单，给收货仓下发收货通知单 | 仓间调拨单（6） |
| 库存调整的结果是盘盈或盘亏 | 库存调整单（7） |
| 退供单审核通过后才创建退仓单 | 退供单（8） |

### 2.2 配货单（出库单）

仓库配给门店的出库单，有两种来源。经中台下发 WMS，司机到仓取货送到门店，门店收货确认；有差异生成差异单，无差异单据完成。

**两种来源**

| 来源 | 怎么来 |
|---|---|
| 算法推送 | 计划配货单提交后，推送至大数据中间表；执行定时任务后生成配货单 |
| 中台手工单 | 中台创建 |

**流转步骤**

| # | 谁 | 在哪 | 做什么 | 备注 |
|---|---|---|---|---|
| 1 | 中台 | 中台 → WMS | 由中台下发 WMS | |
| 2 | 笔记未写明 | | 通知司机到仓取货 | |
| 3 | 司机 | 司机端 | 签到并取货 | |
| 4 | 仓库 | WMS | 回传出库 | |
| 5 | 司机 | | 到店 | |
| 6 | 司机、门店 | PDA | 交接 | |
| 7 | 门店 | 门店 | 录入到货信息 | |
| 8 | 门店 | 门店 | 收货提交 | |
| 9 | 系统（推测） | | 核对是否差异 | |
| 10 | 系统（推测） | | 有差异：生成差异单；无差异：单据变更完成 | |

**关键规则：** 门店收货提交后核对是否差异。有差异则生成差异单，无差异则配货单变更完成。

**技术线索（笔记原记）：** 新大数据中间表 `hotmaxx_erp_scm.hotmaxx_init_delivery_details`；执行定时任务在 `erp-biz-scm`，编号 504，任务名 `unHandledWarehouseTask`。

### 2.4 退货单

门店把货退回仓库的单据，分「中台通知退货单」和「普通退货单」两种。中台审核通过后推送中台，由中台生成物流单，通知门店和 WMS 进入退仓中，司机取货，仓库回传收货。

**两种类型**

| 类型 | 谁发起 | 商品范围 | 之后 |
|---|---|---|---|
| 中台通知退货单 | 中台 | 指定商品，门店不可提交其他商品 | 中台审核，状态变为「已通过」 |
| 普通退货单 | 笔记未写明 | 不限制商品范围 | 中台审核，状态变为「已通过」 |

**流转步骤**

笔记把下面这条路径写在两种类型后面，这里按审核通过后的共同路径理解。

| # | 谁 | 在哪 | 做什么 | 备注 |
|---|---|---|---|---|
| 1 | 系统 | 退货单 → 中台 | 退货单推送中台 | |
| 2 | 中台 | 中台 | 生成物流单 | 可以多单据合成一个物流单 |
| 3 | 中台 | 中台 → 门店、WMS | 推送门店 / WMS | 状态变更为「退仓中」 |
| 4 | 司机 | | 取货 | |
| 5 | 仓库 | WMS | 回传收货 | |

流转图：[02-单据流转总图.puml](../diagrams/02-单据流转总图.puml) 第 4 段。推测：「退货单推送中台」画成从门店推往中台；回传画回中台。
