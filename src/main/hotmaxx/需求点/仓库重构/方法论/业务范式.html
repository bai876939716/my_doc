复杂业务系统穿透图：主线 → 单据 → 状态 → 规则
方法示意，不代表任何具体系统的实际架构
第 1 步 · 找价值主链路（零售折扣业态示例，换成本行业的等价链路即可）
商品建档 › 采购下单 › 到仓入库 › 调拨上架 › 门店销售 › 日结对账 › 退货冲销
只追一件货 / 一笔单走完全程，模块之间的关系会自己浮现，比通读功能清单快一个量级。
第 2 步 · 三层穿透（越往下越接近“深入业务”）
单据层
有什么
采购单 入库单 调拨单 销售单 退货单 结算单
单据是业务的原子，单据之间的流转关系就是系统骨架。
状态层
怎么动
待审 → 已审 → 已入 → 已出 → 已结 → 已冲销
状态机是隐藏的规则库：每次跃迁都带条件、角色、时限；卡住的单子就是规则漏洞。
规则层
为什么
金额与折扣口径 库存扣减时点 审批权限 异常归属 重复提交与冲正
“深入业务”真正发生在这里：同样的动作，为什么这次允许、下次拒绝。
第 3 步 · 四个信息抓手（按投入产出比排序）
① 数据
表结构 + 字段注释 + 真实样本。问“这张表谁写、什么时候写、写错谁修”。
② 人
一线操作者、财务结算、客服。问“哪三件事最烦、最怕出错”。
③ 异常
对账不平、负库存、重复支付、状态卡死。问“上次出事怎么发现的”。
④ 版本
需求变更单、上线时间线。问“这个奇怪逻辑当初为什么这么设计”。
顺序不能颠倒：先有主线（1–3 天）→ 再穿透三层（1–2 周）→ 最后靠异常与版本持续加深。
