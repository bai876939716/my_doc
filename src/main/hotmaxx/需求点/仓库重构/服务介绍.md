# 仓储 ERP 服务介绍

> **来源：** 本地 `haotemai/wms/` 下 11 个仓库的代码（2026-11-26 的 master）和各自的 git 历史。服务的职责、调用关系、表归属都是读代码得出的。
>
> **状态：** 初稿。规模数字（文件数、行数、提交数）由脚本统计；标「推测」的是按常理补的，标「不可见」的是在这 11 个仓库里看不到的。
>
> **行号约定：** `仓库简称 路径:行号` 都相对 `haotemai/wms/`。提交之后行号会漂移，用之前先按方法名搜一下。
>
> **配图：** 服务之间怎么交互见 [diagrams/03-服务交互业务图.puml](diagrams/03-服务交互业务图.puml)，图表索引见 [diagrams/INDEX.md](diagrams/INDEX.md)。
>
> **相关：** [表关系.md](表关系.md)、[单据字典.md](单据字典.md)、[治理与风险.md](治理与风险.md)，以及同目录的 `涉及服务`。

## 一、一句话总览

这 11 个服务分四层：发单和操作的入口、对接 WMS 的网关、把流程串起来的编排层、存单据和库存的数据层。真正改库存余额的只有 `provider-erp-base-ivm` 一个；所有出入库记账和预占，都要先经过一个不在本地的服务 `provider-biz-inventory-middle`。

| 层 | 服务 | 一句话职责 |
|---|---|---|
| 入口 | provider-erp-scm-mms | 仓储 ERP 管理后台的接口层，基本是转发 |
| 入口 | provider-mms-ops | 仓库现场操作端：到货预约、签到、交接、质检 |
| 入口 | provider-mp-driver-biz-scm | 司机小程序后端 |
| 入口 | provider-wd-ops-brd | 边界服务：CRM、算法、门店调 ERP 的转发层 |
| 入口 | provider-erp-base-fio | 异步导出 |
| 网关 | provider-ops | 对接各家 WMS，下发指令、接收回传 |
| 编排 | provider-erp-biz-scm | 流程逻辑：记账定时任务、差异处理、审核作废、MQ |
| 数据 | provider-erp-base-scm | 单据主数据和状态流转 |
| 数据 | provider-erp-base-ivm | 库存余额、流水、预占、库位 |
| 数据 | provider-erp-base-rule | 规则、主数据、排车引擎、仓储账单 |
| 报表 | provider-biz-hd-rpt | 海鼎相关报表（2024-05 后停更） |

## 二、几个共同点

**共库。** 除了 `provider-erp-base-rule`，其余 10 个服务的 `bootstrap.yml` 引用的是同一份数据库配置 `htm-erp-base-mysql.yaml`；base-rule 用自己的 `hotmaxx-base-rule-mysql.yaml`，另外连一个数仓报表库。也就是说服务是按代码仓库拆的，不是按数据库拆的，哪个服务写了哪张表只能看代码（见 [表关系.md](表关系.md) 第七节）。代码里出现过三个库名：`hotmaxx_erp_scm`、`hotmaxx_biz_driver`、`hotmaxx_erp_rpt`；完整的连接信息在 Nacos，不可见。

**技术栈。** JDK 8、Spring Boot 2.3（ops 的 pom 里是 2.3.3，其余服务共用父 pom `provider-pom`）、Spring Cloud Alibaba（Nacos 做注册和配置）、MyBatis-Plus、Redis 和 Redisson、RocketMQ、XXL-Job；base-scm 和 base-ivm 另外接了 Kafka。

**调用方式。** 同步用 Feign，11 个仓库里一共 311 个 Feign 客户端接口；异步靠两样东西：XXL-Job 轮询数据库表（171 个任务），和 RocketMQ。大部分「流程」其实是定时任务扫表。

**端口。** 仓库里只能看到 base-scm 465、ops 8203（mock-wms 8205），其余在 Nacos，不可见。你笔记里的「编号 504」在这套配置里找不到对应的端口，推测是 XXL-Job 执行器或任务的编号。

**体量。** 约 7400 个 Java 文件、57 万行。最大的三个是 base-scm（15.3 万行）、base-rule（9.1 万行）、scm-mms 和 mms-ops（各 7.4 万行）。

### 3.10 provider-erp-base-fio：导出

24 个 Controller 几乎都是 `/scm/export/**` 异步导出，数据经 Feign 取自各服务后上传 OSS。364 个文件、约 2.6 万行；198 次提交。只写一张表 `htm_scm_download_url`，不碰库存和单据。

## 四、服务之间怎么交互

交互图：[diagrams/03-服务交互业务图.puml](diagrams/03-服务交互业务图.puml)。一张时序图按业务分 7 段：采购入库、退供出库、门店配货、配货差异与判责、门店退货、仓间调拨和库位转移、库存调整和冻结。读图约定：参与方是服务，从左到右大致是发单的、执行的、记账的；黄底的系统和服务不在本地；圈号是每段内的先后，虚线箭头是回传。

图里下面几处是按常理补的（推测），或者本地看不到，引用前先确认：

- 库存记账中间层 inventory-middle 怎么改 base-ivm 的余额和流水。11 个仓库里只有对它的调用，没有它的代码。
- 门店提交收货的入口。`provider-biz-scms` 和门店 App 不在这批仓库里，只能看到 base-scm 被调用后的回写（`writeBackByIn`）。
- WMS 回传之后那条「入库结果」「出库结果」MQ 是谁发的。biz-scm 有监听（`rocketmq/InOrderMessageListener.java`），topic 配在 Nacos，生产者不在本地。
- 差异确认单 MQ 的消费方，不在本地。
- 采购发货单的四步跨服务写入（预约单、司机签到、发货任务、质检同步）来自代码盘点，没有逐步复核。

| biz-scm | inventory-middle（不在本地） | 出入库记账、预占、释放预占（全部记账都走它） |
| biz-scm | base-rule | 门店信息、商品、是否虚拟仓 |
| biz-scm | ops | WMS 取消、生鲜医药配送 |
| base-scm | base-ivm | 库位、库存查询、释放预占、改效期 |
| base-scm | inventory-middle（不在本地） | 出入库记账、预占 |
| base-scm | ops、ops-hdg、ops-job | WMS 取消、海鼎（25 个方法）、关单 |
| base-ivm | base-scm、base-rule | 商品入库规格、商品信息 |

### 4.2 异步：MQ 和定时任务

| 发出方 | topic | 接收方 | 传的是什么 |
|---|---|---|---|
| biz-scm | `ERP_ORDER_NOTICE_TOPIC` | ops | 通知单审核通过，由 ops 建单并推 WMS |
| ops | `ERP_STKOUT_BUSINESS_ORDER_HANDLE` | biz-scm | WMS 回传出库后的配货单处理（补成本、效期，再转给 base-scm） |
| biz-scm | `OPS_STKOUT_SYNC_STATUS_TOPIC` | base-scm | 配货单取消同步 |
| base-scm | `TOPIC_ERP_STOCK_WAY_SYNC` | base-ivm | 采购在途、调拨在途的数量，刷报表宽表 |
| biz-scm、base-scm | `TOPIC_OPS_RETURN_ORDER_NOTICE` | 门店侧（不在本地） | 退货单审核、退货入库、完成、取消 |
| biz-scm | `TOPIC_SCM_DIFF_ORDER_CONFIRM` | 不在本地 | 配货差异确认单 |
| 不在本地 | 「入库结果」「出库结果」 | biz-scm | WMS 回传结果，biz-scm 据此向 base-scm 建出入库单 |

biz-scm 和 base-ivm 的监听器和 topic 的对应关系配在 Nacos。表里前六行的 topic 名是代码里写死的字面量或常量；最后一行的名字在本地看不到，是按监听器的类名推的。

定时任务方面，和库存记账直接相关的是 biz-scm 的 `inoutOrderDealwith`：每轮入库、出库各取 1 条，处理完再释放 1 张通知单的预占，再审 1 张配货单，再处理 1 张差异单。其余任务的清单和风险见 [治理与风险.md](治理与风险.md)。

## 五、本地没有、但卡在链路上的服务

| 服务 | 谁在调它 | 它管什么 | 缺了它看不清什么 |
|---|---|---|---|
| provider-biz-inventory-middle | biz-scm、base-scm | 出入库记账、预占、释放预占 | 在途和差异到底怎么记、幂等怎么做 |
| provider-ops-job | ops、base-scm、base-ivm | 关单和作废的中台入口；海鼎出库差异建差异单 | 采购单和通知单怎么关单 |
| provider-ops-hdg | ops、base-scm、base-ivm | 海鼎适配 | 海鼎仓的回传和同步细节 |
| provider-biz-scms | wd-ops-brd、base-scm、biz-scm、base-rule、司机端 | 门店侧：退货交接、要货分发 | 门店收货、退货交接 |
| provider-biz-dc | wd-ops-brd、base-ivm、scm-mms | 配送（按名字推测） | 配送相关 |
| provider-base-shop、provider-common-support、provider-erp-auth、provider-base-configuration | 多个 | 门店主数据、字典、鉴权、公共配置 | 主数据从哪来 |
| CRM（Go）、算法、商品中心 | wd-ops-brd、biz-scm、base-rule、mms-ops | 采购、配货计划、商品 | 上游怎么发单、虚拟仓清单怎么维护 |

要把「在途、差异怎么记」这条线追到底，至少得先把 inventory-middle 和 ops-job 拉下来。
