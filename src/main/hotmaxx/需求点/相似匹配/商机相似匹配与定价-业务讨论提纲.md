# 商机相似匹配与定价：业务讨论提纲

## 一、背景

### 1. 现有流程（待业务确认）

买手提交商机 → 类目审核员审核 → BI → 生成提报单 → 类目长审核

### 2. 本次讨论的核心问题

这件事的目标究竟是：

- 找到“相似商品”；还是
- 找到“能够作为价格锚点、真正支持定价决策的商品”？

两者并不等价：商品相似，不代表其价格一定具有参考价值。还需要考虑价格来源、采集时间、促销状态、规格换算等因素。

### 3. 服务对象与业务价值

需要明确系统主要面向谁：

- 只面向类目长；
- 同时面向类目长和买手。

分别确认不同角色真正关心的问题：

- **买手**：当前最耗时、最容易被退回的环节是什么？希望系统解决什么问题？
- **类目长**：价格是否定得准确？能否快速找到可用的相似商品？匹配结果达到什么程度才有实际帮助？

最终需要把业务价值说成可验证的结果，例如：减少查价时间、减少重复查询、提高匹配命中率、降低定价偏差。

---

## 二、类目长到底要做什么决策

### 1. 审核决策与角色分工

- ★ 审核商机时，最终决定的是零售价、采购价、毛利，还是是否引进？
- 除了价格，还需要判断哪些内容：类目、品牌、规格、数量、保质期、供应商等？
- 什么情况下会直接驳回，而不是继续查价？
- 最终审核结果需要填写哪些字段？是否必须填写定价理由？
- 买手、类目审核员、BI、类目长及其他审核角色分别决定什么？是否存在二次审核？

### 2. 实际审核步骤与痛点

- 从收到商机到完成审核，中间实际经过哪几步？
- 哪几步最耗时间？为什么？
- 过去是否发生过明显的定价失误？代价是什么？
- 当时是哪一步判断错了？如果补充什么信息，原本可以避免？

**本节要拿到：**一张真实的审核流程，以及每个角色的输入、输出和主要痛点。

---

## 三、还原当前人工查价过程

建议让业务方拿一条真实商机，现场完整演示一遍。

### 1. 搜索与筛选过程

- ★ 收到商品后，第一步看什么？先用什么关键词搜索？
- 通常去哪些平台或零售渠道？按什么顺序查？
- 为什么采用这个顺序？什么情况下会放弃某个渠道？
- 会优先看品牌旗舰店、大型商超，还是销量高的店铺？
- 一般查几个商品就停止？停止条件是什么？
- 搜索结果很多时，凭什么判断哪个最有参考价值？
- 找不到对标商品时怎么办？

### 2. 时间消耗与信息沉淀

- 目前一条商机平均查价需要多久？最耗时间的是哪一步？
- 查完之后具体保存哪些信息？
- 为什么后续还会重复查询同一个商品？是已有数据找不到、不信任，还是已经过期？

**本节要拿到：**人工搜索词、渠道选择、候选筛选方式、停止条件和重复查询原因。这些内容可以直接沉淀为第一版匹配规则。

---

## 四、价格锚点从哪里来，什么价格才有效

### 1. 外部渠道及优先级

- 目前具体查询哪些外部渠道？按优先级排序，并说明原因。
- 同一个商品在不同渠道价格不同时，以哪个为准？
- 什么情况下会放弃某个渠道或某条价格？
- 不同平台、店铺类型、地区的价格，权重是否不同？
- 平台销量、店铺类型、品牌旗舰店身份是否影响参考价值？

### 2. 价格口径

- ★ 业务真正采用的是页面价、日常价，还是实际到手价？
- 券后价、会员价、多件折、限购价分别怎么处理？
- 是否需要把运费算进去？整箱包邮和单瓶包邮如何处理？
- 同一商品在不同店铺价格不同，取最低价、主流价，还是某个可信渠道的价格？
- 异常低价如何处理？临期、清仓、双十一等价格能否作为正常商品的有效参照？如何识别？

> 价格口径必须优先问清，否则即使商品匹配正确，也会产生系统性定价偏差。

### 3. 内部价格参考

除外部平台外，是否还会参考：

- 自有门店当前售价和历史售价；
- 其他区域门店价格；
- 供应商供货价区间；
- 上一张商机单的价格；
- 其他内部经营数据。

如果这些信息目前没有进入审核视野，需要继续确认：是没有数据、使用不方便，还是业务不认可？

### 4. 价格时效

- 采集多久以前的价格就不能再使用？不同品类是否不同？
- 当前竞品价格多久更新一次？
- 价格过期后，是降权、仅作展示，还是直接排除？

**本节要拿到：**渠道优先级、统一价格口径、异常价格排除规则和价格有效期。

---

## 五、把“相似商品”的定义问透

建议不要只讨论概念，直接拿例子逐个确认。

| 场景 | 需要确认的问题 |
| --- | --- |
| 条码相同 | 是否一定视为同款？换包装、新老版本是否例外？ |
| 名称相同但条码不同 | 可能是同款、连包还是不同规格？如何进一步判断？ |
| 单瓶与三连包 | 能否直接除以 3？包装溢价是否忽略？ |
| 500ml×12 与 500ml×24 | 是否属于同款？按单瓶价还是整箱价比较？ |
| 同系列不同容量 | 可以按每升价格换算，还是只能参考价格带？ |
| 同系列不同口味 | 哪些口味可互相参考？哪些存在明显价差？ |
| 不同品牌同类商品 | 能否作为定价依据？什么条件下可以使用？ |
| 赠品、组合装、临期装 | 是否排除？如何识别？ |

还需要确认：

- ★ 哪类关系可以直接用于定价，哪类只能辅助参考，哪类必须排除？
- 品牌、品类、口味、规格中，哪些绝对不能冲突？
- 连包、箱装拆成单件价时，内部是否有约定的折算方式？哪些情况不可比？
- 错把一个商品当成同款，最大的业务风险是什么？

**本节要拿到：**一张“商品关系—能否用于定价—换算规则”表。

## 六、从“市场参考价”到“好特卖定价”

这是最需要业务讲清楚的一段：找到价格锚点之后，并不等于已经得到最终售价。

### 1. 定价决策过程

- ★ 查到外部价格后，类目长还要经过哪些判断才能得到最终售价？
- 是否存在一条必须遵守的绝对规则？
- 是否有固定折扣率、公司折扣要求、价格带、尾数规则或最低毛利要求？
- 供应价、保质期、采购数量、门店数量分别如何影响定价？
- 规格换算之后，是否还要叠加保质期折扣？
- 临期程度不同，折扣规则是否不同？
- 同款商品的外部价格差异很大时，取最低价、中位数，还是某个渠道价格？

### 2. 系统输出形式

- 系统应该给一个价格、一个价格区间，还是几档定价方案？
- 除建议零售价外，是否还需要反推最高可接受采购价？
- 哪些规则可以明确写成公式，哪些只能依赖类目长经验？

**本节要拿到：**定价公式或决策因素清单，并明确区分“硬规则”和“经验判断”。

---

## 七、盘点已有商品库、历史数据和业务规模

### 1. 业务规模

- 每天大约产生多少条商机？
- 目前由多少人负责审核？
- 单个商品从查询到定价的平均耗时是多少？

### 2. 商品库规模与字段

- 当前商品信息库、竞品商品库分别有多少条数据？
- 数据主要从哪些渠道采集？
- 已经保存了哪些信息：条码、名称、品牌、类目、规格、包装数量、图片、价格、店铺、链接、采集时间等？
- 是否保存商品照片？图片质量能否支持识别包装和规格？
- 是否已有重复商品、同款关系或人工维护的匹配记录？

### 3. 数据质量与更新机制

- 竞品数据具体如何落库？字段口径是否统一？
- 现有数据样本是否可靠？如何验证真实性？
- 是否存在类目错误、价格为 0、规格缺失、重复记录等问题？
- 竞品价格多久更新一次？过期数据如何处理？
- 当前商品库的数据质量上限和后续扩展瓶颈是什么？
- 历史商机是否保留“候选商品—采用结果—最终定价—人工修改原因”？

**本节要拿到：**商品库现状、数据质量问题、更新机制，以及一批可用于验证的历史案例。

---

## 八、确认系统应该帮到哪一步

建议给业务方以下两种范围进行讨论：

### 方案一：只找商品

系统推荐候选商品，并说明匹配原因；人工完成规格换算和定价。

适合先验证匹配准确率，但对人工查价和计算的替代有限。

### 方案二：找商品并给参考价

系统完成商品匹配、规格和单位换算、异常价格排除，并给出参考价格区间；人工确认最终定价。

对审核效率帮助更直接，但依赖统一的价格口径和明确的换算规则。

需要进一步确认：

- ★ 当前最希望优先替代哪一步？
- 哪些错误宁可不返回结果，也绝对不能发生？
- 候选结果达到什么准确率，业务才愿意使用？
- 什么情况下必须人工确认？
- 类目长排除系统推荐后，是否愿意填写原因，供后续优化？

## 九、业务规则的三种处理方式

讨论过程中，将业务方的回答同步分成三类：

| 类型 | 典型表达 | 建议处理方式 |
| --- | --- | --- |
| 硬规则 | “一定这样判断”“这种情况绝对不能比” | 写进匹配或打分规则，不交给模型自由判断 |
| 经验系数 | “大概贵一成”“临期打七折” | 按类目保存为可配置参数，后续用真实数据校准 |
| 模糊经验 | “看情况”“凭感觉” | 作为 AI 需要辅助判断的灰区，同时优先积累人工审核样本 |

这张分类表可以帮助控制项目边界：不是所有问题都需要 AI，也不是所有经验都能立即写成固定规则。

## 十、验证方式

建议先让系统结果与人工审核并行运行，不直接替代人工决策。

重点对比：

- 系统候选与人工实际采用商品的差异；
- 系统参考价与人工最终定价的差异；
- 人工排除系统推荐的原因；
- 不同类目、不同匹配关系下的表现差异；
- 是否确实减少查询和换算时间。

通过差异分析，继续补充硬规则、校准经验系数，并识别真正需要 AI 处理的灰区。

---

## 十一、会议结束前需要确认的结论

- [ ] 系统目标是“找相似商品”，还是“找可用于定价的价格锚点”？
- [ ] 系统主要服务类目长，还是同时服务买手？
- [ ] 类目长最终要做出的决策及完整审核流程是什么？
- [ ] 哪些商品关系可以直接定价、辅助参考或必须排除？
- [ ] 外部价格采用什么口径，哪些渠道优先，多久以后失效？
- [ ] 从市场参考价到好特卖售价，还有哪些硬规则和经验因素？
- [ ] 当前商品库的数据规模、质量和更新机制是否支持第一期建设？
- [ ] 第一期选择“只找商品”还是“找商品并给参考价”？
- [ ] 第一期优先覆盖哪些类目和匹配场景？
- [ ] 使用哪些历史样本验证，由谁验收，以什么指标判断有价值？
