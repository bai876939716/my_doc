# 接口文档 · H5 ↔ Agent 服务

> 本文是前后端开发的**接口真值**，与 diagrams/03 两张交互泳道图对应。
> 上线前 TODO：真实域名、token 签发方式（复用 App 登录态）。

## 0. 通用约定

- 鉴权：`Authorization: Bearer <token>`（复用 App 登录态，服务端校验并绑定门店）
- 编码：JSON · UTF-8
- 并发：`ver` 乐观锁（每次响应带最新 ver，提交时校验，冲突返回 409）

## 1. 六接口总览

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/sessions` | POST | 建会话 / 恢复入口（见 §2.1） |
| `/api/sessions/{id}/messages` | POST | 用户消息，响应 SSE 流（见 §2.2） |
| `/api/sessions/{id}/upload` | POST | multipart 附件 → media_ids（见 §2.3） |
| `/api/sessions/{id}` | GET | 会话内刷新 / SSE 断线重连（见 §2.4） |
| `/api/sessions/{id}/submit` | POST | CONFIRM 提交（见 §2.5） |
| `/api/sessions/{id}/exit` | POST | 主动退出 keep / abandon（见 §2.6） |

## 2. 接口明细

### 2.1 建会话 / 恢复入口 —— `POST /api/sessions`

服务端先查 `rp:active:{uid}`：有活跃会话 → 复用返回（`is_resumed=true`，前端弹「继续上次报修」）；无 → 新建。恢复不依赖前端本地存储。

```json
// 响应 200
{
  "session_id": "rp_9f3k2m",
  "ver": 12,
  "is_resumed": false,
  "context": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "date": "2026-11-04", "phone": "138****1234" },
  "messages": [
    { "seq": 1, "type": "status_bar",  "data": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "phone": "138****1234" } },
    { "seq": 2, "type": "text",        "data": { "content": "白云翔你好！直接说哪儿坏了就行…" } },
    { "seq": 3, "type": "quick_cards", "data": { "cards": [ { "id": "c_cool", "title": "❄️ 冷柜/空调不制冷" } ] } }
  ]
}
```

### 2.2 发消息 —— `POST /api/sessions/{id}/messages`（响应 = SSE 流）

**用户消息 type 7 种**（按手势分类；只有 `text` 走 LLM，其余为结构化事件直接查状态机转移表）：

| type | body | 场景 |
|---|---|---|
| `text` | `{"type":"text","content":"冷柜不制冷了…"}` | 一切打字：描述 / 补充 / 改字段（如「电话换成店长的」） |
| `card` | `{"type":"card","card_id":"c_cool"}` | 点高频卡片（B 路径，类别直锁） |
| `enum_pick` | `{"type":"enum_pick","value":"工程类 - 制冷设备/冷柜"}` | 枚举卡点选；**CONFIRM 态收到同一 type = 确认单上重选类别**（状态机按 recat 回跳 PHOTO 重校验） |
| `seg_pick` | `{"type":"seg_pick","field":"expect_visit","value":"尽快上门"}` | 二选一点选：期望上门 / 影响营业（同一手势复用，状态机按当前状态解释） |
| `upload_done` | `{"type":"upload_done","media_ids":["m_001","m_002"]}` | 上传完成通知 |
| `phone` | `{"type":"phone","use_default":true}` 或 `{"type":"phone","phone":"13900000000"}` | 联系电话确认 / 修改 |
| `submit` | `{"type":"submit"}` | 确认单上点【确认提交】 |

**SSE 响应格式**（`Accept: text/event-stream`）：

```
event: typing                          ← 先行：前端立即显示"输入中"
data: {}

event: message                         ← 0..n 条：正文/卡片/确认单
data: {"seq":4,"type":"enum_card","data":{"preselect":0,"options":["工程类 - 制冷设备/冷柜","工程类 - 暖通/空调"]}}

event: done                            ← 终止：当前状态 + 版本号
data: {"state":"A_ENUM","ver":4}

: ping                                 ← 心跳注释行，每 15s 一条
```

**服务端消息 type 10 种**（每种对应前端一个组件，前端零业务逻辑）：

| type | 渲染组件 | 场景 |
|---|---|---|
| `status_bar` | 顶部状态条 | 进入时展示带出的门店 / 报修人 / 电话 |
| `text` | 对话气泡 | 话术模板拼装的助手消息 |
| `quick_cards` | 高频卡片墙 | 首屏 6 张卡 |
| `enum_card` | 枚举单选卡 | Top3 / 全量列表（首位预选、仅限点选） |
| `photo_guide` | 拍照引导 | 拍摄清单（购物袋类含袋底供应商标识红色警示） |
| `system_tip` | 系统提示条 | 缺项提示 / 错误提示（样式区别于对话气泡） |
| `seg_card` | 二选一卡 | 期望上门、影响营业复用 |
| `phone_confirm` | 电话确认卡 | 用本人号码 / 修改 |
| `confirm_card` | 确认单 | 10 字段平铺、点哪改哪、提交按钮；B 路径描述预填「类别＋详见现场照片」 |
| `result` | 结果卡 | 单号 + 状态 + 跳已有记录页按钮 |

### 2.3 上传附件 —— `POST /api/sessions/{id}/upload`

```
请求：multipart/form-data，字段 files[]（image/* 或 video/*）
响应 200：{ "media_ids": ["m_001"], "urls": ["https://oss…/m_001.jpg"] }
```

前端拿到 media_id 后发 `upload_done` 消息推进流程（文件不进消息通道）。

### 2.4 恢复会话 —— `GET /api/sessions/{id}`

会话内刷新 / SSE 断线重连。响应同 2.1（含当前 `state`、`collected_fields`、完整 `messages`、`ver`）；不存在或已废弃返回 404。

### 2.5 提交 —— `POST /api/sessions/{id}/submit`（仅 CONFIRM 态接受）

```json
// 请求（ver 乐观锁）
{ "ver": 9 }
// 响应 200
{ "order_no": "BX-20261104-1032", "status": "已提交 / 待派单" }
```

服务端先做 10 字段必填校验，再调 `create_repair_order`（order_key 幂等），成功后清 Redis 草稿 + MySQL 归档。

### 2.6 主动退出 —— `POST /api/sessions/{id}/exit`

```json
// 请求
{ "mode": "keep" }        // keep=保存草稿退出（7天可续） | abandon=放弃本次报修
// 响应 200（keep）
{ "result": "ok", "draft_expired_at": "2026-11-11T12:00:00+08:00" }
```

## 3. 错误码

| 码 | 场景 | 前端行为 |
|---|---|---|
| 401 | token 无效/过期 | 引导重新登录 |
| 404 | 会话不存在/已过期/已废弃 | 静默开新会话 |
| 409 | ver 冲突（双端并发） | GET 会话刷新后重试 |
| 422 | 提交时字段校验失败 | 收 confirm_card 高亮缺失项 |
| 429 | 当日 LLM 配额用尽 | 收 system_tip，降级卡片向导 |
| 503 | LLM 不可用 | 降级卡片向导 / 引导回表单，不阻塞报修 |
