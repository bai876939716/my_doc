# 接口文档 · H5 ↔ Agent 服务（design/4 全量版）

> **版本**：v2.0（2026-11-05 · 随 design/4 技能包化重构：`/agent/{skill}/v1` 多技能包、新增报销 4 组消息 type、state 改为图状态）｜**协议变更规则**：本文档是 H5 ↔ Agent 消息契约的唯一真值，新增/修改字段或 type 须前后端双方确认后同步本文档；type 只描述「手势/消息种类」，与前端组件实现解耦。
> 上线前 TODO：真实域名、token 签发方式（复用 App 登录态）。

## 0. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | `https://{gateway-host}/agent/{skill}/v1`，`skill` = 技能包名：报修 `repair`、报销 `expense`（经公司网关转发，按 `/agent/**` 路由到 Agent 服务，是否 StripPrefix 与平台组确认） |
| 版本 | `/v1` 属于业务（技能包）：各技能包独立升版；仅 H5 ↔ Agent 消息协议破坏性变更时升版本号，字段新增一律 v1 内兼容 |
| 会话 ID | 技能包前缀：报修 `rp_*`、报销 `ex_*` |
| 内容类型 | 请求/响应 `application/json; charset=utf-8`；SSE 响应 `text/event-stream` |
| 鉴权 | `Authorization: Bearer <token>`（App 登录态，网关校验后注入 `HTM-HEADER`） |
| 时间格式 | `yyyy-MM-dd'T'HH:mm:ss+08:00` |
| 并发 | 同一会话不做多端并发控制（后写覆盖，已知简化）；防重复提交由服务端 order_key（= 会话 ID）幂等保证 |
| 手机号 | 任何出参不出现完整手机号，一律掩码（`138****1234`） |

**错误响应体**（所有非 2xx 统一结构）：

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 业务错误码，见 §3 |
| message | string | 人话描述，前端可直接 toast |

## 1. 接口总览

| # | 接口 | 方法 | 用途 |
|---|---|---|---|
| 1 | `/agent/{skill}/v1/sessions` | POST | 建会话 / 恢复入口 |
| 2 | `/agent/{skill}/v1/sessions/{id}/messages` | POST | 用户消息（响应 = SSE 流） |
| 3 | `/agent/{skill}/v1/sessions/{id}/upload` | POST | 附件上传（multipart） |
| 4 | `/agent/{skill}/v1/sessions/{id}` | GET | 会话内刷新 / SSE 断线重连 |
| 5 | `/agent/{skill}/v1/sessions/{id}/submit` | POST | 确认提交 |
| 6 | `/agent/{skill}/v1/sessions/{id}/exit` | POST | 主动退出 |

## 2. 接口明细

### 2.1 建会话 / 恢复入口 —— `POST /agent/{skill}/v1/sessions`

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| store_no | string | 否 | 门店编号；默认取登录人绑定门店，督导多店时显式指定（报修用） |

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| session_id | string | 会话 ID（技能包前缀），后续接口路径参数 |
| is_resumed | boolean | true=复用了活跃会话（前端弹「继续上次填报」卡片） |
| context | object | 系统带出字段（报修：`store`/`reporter`/`date`/`phone_masked`；报销：另含 `apply_no` 申请编号等只读项） |
| messages | array | 首屏消息序列，**按 seq 顺序渲染**；元素结构见 §2.2 服务端消息 |

```json
{ "session_id": "rp_9f3k2m", "is_resumed": false,
  "context": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "date": "2026-11-05", "phone_masked": "138****1234" },
  "messages": [
    { "seq": 1, "type": "status_bar", "data": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "phone_masked": "138****1234" } },
    { "seq": 2, "type": "text", "data": { "content": "白云翔你好！直接说哪儿坏了就行，比如「冷柜不制冷了，今天早上开始的」" } },
    { "seq": 3, "type": "quick_cards", "data": { "cards": [ { "id": "c_cool", "icon": "❄️", "title": "冷柜/空调不制冷" } ] } }
  ] }
```

### 2.2 发消息 —— `POST /agent/{skill}/v1/sessions/{id}/messages`（响应 = SSE 流）

**请求公共字段**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| type | string | 是 | 手势类型，十种（见下）；只有 `text` 走 LLM，其余为结构化事件 |
| （其余字段） | — | — | 按 type 见下表 |

**用户消息 type 10 种**（`submit` 走独立接口 §2.5，不经 messages）：

| type | 附加字段 | 类型 | 说明 |
|---|---|---|---|
| `text` | content | string ≤500 | 一切打字：描述 / 补充 / 改字段 |
| `card` | card_id | string | 高频卡片 ID（报修：类别直锁；报销：费用项目快捷卡） |
| `enum_pick` | field / value | string ×2 | 枚举点选值（必须字典内）；confirm 态收到 = 确认单上改枚举字段（类别改动触发联动失效） |
| `seg_pick` | field / value | string ×2 | 二选一点选（报修 expect_visit / impact_business）；同一手势复用 |
| `upload_done` | media_ids | array\<string\> | 上传完成通知（先调 §2.3 拿 media_id） |
| `phone` | use_default 或 phone | boolean / string | 用本人号码 / 提交新号码（11 位正则校验） |
| `tree_pick`（报销） | field / path | string ×2 | 树路径点选结果；path=完整路径数组（服务端与树白名单复验） |
| `subtable_op`（报销） | op / row_id / cells | string ×3 | 行操作：`add` / `edit` / `del` / `confirm`；cells=行内字段值 |
| `group_submit`（报销） | field / values / use_memory | string / object / boolean | 字段组提交（收款人四件套）；use_memory=true 表示直接采用记忆预填值 |
| `input_submit` | field / value / row_id? | string ×3 | 键盘输入（金额 / 银行账号等），row_id 用于子表行内 |

**SSE 事件规范**：

| event | data 结构 | 说明 |
|---|---|---|
| typing | `{}` | 收到请求立即下发，前端显示"输入中" |
| message | `{ "seq": int, "type": string, "data": object }` | 0..n 条；data 按 type 见下表 |
| done | `{ "state": string, "focus": string? }` | 终止事件；state/focus 见 §4 枚举 |
| （注释行） | `: ping` | 每 15s 一条心跳，防中间层掐连接 |

**服务端消息 type 14 种（message.data 结构）**：

| type | data 字段 | 类型 | 说明 |
|---|---|---|---|
| `status_bar` | store / reporter / phone_masked | string ×3 | 顶部状态条（报销 context 同构，字段随技能包） |
| `text` | content | string | 对话气泡（模板话术） |
| `quick_cards` | cards[].id / icon / title | string ×3 | 高频卡片墙 |
| `enum_card` | field / mode / options[] / preselect | string ×4 | mode ∈ `top3`｜`full`；preselect=预选下标（-1 无）；**仅限点选** |
| `photo_guide` | need_count / tips[].text / tips[].level / warning | int / string / `info`｜`warn` / string? | 拍摄清单；warning 非空时红色警示 |
| `system_tip` | content / level | string / `info`｜`warn`｜`error` | 系统提示条（非对话语气） |
| `seg_card` | field / question / options[].value / options[].label | string ×4 | 二选一卡 |
| `phone_confirm` | phone_masked / use_default | string / boolean | 电话确认卡（报修） |
| `confirm_card` | groups[].group_name / groups[].items[].field·label·value·editable·source / missing[] | — / string ×5 / array\<string\> | 确认单；source ∈ `system_default`｜`ai_filled`｜`user_edited`；missing=缺失字段提示 |
| `result` | order_no / status / tip | string ×3 | 结果卡（单号/状态/提示文案，报销欠票补传提示在此） |
| `tree_card`（报销） | field / options[].path / options[].label_path / matched | string / array\<string\> / string / boolean | 部门树 Top3 完整路径确认卡；matched=false 时 options 为折叠树结构，前端渲染树搜索 |
| `subtable_card`（报销） | field / rows[].row_id / rows[].cells / rows[].status / can_add | string / object / `draft`｜`confirmed` / boolean | 子表行卡片列表；can_add=false 表示已达行数上限（10） |
| `group_card`（报销） | field / fields[].name·label·type·value·source / memory_hit | string / ×5 / boolean | 字段组确认卡（收款人四件套）；memory_hit=true 时 value 为记忆预填值 |
| `amount_card`（报销） | field / row_id? / unit / max | string ×4 | 金额/账号输入卡（数字键盘）；row_id 用于子表行内金额 |

### 2.3 上传附件 —— `POST /agent/{skill}/v1/sessions/{id}/upload`

**请求**：`multipart/form-data`，字段 `files[]`（image/* 或 video/*，单文件 ≤10MB，单会话 ≤5 个）。

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| media_ids | array\<string\> | 附件 ID，供 `upload_done` 消息引用 |
| urls | array\<string\> | 预览地址（OSS 临时链接） |

### 2.4 恢复会话 —— `GET /agent/{skill}/v1/sessions/{id}`

**响应 200**：结构同 §2.1，另增：

| 字段 | 类型 | 说明 |
|---|---|---|
| state | string | 当前图状态（§4 枚举），前端据此渲染当前步骤 |
| focus | string? | collecting 态下当前正在采集的槽位名 |
| collected | object | 已采集槽位（含 source；报销含 rows 子表行），确认单/回显用 |

404 = 会话不存在 / 已过期 / 已废弃 → 前端静默开新会话。

### 2.5 提交 —— `POST /agent/{skill}/v1/sessions/{id}/submit`（仅 confirm 态接受）

**请求**：无请求参数（服务端以会话快照为准，order_key = 会话 ID）。服务端行为 = 恢复 confirm 节点的 interrupt 挂起（`Command(resume)`）。

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| order_no | string | 单号（明道云返回：报修 `BX-*` / 报销 `FY-*`） |
| status | string | 状态（如「已提交 / 待提交」） |

服务端流程：全字段必填校验（报修卡片路径描述自动补默认值；报销行数/金额一致性校验）→ 建单工具（order_key 幂等）→ 清 Redis（检查点 + 活跃索引）→ 终态归档 MySQL（报销另写回收款人记忆）。

### 2.6 主动退出 —— `POST /agent/{skill}/v1/sessions/{id}/exit`

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| mode | string | 是 | `keep`=保存草稿（7 天可续）｜`abandon`=放弃本次填报 |

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| result | string | 固定 `ok` |
| draft_expired_at | string | keep 时返回，草稿过期时间；abandon 不返回 |

## 3. 错误码

| code | HTTP | 场景 | 前端行为 |
|---|---|---|---|
| 40101 | 401 | token 无效/过期 | 引导重新登录 |
| 40401 | 404 | 会话不存在/过期/废弃 | 静默开新会话 |
| 42201 | 422 | 提交字段校验失败 | 收 confirm_card，高亮 missing 字段 |
| 42901 | 429 | 当日 LLM 配额用尽 | 收 system_tip，降级卡片向导 |
| 50301 | 503 | LLM 不可用 / 引擎运行时异常 | 降级卡片向导 / 引导回表单 |
| 50302 ❗ | 503 | 明道云提交失败-已转待重试（**待评审确认后正式启用**） | 提示稍后自动重试 + 客服兜底 |

## 4. 枚举字典

**图状态 state（5）**：`collecting`（采集进行中）/ `confirm`（确认单挂起，等 submit）/ `done`（提交成功）/ `exited`（主动退出）/ `fallback`（降级卡片向导）

**focus 常用槽位名**（由技能包 schema 定义）：

| 技能包 | focus 取值 |
|---|---|
| 报修 | `category` · `detail` · `photos` · `expect_visit` · `impact_business` · `phone` |
| 报销 | `expense_rows`（子表）· `dept`（部门树）· `office`（办公地点）· `pay_company` · `invoice_state` · `payee`（收款人组）· `attachments` |

**seg_pick.field（2，报修）**：`expect_visit` ｜ `impact_business`

**enum_card.mode（2）**：`top3`（AI 候选）｜ `full`（FALLBACK 全量）

**subtable_op.op（4，报销）**：`add` ｜ `edit` ｜ `del` ｜ `confirm`

**invoice_state（3，报销字典）**：`有发票/收据` ｜ `无发票/无收据` ｜ `欠票/收据`

**槽位 source（3）**：`system_default` ｜ `ai_filled` ｜ `user_edited`

## 5. 场景示例

> 按 H5 真实交互时序串联的完整报文流，字段与 §2/§4 枚举一一对应。
> 通用约定：`seq` 全会话单调递增；SSE 三事件 `typing / message / done`，每 15s 一条 `: ping` 心跳（注释行，前端忽略）；出参手机号一律掩码。

### 5.1 场景一 · 报修自由描述（主路径全流程）

**① 建会话 `POST /agent/repair/v1/sessions`**：同 §2.1 示例（`store_no: null`）。

**② 自由描述（全流程唯一 LLM 调用点）`POST .../rp_9f3k2m/messages`**

```json
{ "type": "text", "content": "店里的冷藏风幕柜不制冷了，柜内温度显示15度，今天早上开始的，里面的鲜奶不敢卖只好全下架了。" }
```

响应 = SSE 流（`text/event-stream` 原文）：

```
event: typing
data: {}

event: message
data: {"seq":4,"type":"text","data":{"content":"听下来了。我认出的类别如下——怕报错被驳回，点一下确认（不对就选别的）："}}

event: message
data: {"seq":5,"type":"enum_card","data":{"field":"category","mode":"top3","options":["工程类 - 制冷设备/冷柜","工程类 - 暖通/空调","特别紧急 - 影响营业的紧急故障"],"preselect":0}}

event: done
data: {"state":"collecting","focus":"category"}
```

> `preselect: 0` = AI 首位预选仅影响卡片顺序，**必须点选**才入槽（enum_first_pick 埋点在此触发）。

**③ 点选类别 → 拍照引导**

```json
{ "type": "enum_pick", "field": "category", "value": "工程类 - 制冷设备/冷柜" }
```

```
event: message
data: {"seq":6,"type":"text","data":{"content":"类别登记好了。麻烦拍两张现场照片：设备整体 + 问题部位，维修师傅好提前判断。"}}

event: message
data: {"seq":7,"type":"photo_guide","data":{"need_count":2,"tips":[{"text":"设备整体一张","level":"info"},{"text":"问题部位特写一张","level":"info"}],"warning":null}}

event: done
data: {"state":"collecting","focus":"photos"}
```

**④ 上传照片 `POST .../rp_9f3k2m/upload`（multipart）→ `upload_done`**

```json
{ "type": "upload_done", "media_ids": ["m_001", "m_002"] }
```

```
event: message
data: {"seq":9,"type":"seg_card","data":{"field":"expect_visit","question":"期望上门","options":[{"value":"维修人员尽快上门","label":"🔧 维修人员尽快上门"},{"value":"可等待安排","label":"🗓 可等待安排"}]}}

event: done
data: {"state":"collecting","focus":"expect_visit"}
```

### 5.2 场景二 · 报修高频卡片（0 次 LLM，只列差异）

```json
{ "type": "card", "card_id": "c_cool" }
```

直接下发 `photo_guide`（`focus: photos`）；购物袋类差异（`c_bag`）`warning` 非空触发红色警示。卡片路径确认单差异：`detail` 为空自动补默认值 `"制冷设备/冷柜，详见现场照片"`（source `system_default`）。

### 5.3 场景三 · 断点恢复（杀 App 后重进 / 主动退出 keep 后重进）

统一入口 `POST /agent/expense/v1/sessions`（不带本地 session_id，恢复不依赖前端缓存）：

```json
{
  "session_id": "ex_7a2k9f",
  "is_resumed": true,
  "context": { "store": "11522 安徽商之都OK店", "apply_no": "FY-20261105-0012", "date": "2026-11-05" },
  "messages": [
    { "seq": 18, "type": "confirm_card", "data": { "...": "会话内已产生的消息按 seq 重放" } },
    { "seq": 19, "type": "text", "data": { "content": "检测到未完成的报销（2 行费用明细），继续上次填写？" } }
  ]
}
```

前端弹「继续上次填报」卡片；用户确认后按快照渲染界面。

会话内刷新 / SSE 断线重连：`GET .../ex_7a2k9f`——结构同上，另含 `state` / `focus` / `collected`；404（code 40401）时前端静默开新会话：

```json
{ "state": "collecting", "focus": "payee", "collected": { "dept": {"path":["华东大区","安徽","合肥"],"source":"user_edited"}, "rows": [{"item":"门店费用-房租","amount":"5000.00","days":31}] } }
```

### 5.4 场景四 · 随时可改（任意时刻打字，焦点不变）

在 `focus: expect_visit` 时打字改电话：

```json
{ "type": "text", "content": "电话换成店长的 13900005678" }
```

```
event: typing
data: {}

event: message
data: {"seq":13,"type":"text","data":{"content":"已把联系电话更新为「139****5678」，继续当前的步骤就行。"}}

event: done
data: {"state":"collecting","focus":"expect_visit"}
```

> `done.focus` 与改前相同——改普通字段原地覆盖槽位、**议程不变**；检查点已自动更新。

confirm 态重选类别（例外，联动失效）：发 `{"type":"enum_pick","field":"category","value":"工程类 - 照明/招牌"}` → 钩子触发照片清单重校验 → `done` 返回 `{"state":"collecting","focus":"photos"}`。

### 5.5 场景五 · 异常与降级

**提交缺字段（422）**——`POST /submit` 时照片缺失：

**会话 LLM 次数超限（429 → 降级卡片向导）**——打字消息仍返回 SSE，但不再调 LLM：

### 5.8 前端联调自查清单

| 检查项 | 口径 |
|---|---|
| seq 连续性 | 每条 message.seq 严格递增；重连后从快照重放不重不漏 |
| SSE 事件 | 只有 typing / message / done 三种 event；`: ping` 心跳按注释行忽略 |
| 状态一致性 | done.state ∈ 5 种；collecting 必带 focus；改字段消息的 state/focus 不变 |
| 手机号/账号 | 出参掩码；入参走正则（手机 11 位、账号数字串） |
| 枚举值 | enum_card.options / tree_card.path / seg_pick.value 全部来自服务端字典，前端不自持枚举 |
| 子表 | 行操作逐行确认；can_add=false 时隐藏「加一行」；行内必填齐才允许提交 |
| 幂等 | submit 重复点击只产生一个 order_key；重试返回同一单号 |
