## 2. slots.py · 10 槽位全量（声明顺序 = 议程问序）

```python
class RepairSlots(SkillSlots):

    # —— 带出组（不问，状态条展示）——
    store    = Slot(ContextSlot, label="门店名称", required=True,
                    source_tool="get_user_context", editable=False)
    reporter = Slot(ContextSlot, label="报修人员", required=True,
                    source_tool="get_user_context", editable=True)   # 店长替店员报修可改
    date     = Slot(ContextSlot, label="报修日期", required=True, default="today")

    # —— 采集组（进议程）——
    category = Slot(EnumSlot, label="报修类别", required=True,
                    dict_source="repair_category", card="enum_card",
                    hooks=[MustPick(),                                   # AI 只提名，点选才入库
                           OnChange(invalidates=["photos", "detail"])])  # 重选联动

    detail   = Slot(TextSlot, label="描述具体故障", required=True,
                    pattern="故障现象/发生时间/影响范围", max_len=100,
                    hooks=[DefaultFill(when="category_from_card",          # 卡片路径免描述
                                       value="{category_short}，详见现场照片")])

    photos   = Slot(MediaSlot, label="现场照片", required=True,
                    check_list="repair_category.shots",                    # 按类别拍摄清单（0 LLM）
                    card="photo_guide", max_files=5)

    expect_visit = Slot(EnumSlot, label="期望上门", required=True,
                    dict_source=StaticDict(["维修人员尽快上门", "可等待安排"]),
                    card="seg_card")

    impact   = Slot(EnumSlot, label="影响营业", required=True,
                    dict_source=StaticDict(["是", "否"]),
                    predict=True,                                          # extract 可预判，点选确认
                    card="seg_card")

    phone    = Slot(ContextSlot, label="联系电话", required=True,
                    source_tool="get_user_context.phone", editable=True,
                    card="phone_confirm")

    # —— 选填组（不进议程，确认单可补）——
    expect_process = Slot(TextSlot, label="期望处理", required=False, ask=False)
```

## 4. hooks.py · 钩子注册表

| 钩子 | 挂在 | 触发时机 | 规则 |
|---|---|---|---|
| `MustPick` | category | extract 产出候选 | 候选只进卡片不进槽位；`enum_pick` 才定稿 |
| `OnChange(invalidates=[photos, detail])` | category | 类别被改（含确认单重选） | 照片/描述失效重问、清单重校验 |
| `DefaultFill` | detail | 卡片路径进 confirm 且 detail 为空 | 自动填「类别细分名 + 详见现场照片」，确认单展示可编辑 |
| `SubmitCheck` | 包级 | submit 节点 | 10 必填齐（卡片路径默认值先行补齐）才放行建单 |

# 二、报销包接入推演（摘要 · 待业务访谈后转正式设计）

> 用真实报销表单（门店费用通道，24 字段）做全字段映射，验证架子装得下复杂业务。❗本节数据来源为表单截图 OCR + 口述，访谈后定稿。

**字段全景**：只读 13 项（申请编号/申请日期/审批状态/大区/门店类型/欠票到期/冻结状态/请款状态/大写金额/税额合计×2/费用承担门店×3）+ 对话采集 11 项。

**三个最难字段的承接方式**（新增机制均不碰引擎流程）：

| 难点 | 承接 | 新增什么 |
|---|---|---|
| 部门树筛选（所在/一级部门） | `tree` 类型：说部门名 → 树匹配 Top3 **完整路径** → 点选 | 1 张卡片（路径确认卡）+ 1 道闸（路径白名单）+ 1 个推导钩子（一级随路径带出） |
| 费用明细子表（多行） | `subtable` 类型：一句话抽多行草稿 → 行卡片逐行确认 | 1 张卡片（行卡列表）+ 1 道闸（行数/行内必填） |
| 收款人四件套（重复填） | `subgroup` + 记忆工具：首次填过，下次"用上次的/改" | 1 张卡片（组卡）+ 2 个记忆工具（recall/save，走 ToolProvider） |

**接入账**（对照 SOP 五步）：≈4~5 人天后端 + 2 人天前端（4 个新卡片形态）；引擎、通用图、既有卡片协议零改动。
