# 会话管理与草稿恢复

> 一句话：**会话即草稿**——Checkpointer 每个节点后自动把 State 落 Redis（窗口内消息在 State、全量在 MySQL 消息表）；无论杀 App、断网还是主动退出，进度天然不丢，重进一个请求续填。
> 接口报文：[接口文档.md](./接口文档.md)｜State 结构：[State设计.md](./State设计.md)

---

## 一、生命周期

1. **出生**：`POST /sessions` → 查活跃索引 `rp:active:{uid}`（后续技能包同构）：有则复用（`is_resumed=true`，弹「继续上次填报」），无则新建并 `load_context` 带出，首个检查点落盘。
2. **成长**：每条用户消息 = 一轮图执行，**每个节点后自动存档**（零业务存档代码）；轮末把本轮消息**同步批量 upsert 入 MySQL 消息表**，再裁剪 State 窗口至最近 10 轮。三条规则保证正确性：**先入库再裁剪**（被裁必已入库）、**(session_id, seq) 唯一键 + upsert**（崩溃后重执行重发同 seq，后写覆盖自愈）、**seq 用计数器生成**（裁剪后 length 不可当序号）——推演见《[ext/关键决策问答.md](./ext/关键决策问答.md)》State 设计决策 9。
3. **三种终态**：**DONE**（建单成功 → 摘要归档一行 → 删检查点 + 活跃索引）；**keep**（检查点保留 7 天，重进提示续填）；**abandon**（标记废弃，留 24h 排查）。
4. **过期**：TTL 到期自动清 + 每日清理任务兜底（删前确认消息已全量在库）；超期重进静默开新会话。

**错误退出零处理**：存档时机是"每个节点后"而非"退出时"——杀 App、断网来不及发请求，检查点早已最新。**并发（已知简化）**：同一会话不做多端并发控制（后写覆盖），防重复提交由 order_key 幂等保证。

## 二、数据留存

| 存储 | Key / 表 | 内容 | 留存 |
|---|---|---|---|
| Redis | 检查点（thread_id = 会话） | 整个 State：槽位/议程/上下文/**消息窗口（最近 10 轮）** | TTL 7 天，活跃滑动续期 |
| Redis | `rp:active:{uid}` | 活跃会话索引：用户 → 当前会话 | 建会话写；DONE/abandon/过期清 |
| Redis | `quota:{uid}:{yyyyMMdd}` | 单人单天 LLM 配额 | 当日过期 |
| MySQL | 消息表 | **全量对话，每轮批量 upsert**（唯一键幂等） | 长期：审计/回放/复原数据源 |
| MySQL | 会话归档表 | 终态摘要一行（context/slots/meta JSON） | 长期，对账 |
| MySQL | 埋点明细 | 埋点事件（含 skill 维度） | 长期 |

要点：**恢复不依赖前端本地**——重进统一 `POST /sessions` 按活跃索引复用，换设备/清缓存都成立；前端存的 session_id 只作刷新/断线重连加速。照片本体在 OSS，检查点只存 media_id。

## 三、接口与草稿的关系

| 接口 | 草稿动作 |
|---|---|
| `POST /sessions` | 查活跃索引：复用（get_state 重放）/ 新建 + 首存 |
| `POST /messages` | 一轮图执行，节点逐个自动存档；轮末消息入库 + 裁剪 |
| `POST /upload` | media_ids 并入槽位后存档 |
| `GET /{id}` | 只读：会话内刷新 / 断线重连（快照 + 消息重放） |
| `POST /submit` | resume → submit；成功后归档 + 清检查点/索引 |
| `POST /exit` | keep：保留 7 天；abandon：标记废弃 |

两处防坑：闲聊拉回轮次只追加消息、议程不动，同样存档；配额 Key 与检查点独立，超限降级不影响草稿。

## 四、复原（两源拼接，前端无感）

```
POST /sessions → 活跃索引命中
 → get_state：槽位 + 议程 + focus + 窗口尾巴（最近 10 轮）
 → MySQL 查 seq < 窗口首条 的全部消息
 → 拼接下发：老消息（库）+ 窗口（Redis）+ 按焦点渲染当前步骤
```

- **错误退出重进**：检查点停在 `focus: photos` 之类，重放回原步骤、已答全回显，零 LLM。
- **keep 7 天内重进**：弹「继续上次填报」→ 点选恢复（draft_resume 埋点）。
- **TTL 过期后**：草稿按设计失效开新会话，但消息在库永久可查（"上次对话记录还在，重新填一次"）。
- **对账兜底**：复原时 DB 的 max(seq) 落后于窗口最早 seq 就现场补写；每日任务全量对账，异常（只可能是规则违背）告警。

## 五、演进项（放量后）

同步批量 → 异步批量：轮末只投进程内写器（攒批 flush），配**裁剪同步门槛**（裁前必 flush）+ 每日对账——窗口天然是缓冲区，零丢失；主路径不再等待 DB。
