# 接口文档 · H5 ↔ Agent 服务（报修技能包）


## 0. 通用约定

| 项 | 约定                                                       |
|---|----------------------------------------------------------|
| Base URL | `https://{gateway-host}/agent/repair/v1`                 |
| 内容类型 | 请求/响应一律 `application/json; charset=utf-8`（同步 JSON ）      |
| 时间格式 | `yyyy-MM-dd'T'HH:mm:ss+08:00`                            |
| seq / role | 消息序号全会话单调递增，**用户消息与服务端消息统一编号**；每条消息带 `role`（`user`｜`server`），**响应回显用户消息**，前端按 seq 渲染完整时间线 |

**错误响应体**：

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 业务错误码 |
| message | string | 人话描述，前端可直接 toast |

## 1. 接口总览

| # | 接口 | 方法 | 用途 |
|---|---|---|---|
| 1 | `/agent/repair/v1/sessions` | POST | 建会话 / 恢复入口 |
| 2 | `/agent/repair/v1/sessions/{id}/messages` | POST | 用户消息（响应 = JSON：本轮新增消息 + state/focus） |
| 3 | `/agent/repair/v1/sessions/{id}/upload` | POST | 附件上传（multipart） |
| 4 | `/agent/repair/v1/sessions/{id}` | GET | 会话内刷新 / 响应超时后对齐重放 |
| 5 | `/agent/repair/v1/sessions/{id}/submit` | POST | 确认提交 |
| 6 | `/agent/repair/v1/sessions/{id}/exit` | POST | 主动退出 |

## 2. 接口明细


### 2.1 建会话 / 恢复入口 —— `POST /agent/repair/v1/sessions`

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| store_no | string | 否 | 门店编号；默认取登录人绑定门店，督导多店时显式指定 |

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| session_id | string | 会话 ID（`rp_` 前缀），后续接口路径参数 |
| is_resumed | boolean | true=复用了活跃会话（前端弹「继续上次报修」卡片） |
| context | object | 系统带出字段：`store`(string) / `reporter`(string) / `date`(string) / `phone_masked`(string) |
| messages | array | 首屏消息序列，**按 seq 顺序渲染**；元素结构 `{"seq", "role", "type", "data"}` |

**场景 ① · 首次进入**（无活跃会话 → 新建并带出 context）：

```json
{ "session_id": "rp_9f3k2m", "is_resumed": false,
  "context": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "date": "2026-11-05", "phone_masked": "138****1234" },
  "messages": [
    { "seq": 1, "role": "server", "type": "status_bar", "data": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "phone_masked": "138****1234" } },
    { "seq": 2, "role": "server", "type": "text", "data": { "content": "白云翔你好！直接说哪儿坏了就行，比如「冷柜不制冷了，今天早上开始的」" } },
    { "seq": 3, "role": "server", "type": "quick_cards", "data": { "cards": [ { "id": "c_cool", "icon": "❄️", "title": "冷柜/空调不制冷" } ] } }
  ] }
```

**场景 ② · 断点恢复**（杀 App 后重进 / 主动退出 keep 后重进；不带本地 session_id，恢复不依赖前端缓存）：

```json
{
  "session_id": "rp_9f3k2m",
  "is_resumed": true,
  "context": { "store": "11522 安徽商之都OK店", "reporter": "白云翔", "date": "2026-11-05", "phone_masked": "138****1234" },
  "messages": [
    { "seq": 13, "role": "server", "type": "confirm_card", "data": { "...": "会话内已产生的消息（含用户消息，带 role）按 seq 重放（此处截取末尾）" } },
    { "seq": 14, "role": "server", "type": "text", "data": { "content": "检测到未完成的报修（工程类 - 制冷设备/冷柜），继续上次填写？" } }
  ]
}
```

前端弹「继续上次报修」卡片；用户确认后按已回放的消息渲染界面（已答全回显，界面停在上次问到的那一步）。

### 2.2 发消息 —— `POST /agent/repair/v1/sessions/{id}/messages` 

**请求体**：一个 JSON 对象，`type` 必带，其余字段由 type 决定（`submit` 走独立接口  不经 messages）。

**type 枚举（7 种）· 每种一个全量请求示例**：

| type | 请求示例 | 语义 |
|---|---|---|
| `text` | `{"type":"text","content":"冷柜不制冷了，尽快派人来修","source":"keyboard"}` | 一切打字：描述 / 补充 / 改字段；语音输入经前端 ASR 转文字回填后同此 type（source 传 `voice`） |
| `card` | `{"type":"card","card_id":"c_cool"}` | 高频卡片：类别直锁，免类别免描述 |
| `enum_pick` | `{"type":"enum_pick","field":"category","value":"工程类 - 制冷设备/冷柜"}` | 枚举点选；confirm 态收到 = 确认单重选类别，触发照片/描述联动重校验 |
| `seg_pick` | `{"type":"seg_pick","field":"expect_visit","value":"维修人员尽快上门"}` | 二选一点选；field ∈ `expect_visit`｜`impact_business`；confirm 态收到 = 在确认单上改值（见场景 C3） |
| `upload_done` | `{"type":"upload_done","media_ids":["m_001","m_002"]}` | 上传完成通知（media_id 来自上传接口） |
| `phone` | `{"type":"phone","use_default":true}` ｜ `{"type":"phone","phone":"13900005678"}` | 用本人号码 / 提交新号码，二选一；confirm 态收到 = 在确认单上改电话 |
| `media_remove` | `{"type":"media_remove","media_id":"m_001"}` | 删除一张已传照片（见场景 C4） |

**请求字段说明**：

| 字段 | 类型 | 必填  | 适用 type | 说明                                     |
|---|---|-----|---|----------------------------------------|
| type | string | 是   | 全部 | 上表 7 种之一                               |
| content | string ≤500 | 是   | `text` | 文本内容；语音场景 = ASR 转写并经用户确认的文本            |
| source | string | 是   | `text` | 输入方式：`keyboard`｜`voice` 本期 只传 keyboard |
| card_id | string | 是   | `card` | 高频卡片 ID                                |
| field | string | 是   | `enum_pick` / `seg_pick` | enum_pick 固定 `category`；seg_pick 为 `expect_visit`（期望上门）｜`impact_business`（影响营业） |
| value | string | 是   | `enum_pick` / `seg_pick` | 点选值，必须服务端字典内                           |
| media_ids | array\<string\> | 是   | `upload_done` | 上传接口返回的附件 ID                          |
| media_id | string | 是   | `media_remove` | 要删除的附件 ID（须在已传清单内，否则 42201） |
| use_default | boolean | 二选一 | `phone` | `true` = 用本人号码                         |
| phone | string | 二选一 | `phone` | 新号码，服务端 11 位正则校验                       |

**响应 200（同步 JSON：一轮一次请求，图执行完毕后一次性返回本轮全部新增消息 = 用户消息回显 + 服务端消息）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| state | string | 本轮结束后的图状态：`collecting`（采集中）｜`confirm`（确认单挂起）｜`done`（已提交）｜`exited`（已退出）｜`fallback`（降级卡片向导），前端据此渲染当前步骤 |
| focus | string? | collecting 态下当前正在采集的字段名：`category`｜`detail`｜`photos`｜`expect_visit`｜`impact_business`｜`phone` |
| messages | array | 本轮新增消息 0..n 条（**含用户消息回显**），**按 seq 升序**；元素结构 `{"seq": int, "role": "user"｜"server", "type": string, "data": object}`——`role=user` 条目为请求回显（data = 请求体除 `type` 外字段原样），`role=server` 的 type/data 见下表 |

> 打字消息（LLM 轮）服务端处理最长 ~10s，前端展示"处理中"态；请求超时/响应丢失 → 调 `GET /{id}` 对齐。
> **回显口径**：用户消息计入 seq 且**随响应回显**（role=user、data=请求体除 type 外字段原样）——前端拿到响应即可整轮渲染，"处理中"占位由回显条目替换，不靠本地拼接；seq 由服务端生成，前端不自行计算。

**服务端消息 type 10 种（message.data 结构）**：

| type | data 字段 | 类型 | 说明 |
|---|---|---|---|
| `status_bar` | store / reporter / phone_masked | string ×3 | 顶部状态条 |
| `text` | content | string | 对话气泡（模板话术） |
| `quick_cards` | cards[].id / icon / title | string ×3 | 高频卡片墙 |
| `enum_card` | field / mode / options[] / preselect | string ×4 | mode ∈ `top3`｜`full`；preselect=预选下标（-1 无）；**仅限点选** |
| `photo_guide` | need_count / tips[].text / tips[].level / warning | int / string / `info`｜`warn` / string? | 拍摄清单；warning 非空时红色警示（购物袋拍袋底供应商标识） |
| `system_tip` | content / level | string / `info`｜`warn`｜`error` | 系统提示条（非对话语气） |
| `seg_card` | field / question / options[].value / options[].label | string ×4 | 二选一卡（期望上门 / 影响营业复用） |
| `phone_confirm` | phone_masked / use_default | string / boolean | 电话确认卡 |
| `confirm_card` | groups[].group_name / groups[].items[].field·label·value·editable·source / missing[] | — / string ×5 / array\<string\> | 10 字段确认单；source ∈ `system_default`｜`ai_filled`｜`user_edited`；missing=缺失字段提示 |
| `result` | order_no / status / tip | string ×3 | 结果卡（单号 / 状态 / 提示文案）；由前端用 submit 响应组装渲染 |

**场景 A · 自由描述（主路径）**

A1 描述（说到的字段直接预填）：

响应 = 回显 + 更新话术；若删除的是拍摄清单必拍项，追加下发 `photo_guide` 提示补拍。删除不在已传清单内的 media_id → `42201`。

**场景 D · 降级（照样交单）**

打字消息超过单会话 LLM 配额后：**仍返回 200**，state 切 `fallback`，下发卡片向导（连续识别失败同理；当日配额用尽、AI 服务不可用才走错误码 42901 / 50301，见错误码表）：

```json
{ "state": "fallback", "focus": null, "messages": [
  { "seq": 17, "role": "user", "type": "text", "data": { "content": "冷柜还是不制冷，麻烦再看下", "source": "keyboard" } },
  { "seq": 18, "role": "server", "type": "system_tip", "data": { "content": "AI 手速有点慢，先用卡片点选填，一样能交单", "level": "warn" } },
  { "seq": 19, "role": "server", "type": "enum_card", "data": { "field": "category", "mode": "full", "options": ["（全量类别列表，来自字典）"], "preselect": -1 } }
] }
```

### 2.3 上传附件 —— `POST /agent/repair/v1/sessions/{id}/upload`

**请求**：`multipart/form-data`，字段 `files[]`（image/* 或 video/*，单文件 ≤10MB，单会话 ≤5 个）。

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| media_ids | array\<string\> | 附件 ID，供 `upload_done` 消息引用 |
| urls | array\<string\> | 预览地址（OSS 临时链接） |

**场景 ① · 正常上传**（对应场景 A3 前置）：选 2 张照片 → `{"media_ids": ["m_001", "m_002"], "urls": ["https://oss.../m_001.jpg", "https://oss.../m_002.jpg"]}` → 前端随发 `upload_done` 消息（场景 A3）。

**场景 ② · 非法文件被拒**：单文件 >10MB / 第 6 张 / 非 image·video 格式 → `42201` + 人话提示，已传照片不受影响。

### 2.4 恢复会话 —— `GET /agent/repair/v1/sessions/{id}`

**响应 200**：结构同建会话响应（session_id / is_resumed / context / messages），另增：

| 字段 | 类型 | 说明 |
|---|---|---|
| state | string | 当前图状态：`collecting`（采集中）｜`confirm`（确认单挂起）｜`done`（已提交）｜`exited`（已退出）｜`fallback`（降级卡片向导），前端据此渲染当前步骤 |
| focus | string? | collecting 态下当前正在采集的字段名：`category`｜`detail`｜`photos`｜`expect_visit`｜`impact_business`｜`phone` |
| collected | object | 已采集字段（含 source），确认单/回显用 |

404 = 会话不存在 / 已过期 / 已废弃 → 前端静默开新会话。

> 复原/重连返回的 `messages` 为**全量**（含用户消息回显，带 role），前端无感。

**场景 ① · 响应超时对齐 / 会话内刷新**（messages 请求超时或响应丢失后补齐，不重不漏）：

```json
{ "state": "collecting", "focus": "photos", "collected": { "category": "工程类 - 制冷设备/冷柜", "photos": ["m_001"] } }
```

**场景 ② · 会话已不存在**（abandon 后 / 超过 7 天过期）：`404 {"code": 40401, "message": "会话不存在或已过期"}` → 前端静默开新会话（历史对话仍在库可查）。

### 2.5 提交 —— `POST /agent/repair/v1/sessions/{id}/submit`（仅 confirm 态接受）

**请求**：无请求参数——以服务端记录的会话内容为准提交（order_key = 会话 ID）。

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| order_no | string | 报修单号（明道云返回） |
| status | string | 工单状态（如「已提交 / 待派单」） |

**幂等**：order_key = 会话 ID——重复点击/网络重试只建一单，返回同一单号；提交成功后会话终结，后续 GET 返回 404。

**场景 ① · 提交成功**（对应场景 A4 之后的确认单）：

```json
{ "order_no": "BX-20261105-0007", "status": "已提交 / 待派单" }
```

前端用响应字段渲染 `result` 卡（单号 + 状态 + 「查看报修记录」跳已有记录页）。

**场景 ② · 缺必填字段（422）**：

```json
{ "code": 42201, "message": "还有 1 项没填：现场照片" }
```

前端停在确认单，高亮 missing 字段。

**场景 ③ · 明道云提交失败（50302，❗待评审确认后正式启用）**：

```json
{ "code": 50302, "message": "提交暂时失败，已记录自动重试；紧急请联系客服 400-xxx-xxxx" }
```

### 2.6 主动退出 —— `POST /agent/repair/v1/sessions/{id}/exit`

**请求**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| mode | string | 是 | `keep`=保存草稿（7 天可续）｜`abandon`=放弃本次报修 |

**响应 200**：

| 字段 | 类型 | 说明 |
|---|---|---|
| result | string | 固定 `ok` |
| draft_expired_at | string | keep 时返回，草稿过期时间；abandon 不返回 |

**场景 ① · keep（存草稿离开）**：`{ "mode": "keep" }` → `200 { "result": "ok", "draft_expired_at": "2026-11-12T09:41:00+08:00" }`；7 天内重进 = 建会话场景 ②（is_resumed=true）。

**场景 ② · abandon（放弃本次）**：`{ "mode": "abandon" }` → `200 { "result": "ok" }`；随后 GET 返回 404/40401，前端静默开新会话。

## 3. 错误码

| code | HTTP | 场景 | 前端行为 |
|---|---|---|---|
| 40101 | 401 | token 无效/过期 | 引导重新登录 |
| 40401 | 404 | 会话不存在/过期/废弃 | 静默开新会话 |
| 40901 | 409 | 非 confirm 态调用 submit（还没到确认单就提交） | toast 提示还有哪几项没填，留在当前界面 |
| 42201 | 422 | 字段/附件校验失败（提交缺项、非法文件、删不存在的附件） | 收 confirm_card，高亮 missing 字段；附件违规 toast 提示 |
| 42901 | 429 | 当日 LLM 配额用尽（新会话也开不出 AI 轮） | 提示「今日 AI 次数已用完」，引导切传统表单 |
| 50301 | 503 | AI 服务不可用（进程无响应/部署中断） | 提示暂不可用，引导回传统表单，稍后重试 |
| 50302 ❗ | 503 | 明道云提交失败-已转待重试（**待评审确认后正式启用**） | 提示稍后自动重试 + 客服兜底 |

## 4. 枚举字典

**图状态 state（5）**：`collecting`（采集进行中）/ `confirm`（确认单挂起，等 submit）/ `done`（提交成功）/ `exited`（主动退出）/ `fallback`（降级卡片向导）

**focus 字段名（报修）**：`category` · `detail` · `photos` · `expect_visit` · `impact_business` · `phone`

**seg_pick.field（2）**：`expect_visit` ｜ `impact_business`

**enum_card.mode（2）**：`top3`（AI 候选）｜ `full`（FALLBACK 全量）

**字段 source（3）**：`system_default` ｜ `ai_filled` ｜ `user_edited`

## 5. 前端联调自查清单

| 检查项 | 口径                                                                                     |
|---|----------------------------------------------------------------------------------------|
| seq 连续性 | 用户消息与服务端消息统一编号，seq 全会话严格递增；响应含用户消息回显（role 区分，user 消息 data=请求体除 type 外字段原样）；重连后全量重放不重不漏 |
| 响应结构 | 三字段 `state / focus / messages`；messages 按 seq 升序；                                      |
| 状态一致性 | state ∈ 5 种；collecting 必带 focus；改字段消息的 state/focus 不变                                  |
| 枚举值 | enum_card.options / seg_pick.value 全部来自服务端字典，前端不自持枚举                                   |
| 幂等 | submit 重复点击只产生一个 order_key；重试返回同一单号                                                    |
