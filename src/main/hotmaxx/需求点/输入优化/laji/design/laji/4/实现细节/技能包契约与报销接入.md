# 技能包契约与报销接入

> 一句话：**技能包 = 一份"字段说明书"（schema）+ 字典 + 话术 + 工具 + 钩子；引擎读说明书干活，业务一个流程代码都不写。报销（门店费用通道）是第二个技能包，用它最难的字段验证架子。**
> 主文档：[../技术方案.md](../技术方案.md) §5 §8

---

## 一、技能包结构（对齐代码仓 app/skills/）

```
app/skills/repair/            app/skills/expense/
├── skill.py      # 包声明：名称/URL段/入口话术/钩子注册
├── slots.py      # 字段 schema（Pydantic，逐字段声明类型与策略）
├── prompts.py    # 技能包注入的系统词片段 + 抽取 schema 差异
├── dict_sources.py   # 字典源（类别表 / 费用项目+付款公司+部门树）
├── tools.py      # 提交/带出工具（ToolProvider 注册）
└── cards.py      # 卡片皮肤（复用引擎已有形态 + 特化）
```

接入新业务 = 复制这个目录骨架填内容。**core 目录零改动。**

## 二、槽位 schema 形状（说明书长什么样）

```python
# repair/slots.py（节选）
category: Slot(type=EnumSlot, dict="repair_category", required=True,
               hook="must_pick",          # 类别必须点选，不接受文本直填
               on_change="reset_photos")  # 重选联动：照片清单重校验
detail:    Slot(type=TextSlot, required=True, pattern="现象/时间/范围", max_len=100)
photos:    Slot(type=MediaSlot, required=True, check_list="by_category")

# expense/slots.py（节选）
dept:        Slot(type=TreeSlot, dict="dept_tree", required=True)
dept_l1:     Slot(type=TreeSlot, required=True, derive="dept.root")   # 一级部门=路径推导
pay_company: Slot(type=EnumSlot, dict="pay_company", required=True)
invoice_state: Slot(type=EnumSlot, dict="invoice_state", required=True)  # 三选一
expense_rows: Slot(type=SubtableSlot, required=True, max_rows=10, row_schema=[...])
payee:       Slot(type=GroupSlot, fields=["name","bank_no","bank","branch"],
                  mem_tools=("recall_payee","save_payee"))          # 记忆经工具读写
amount_cn:   Slot(type=ComputedSlot, formula="sum(rows.amount) → 大写")
```

## 三、槽位类型 → 引擎行为总表（10 类一次建设，全业务受益）

| 类型 | 追问话术 key | 卡片 type（服务端） | 用户回传 type | 防幻觉闸 |
|---|---|---|---|---|
| `context` 带出 | 不问 | `status_bar` | — | 工具单源 |
| `enum` 枚举 | ask_enum | `enum_card` / `quick_cards` | `enum_pick` / `card` | 字典白名单 + 必须点选 |
| `tree` 树 | ask_tree | `tree_card`（新） | `tree_pick`（新） | 树路径白名单匹配 |
| `text` 文本 | ask_text（带示例） | `text` | `text` | 范式整理 + 确认单可编辑 |
| `money` 金额 | ask_amount | `amount_card`（新） | `input_submit`（新） | 格式 + 上限 + Σ 一致性 |
| `date` 日期 | ask_date | `seg_card` / 日期选择 | `seg_pick` | 默认值优先（当天） |
| `media` 附件 | ask_photo（按清单） | `photo_guide` | `upload_done` | 清单规则校验（0 LLM） |
| `subgroup` 字段组 | ask_group | `group_card`（新） | `group_submit`（新） | 逐字段校验 + 记忆预填标 source |
| `subtable` 子表 | ask_rows | `subtable_card`（新） | `subtable_op`（新） | 行数上限 + 行内必填齐 |
| `computed` | 不问 | 确认单展示 | — | 程序计算 |

## 四、报销字段映射全集（门店费用通道）

> 依据：真实表单截图（2026-11-05）+ OCR。❗ = 待与报销负责人对齐。

### 4.1 系统/只读（不问不抽，13 项）

| 字段 | 来源 |
|---|---|
| 申请编号 / 审批状态 | 明道云自动 |
| 申请日期 | 默认当天 |
| 大区 / 门店类型 / 冻结状态 / 门店请款状态 | 接口同步（门店主数据） |
| 欠票到期日期 | 财务流程维护 ❗规则待对齐 |
| 大写金额 / 税额合计 / 税额合计(前四类发票) | computed（Σ 子表金额） |
| 费用承担门店(接口同步) / 费用承担门店ID / 费用承担门店(新) | 登录门店带出 |
| 期间天数 | computed（结束-开始） |

### 4.2 对话采集（11 项）

| # | 字段 | 必填 | 类型 | 策略与话术要点 |
|---|---|---|---|---|
| 1 | 所在部门 | ✅ | tree | 说部门名→Top3 完整路径卡；匹配不到→树搜索卡 |
| 2 | 一级部门 | ✅ | tree+derive | 由 #1 路径自动带出，确认单可改 |
| 3 | 办公地点 | ✅❓ | enum | 地点字典 Top3 |
| 4 | 付款公司 | ✅ | enum | 下拉字典 Top3；常用项前置 |
| 5 | 费用承担类型 | ✅ | enum | 默认"门店"，确认即可 |
| 6 | 付款事由 | ✅ | text | LLM 整理；话术强调"一个门店相关付费、≤10 个子项" |
| 7 | 费用明细 | ✅ | subtable | 行=门店费用项目(enum)+费用金额(money)+开始时间+结束时间；一句话抽多行；≤10 行 |
| 8 | 是否有发票 | ✅ | enum | 三选一：有发票/收据 · 无发票/无收据 · 欠票/收据；欠票→确认单提示补票规则 ❗ |
| 9 | 收款人银行信息 | ✅ | subgroup | 四件套：收款人/银行账号/开户行/支行；**记忆预填**（BaseStore） |
| 10 | 附件/发票影像 | ❓❗ | media | 欠票时提示"票到补传"？——是否必填待对齐 |
| 11 | 手机号 | ❓❗ | context | 截图提示"填门店代码自动匹配中文名称"，语义待对齐 |

### 4.3 钩子清单（报销专属规则）

| 钩子 | 规则 |
|---|---|
| `rows_limit` | 子表 ≤10 行，超出引导拆单 |
| `derive_dept_l1` | 一级部门随所在部门推导 |
| `invoice_link` | 欠票/收据 → 确认单展示欠票到期日期提示 ❗ |
| `amount_check` | 大写金额=Σ行金额，不一致禁止提交（理论不会发生，computed 单源） |

## 五、报销交互剧本（完整版）

**主路径（记忆命中 + 一句话多行）**：

> 【状态条】📍 11522 安徽商之都OK店 ｜ 门店费用通道
> 🤖 说下这次报什么费用就行，比如「11月房租5000、电费1200，发票还没到」。
> 👤 这个月房租 5000，电费 1200，发票都还没到。
> 🤖 好，先建了两行明细，你看对不对：
> **[子表卡]** ① 门店费用-房租 ¥5,000 ② 门店费用-电费 ¥1,200 —— 发票状态先按「欠票/收据」登记，票到要补。**费用项目确认**：[房租✓] [电费✓]（Top3 点选）
> 👤 （点选确认）
> 🤖 部门还是 **安徽大区-合肥-商之都OK店** 吗？[tree_card 路径确认] → 办公地点 [XX广场] ｜ 付款公司 [海易名]（Top3 卡）
> 🤖 **收款人**：上次用的是「张三 · 工行合肥XX支行 · 尾号6688」，这次还用吗？ [✅用上次的] [✏️改]
> 👤 用上次的。
> 🤖 齐了，请核对：**确认单**（明细两行+期间天数自动算 30 天+大写金额 人民币陆仟贰佰元整+欠票提示）→ [✅ 确认并提交]
> 🤖 提交成功 ✅ 申请编号：`FY-20261105-0012`，状态：待提交。欠票记得到期前补传发票。

**分支要点**：记忆未命中 → 收款人四件套逐项问（group_card 空表单）；部门说不出 → 树搜索卡（按大区折叠）；金额对不上 → 逐行 amount_card 修改。

## 八、防幻觉增补三闸（在八道闸之后）

| 闸 | 位置 | 规则 |
|---|---|---|
| 树路径闸 | update 节点 | LLM 给的路径逐条与树白名单精确比对（节点名+层级都匹配），非法丢弃；候选空 → 树搜索卡 |
| 金额闸 | update 节点 | 正则格式 + 上限 + 子表 Σ 一致性（computed 单源，杜绝 LLM 算数） |
| 子表闸 | route 前 | 行数 ≤10、每行必填齐才允许进 confirm；行内枚举同样过白名单 |
