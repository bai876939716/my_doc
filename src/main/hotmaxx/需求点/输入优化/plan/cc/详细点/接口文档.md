# 接口文档 · H5 ↔ Agent 服务 · Agent ↔ MCP Server

> 本文是交互图（diagrams/03）与前端/服务端开发的**接口真值**：图上每条箭头都能在本文找到对应定义。
> 上线前 TODO：真实域名、token 签发方式、员工档案/门店主数据接口名（见技术方案文末 TODO）。

## 0. 总览

| 链路 | 协议 | 说明 |
|---|---|---|
| H5 ↔ Agent 服务 | REST + SSE（fetch POST + 流式响应） | 6 个接口；用户消息走 POST，AI 回复以 SSE 事件流返回 |
| Agent ↔ MCP Server | MCP **Streamable HTTP**（JSON-RPC 2.0） | 单端点 `/mcp`；initialize 握手 + tools/call |

> **命名说明**：「Streamable HTTP」是 MCP 规范的专有传输名称（JSON-RPC + initialize 握手那一套）。两条链路**传输形态相同**（单端点 POST + 响应可为 SSE 流），但 H5 ↔ Agent 跑的是**自有消息协议**（text / quick_cards / enum_card 等 8 种类型，无 JSON-RPC、无握手），故表中写作 REST + SSE 而非 Streamable HTTP——写成后者会误导他人以为前端在跑 MCP。前端不直接跑 MCP 的理由见《技术选型与方案设计对比.md》§3.4（鉴权 / 编排归服务端 / 密钥不下发）。

## 1. H5 ↔ Agent 服务（REST + SSE）

通用约定：`Authorization: Bearer <token>`；JSON 编码 UTF-8；会话并发用 `ver` 乐观锁（每次响应带最新 ver，提交时校验）。

### 1.1 建会话 —— `POST /api/sessions`

```json
// 请求（body 可空；督导多店时传 store_no）
{ "store_no": "SH0021" }

// 响应 200
{
  "session_id": "rp_9f3k2m",
  "ver": 1,
  "context": {                       // 系统带出字段（确认单中可改）
    "region": "华东大区", "store": "上海静安寺店", "store_no": "SH0021",
    "property": "商场店", "address": "上海市静安区南京西路1618号B1层",
    "hours": "10:00-22:00", "contact": "张伟", "phone": "+8613800001234"
  },
  "messages": [                      // 首屏消息序列（按序渲染）
    { "seq": 1, "type": "text",       "data": { "content": "张伟你好！门店信息已自动带出。这次哪里出了问题？" } },
    { "seq": 2, "type": "quick_cards","data": { "cards": [ { "id": "c_cool", "title": "❄️ 冷柜/空调不制冷" } ] } }
  ]
}
```

### 1.2 发消息 —— `POST /api/sessions/{id}/messages`（响应 = SSE 流）

请求体按 `type` 分七种（与原型交互一一对应）：

| type | body | 场景 |
|---|---|---|
| `text` | `{"type":"text","content":"冷藏风幕柜不制冷…"}` | 分支A 自由描述 |
| `card` | `{"type":"card","card_id":"c_cool"}` | 分支B 点高频卡片 |
| `enum_pick` | `{"type":"enum_pick","value":"制冷设备 - 风幕柜/立式冷柜"}` | 枚举卡点选 |
| `detail_text` | `{"type":"detail_text","content":"…"}` | 详情/补充描述 |
| `upload_done` | `{"type":"upload_done","media_ids":["m_001","m_002"]}` | 上传完成通知 |
| `contact` | `{"type":"contact","name":"李店长","phone":"13900000000"}` | 修改联系人 |
| `contact_use_default` | `{"type":"contact_use_default"}` | 用本人信息 |

SSE 响应格式（`Accept: text/event-stream`）：

```
event: typing                          ← 先行：立即让前端显示"输入中"
data: {}

event: message                         ← 0..n 条：正文/卡片/确认单
data: {"seq":3,"type":"enum_card","data":{"preselect":0,"options":["制冷设备 - 风幕柜/立式冷柜","制冷设备 - 卧式冰柜","暖通设备 - 门店空调"]}}

event: done                            ← 终止：当前状态 + 版本号
data: {"state":"A_ENUM","ver":4}

: ping                                 ← 心跳注释行，每 15s 一条
```

服务端消息类型全集（`message.data.type`）：`text` / `quick_cards` / `enum_card` / `photo_guide` / `contact_confirm` / `confirm_card` / `result` / `system_tip`（降级提示）。

### 1.3 上传附件 —— `POST /api/sessions/{id}/upload`

```
请求：multipart/form-data，字段 files[]（image/* 或 video/*）
响应 200：{ "media_ids": ["m_001"], "urls": ["https://oss…/m_001.jpg"] }
```

（Agent 收到后经 MCP `upload_media` 落 OSS；前端拿到 media_id 再发 `upload_done` 消息。）

### 1.4 恢复会话 —— `GET /api/sessions/{id}`

断点续填 / 换端 / 主动退出后重进。响应同 1.1（含当前 `state`、`collected_fields`、完整 `messages`、`ver`）；会话不存在或已废弃返回 404。

### 1.5 提交 —— `POST /api/sessions/{id}/submit`

```json
// 请求（ver 乐观锁；仅 CONFIRM 状态接受）
{ "ver": 9 }

// 响应 200
{ "order_no": "BX-20261101-1032", "status": "已提交 / 待派单" }
```

### 1.6 主动退出 —— `POST /api/sessions/{id}/exit`

```json
// 请求
{ "mode": "keep" }        // keep=保存草稿退出（7天可续） | abandon=放弃本次报修

// 响应 200（keep）
{ "result": "ok", "draft_expired_at": "2026-11-08T12:00:00+08:00" }
```

### 1.7 错误码

| 码 | 场景 | 前端行为 |
|---|---|---|
| 401 | token 无效/过期 | 引导重新登录 |
| 404 | 会话不存在/已过期/已废弃 | 开新会话 |
| 409 | ver 冲突（双端并发） | GET 会话刷新后重试 |
| 429 | 当日 LLM 配额用尽 | 收 `system_tip`，降级卡片向导 |
| 503 | LLM 不可用 | 降级卡片向导 / 引导老表单，不阻塞 |

## 2. Agent ↔ MCP Server（Streamable HTTP · JSON-RPC 2.0）

### 2.1 传输约定

| 项 | 约定 |
|---|---|
| 端点 | `http://mcp-svc:8000/mcp`（单端点，全部 POST） |
| 编码 | 请求 `application/json`（JSON-RPC 2.0）；响应 `application/json` **或** `text/event-stream`（SSE 分片，一条结果一个 event） |
| 会话 | 首次 `initialize` 的响应头返回 `MCP-Session-Id`，后续所有请求携带；失效（HTTP 404）则重新 initialize |
| 断线 | SSE 分片场景带 `Last-Event-ID` 请求头续传，不重算 |
| 服务端 | fastmcp：`mcp.run(transport="streamable-http")`；客户端：官方 SDK `streamablehttp_client` |

### 2.2 握手（服务启动后一次，长会话复用）

```json
// ① 请求
{ "jsonrpc":"2.0", "id":1, "method":"initialize",
  "params": { "protocolVersion":"2025-03-26", "capabilities":{},
              "clientInfo": {"name":"repair-agent","version":"0.1.0"} } }

// ② 响应（响应头：MCP-Session-Id: 86e3f0e5-…）
{ "jsonrpc":"2.0", "id":1,
  "result": { "protocolVersion":"2025-03-26",
              "capabilities": {"tools":{"listChanged":true}},
              "serverInfo": {"name":"hotmaxx-mcp","version":"0.1.0"} } }

// ③ 通知（无响应体）
{ "jsonrpc":"2.0", "method":"notifications/initialized" }

// ④ 工具发现（按需/缓存）
{ "jsonrpc":"2.0", "id":2, "method":"tools/list" }
```

> **Q：H5 ↔ Agent 也用 POST + SSE，为什么它不用握手，MCP 却要？**
> ① 两个"会话"不是一回事：H5 侧 `POST /api/sessions` 建的是**业务会话**（一台报修单的状态机快照载体，每用户每单一个）；MCP 侧 initialize 建的是**协议会话**（Agent 进程 ↔ MCP 进程的连接上下文，每 Agent 实例一个，全部用户复用）。
> ② initialize 是 MCP 规范强制的第一条消息（不握手，后续 tools/call 直接报错），换来：协议版本协商、能力发现（tools/list 变更推送）、MCP-Session-Id。Session-Id 由服务器**可选**下发（无状态服务器可不给；fastmcp 默认给），用于通知订阅与 Last-Event-ID 断线关联，**不承载业务状态**（业务草稿在 Redis）。
> ③ H5 ↔ Agent 是自有协议：前后端同版本发布（版本放 URL `/api/v1/`），鉴权走 Bearer token、业务会话 id 在 URL 路径、请求自描述——initialize 要解决的问题它都没有。与 Streamable HTTP 相同的只是"POST + 可选 SSE 响应"的**传输形态**，不是协议本身。
> ④ 成本：握手在 Agent 服务启动后一次（或首次调用懒加载），所有用户所有单复用；会话失效（404）自动重握，摊到每单 ≈ 0。

### 2.3 工具调用 —— `tools/call`

```json
// 请求示例：get_login_profile
{ "jsonrpc":"2.0", "id":3, "method":"tools/call",
  "params": { "name":"get_login_profile", "arguments": { "token_hash":"…" } } }

// 响应示例（result.content[0].text 内为工具 JSON）
{ "jsonrpc":"2.0", "id":3,
  "result": { "isError": false,
              "content": [ { "type":"text",
                "text": "{\"name\":\"张伟\",\"phone\":\"13800001234\",\"store_no\":\"SH0021\",\"role\":\"店员\"}" } ] } }
```

七工具参数与返回（arguments → 返回）：

| 工具 | arguments | 返回 | 后端依赖 |
|---|---|---|---|
| `get_login_profile` | token_hash | 姓名、手机号、门店编号、角色 | 员工档案 TODO |
| `get_store_master` | store_no | 门店名、大区、属性、地址、营业时间 | 主数据 TODO |
| `get_category_dict` | store_no（可选） | 类别树、Top6 卡片文案、各类别拍摄清单 | 字典配置表 |
| `validate_photos` | category、media_ids | 缺项名称列表（空=通过，纯规则不调 LLM） | 字典配置表 |
| `upload_media` | filename、content_b64、session_id | media_id、url | OSS |
| `create_repair_order` | 13 字段完整 JSON | 报修单编号、状态（幂等键 order_key） | 明道云 API |
| `draft_save` / `draft_get` | session_id、collected_fields / session_id | OK / 草稿内容 | Redis |

`create_repair_order` 请求示例（提交路径全貌）：

```json
{ "jsonrpc":"2.0", "id":9, "method":"tools/call",
  "params": { "name":"create_repair_order", "arguments": {
    "order_key": "rp_9f3k2m",                  // 幂等键（防网络重试重复建单）
    "region": "华东大区", "store_no": "SH0021", "store": "上海静安寺店",
    "property": "商场店", "address": "上海市静安区南京西路1618号B1层", "hours": "10:00-22:00",
    "contact": "张伟", "phone": "+8613800001234",
    "category": "制冷设备 - 风幕柜/立式冷柜",
    "detail": "【故障表现】…【产生原因】…【导致后果】…",
    "media_ids": ["m_001","m_002"] } } }
```

## 3. 交互图对应关系（diagrams/03 每阶段的真实调用）

| 阶段 | H5 → Agent | Agent → MCP（均为 POST /mcp tools/call） |
|---|---|---|
| 握手 | — | initialize → notifications/initialized → tools/list |
| INIT 建会话 | POST /api/sessions | get_login_profile、get_store_master、get_category_dict、draft_save |
| 分支A/B | POST /messages（text / card / enum_pick） | （分支A 仅调 LLM，无 MCP） |
| DETAIL | POST /messages（detail_text） | draft_save |
| PHOTO | POST /upload → POST /messages（upload_done） | validate_photos、upload_media |
| CONTACT | POST /messages（contact / contact_use_default） | — |
| CONFIRM | POST /submit | create_repair_order |
| 主动退出 | POST /sessions/{id}/exit（keep/abandon） | draft_save（keep）/ 废弃标记（abandon） |
| 恢复 | GET /api/sessions/{id} | draft_get |
