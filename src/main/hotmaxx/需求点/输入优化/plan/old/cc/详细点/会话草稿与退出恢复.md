# 会话草稿与退出恢复 

> 一句话：**会话即草稿**——不依赖用户点"保存"，每次状态变更服务端先落 Redis 再推送；所以无论哪种退出（杀 App、断网、主动退出），进度天然不丢，回来一条 `GET` 就能接着填。
> SSE 协议与消息格式见同目录《接口文档.md》§1.2；本文只讲草稿本身：**管理过程 → 数据留存 → 接口关系 → 典型场景**。

---

## 一、管理过程（草稿的一生）

全场景时序图（状态修改 + 会话存储动作逐条标注）：[06-会话时序图.puml](../../../../diagrams/06-会话时序图.puml)

**四个阶段：**

1. **出生**：`POST /api/sessions` 建会话，状态机调工具带出 10 项字段，**首次 `draft_save`** 落 Redis——草稿从第一秒就存在。
2. **成长**：填报中每次状态变更（答完类别、传完照片、改完联系人），服务端**先 `draft_save` 再推送 SSE**。顺序不能反：先存后推，推送失败数据也已经在 Redis 里；SSE 断线重连后从快照重放即可。
3. **三种终态**：
   - **DONE**：提交成功，Redis 草稿清除，完整会话转 MySQL 归档（对账 / 回放用）；
   - **EXITED-keep**：主动退出选"保存"，再存一次快照，TTL 续 7 天，重进下发「继续上次报修」卡片；
   - **EXITED-abandon**：选"放弃"，标记废弃，保留 24h 供排查后删除。
4. **过期**：TTL 到期自动清除，不需要定时任务。7 天内随时可续；超期重开新会话（老表单从来没有过"草稿保留 7 天"，体验只升不降）。

**为什么"错误退出零处理"**：保存时机是"每次状态变更后"而不是"退出时"——杀 App、闪退、断网根本来不及发请求，但快照早就是最新的，天然等在 Redis 里。

状态机侧对应实现（转移表节选）：

```python
EXIT_EVENTS = {"exit_keep": "EXITED", "exit_abandon": "EXITED"}  # DONE 外任意状态可触发

def step(state, event, ctx):
    nxt = EXIT_EVENTS.get(event) or TRANSITIONS[state].get(event)
    if nxt:
        run_state_handler(nxt, ctx); ctx.state = nxt
        draft_save(ctx)          # 先存
    return nxt                   # 再由调用方推送 SSE
```

**ver 乐观锁**：快照带版本号，每次写入 ver+1；双端并发（手机和电脑同时开着同一会话）提交时校验 ver，不一致返回 409，前端 GET 刷新后重试——防止互相覆盖。

## 二、数据留存（存哪、存什么、留多久）

| 存储 | Key / 表 | 内容 | 留存策略 |
|---|---|---|---|
| Redis | `rp:{session_id}` | 会话快照 JSON（见下） | TTL 7 天**滑动续期**：每次 draft_save 顺延，活跃会话永不过期 |
| Redis | `rp:active:{uid}` | **活跃会话索引**：指向该用户当前 session_id | 建会话写入；DONE / abandon / 过期时清除。重进入口靠它复用会话，不依赖前端本地 |
| Redis | `rp:{session_id}`（status=abandoned） | 废弃草稿 | 保留 24h 供排查（为什么放弃），之后删除 |
| Redis | `quota:{uid}:{yyyyMMdd}` | 单人单天 LLM 调用 / token 配额 | 当日 24:00 自动过期 |
| MySQL | 会话归档表 | 终态会话全量（状态轨迹 + collected_fields + 消息） | 长期，对账与回放 |
| MySQL | 埋点明细 | 9 类埋点事件 | 长期，指标计算 |
| 前端 | localStorage（老表单草稿） | 传统表单字段值 | **与 AI 草稿不同空间，互不覆盖** |

快照 JSON 结构（`rp:{session_id}`）：

```json
{
  "session_id": "s_xxx", "user_id": "u_1001", "store_no": "SH0021",
  "state": "PHOTO", "branch": "B", "ver": 12, "status": "active",
  "collected_fields": {
    "category": "收银设备 - 收银机/扫码枪故障",
    "detail": {"表现": "…", "原因": "…", "后果": "…"},
    "photos": ["m_001", "m_002"],
    "contact": {"name": "王芳", "phone": "+86139****0000"},
    "brought": {"region": "华东大区", "store": "…", "addr": "…", "hours": "…"}
  },
  "updated_at": "2026-11-02T12:00:00Z"
}
```

要点：**session_id 从哪来、恢复靠什么**——建会话时服务端返回（响应体），前端可存一份作加速（刷新 / 断线重连直接 `GET /sessions/{id}`）；但**恢复不依赖本地**：重进 AI 入口统一 `POST /api/sessions`，服务端按 `rp:active:{uid}` 复用活跃会话，换设备、清缓存都能续填。照片本体在 OSS，快照里只存 media_id 引用。

## 三、接口的关系（谁在什么时候动草稿）

| 接口 | 触发时机 | 草稿动作 | 数据变化 |
|---|---|---|---|
| `POST /api/sessions` | 进 AI 入口（**统一恢复入口**） | 先查 `rp:active:{uid}`：有活跃会话则**复用**（is_resumed=true，前端弹继续卡片）；无则新建 + 首次 `draft_save` | Key 创建（或复用），TTL 起算 |
| `POST /api/sessions/{id}/messages` | 每条消息**且状态发生变更** | **先存再推**；done 事件回传最新 ver | state / fields 更新，ver+1，TTL 续期 |
| `POST /api/sessions/{id}/upload` | 附件上传完成 | media_ids 并入 photos 后 `draft_save` | 同上 |
| `GET /api/sessions/{id}` | 会话内刷新 / SSE 断线重连（id 已知时） | `draft_get`（只读） | 不改数据，返回状态 + 消息重放 |
| `POST /api/sessions/{id}/submit` | 确认单点提交 | 提交成功 → 草稿终态化 | Redis 清除，MySQL 归档 |
| `POST /api/sessions/{id}/exit` | 主动退出弹窗选择 | keep：最后一次 `draft_save`；abandon：标记废弃 | state=EXITED / status=abandoned |

两处防坑：消息不产生状态变更时（如 CONFIRM 态追加补充说明）只更新 fields 不动 state，照样先存再推；配额 Key 与草稿 Key 完全独立，超限降级不影响已有草稿。

## 四、三个典型场景走查

会话时序图第 ④⑤⑥ 节：[06-会话时序图.puml](../../../../diagrams/06-会话时序图.puml)

**场景 1 · 错误退出**：填到照片步骤 App 被杀——没有任何退出请求，但快照停在 `{state: PHOTO}`；重进 AI 入口，前端拿本地 session_id 调 `GET /sessions/{id}`，服务端返回快照并**重放消息**，界面直接回到拍照那一步，已答内容全部回显。零 LLM 调用。

**场景 2 · 主动退出 keep**：点返回 → 三选项弹窗 → 选"保存草稿退出"（`exit keep`）；快照续 7 天；几天内再进入口，检测到 keep 快照 → 下发「继续上次报修」卡片（`draft_resume` 埋点）→ 点选即恢复。

**场景 3 · 7 天过期**：keep 后一直没回来，TTL 到期自动清除；重进时 GET 返回 404，前端静默开新会话——用户感知就是"新的一次报修"，没有报错。

## 五、实现难度与工作量

| 模块 | 难度 | 工作量 | 说明 |
|---|---|---|---|
| 状态机引擎 | ★★☆ | 2 人天 | 转移表 + 状态处理函数 + 单测（含 EXITED / exit 事件） |
| Redis 会话保存 | ★☆☆ | 1 人天 | 单 Key JSON，读写各一行 |
| 断点恢复（读档重放） | ★☆☆ | 0.5 人天 | 把快照读出来按状态渲染对应界面 |
| 主动退出（exit 接口 + keep/abandon） | ★☆☆ | 0.5 人天 | 一次 draft_save / 一个废弃标记 |
| **合计** | | **≈ 4 人天** | 全部成熟组件，无自造轮子 |

（SSE 服务端推送 1 人天 + 前端接收 1 人天另计，协议格式见《接口文档.md》§1.2。）
