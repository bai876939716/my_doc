# 门店报修 · 对话式 Agent 整体产品方案

## 1. 产品定位与分工

门店员工知道现场发生了什么，却未必知道后台把它归在哪一类，也不一定知道受理人需要看什么。智能报修入口负责把员工看到的现象、说出的影响和上传的证据，整理成一张可受理的原系统报修单。员工用自己的话说明现场，在提交前对类别和单据内容做最后确认。

| 谁负责 | 具体职责 |
|---|---|
| 门店员工 | 选择当前问题，提供只有现场才知道的信息，上传照片或视频，核对后提单 |
| 聊天界面与 AI | 展示门店与预选卡片，理解口语，从一句话提取多个字段，拟写详情，按缺口生成下一问 |
| 报修业务与产品运营 | 按历史工单量和驳回原因配置高频卡片。每张卡绑定适用现象、原系统类别 ID、易混情形和该类拍摄说明；类别调整时同步更新 |
| 现有系统 | 提供账号门店权限、档案、有效枚举、附件上传与建单能力；校验最终数据，生成单号，继续原有受理、驳回和状态流转 |

**首期范围**覆盖 App 和网页的报修发起、续填、核对、提交及回看。首批优先做已有明确归类口径和附件要求的高频场景。历史单量、实际类别字典及购物袋拍摄原文尚未提供，以下卡片顺序和演示数据不作为上线配置。

## 2. 六条交互原则

1. **新增入口，双草稿隔离。** 原报修页提供「智能报修」，聊天页固定保留「切换原表单」。两边各自续填，切换时不覆盖、不搬运、不提交。
2. **AI 预填，人确认。** 门店档案、员工口述、已选类别分开呈现。字段有误可单项修改，只有点击「确认提交」才建单。
3. **能查不问。** 有当前门店就带出整组档案；员工一句话已经说到的时间、现象和影响一并记下。选填项空缺不触发追问。
4. **一次一问。** 优先解决会改变类别或拍摄要求的问题，其次补现场事实，再补缺失的必填项。员工不清楚原因时按未知处理。
5. **枚举只能选。** 所有可提交选项均来自有效字典。AI 可以检索和解释候选；选项绑定真实 ID，后台再次校验。
6. **先选卡片，再逐步补充。** 用“发生了什么”组织首页。同一现象明确对应一个类别时，卡上显示类别，点卡即完成选择；对应多个类别时，先问能区分它们的现场事实，再展示真实候选。

## 3. 产品流程与关键页面

| 节点 | 员工看到什么 | 产品何时进入下一步 |
|---|---|---|
| ① 首页选问题 | 顶部为「当前门店 · 可切换」，下方为高频现象卡和「其他问题／直接说」。如有聊天草稿，优先显示「继续上次报修」 | 已有当前门店则直接选卡；多店且无当前门店时先从授权列表选店，随即展示适用卡片 |
| ② 确定类别 | 卡片写明现象、适用说明及绑定类别。自由输入或模糊卡片触发匹配 | 如员工只说“收银台那边坏了”，先问“收银台哪样东西出了问题？”依据回答缩小候选，员工点选。仍分不清时提供带适用说明的有效类别列表，可保留草稿待核实 |
| ③ 补现场描述 | 围绕受理人需要判断的事实提问，如“袋子是哪里破了？”员工可以顺带说明影响 | 有可辨认的故障表现即可整理详情。若已有现象与影响，直接收附件；无需员工逐格输入原因、后果 |
| ④ 收证据 | 上传按钮旁显示当前类别的拍摄说明，可拍摄、从相册选择或补传。对购物袋展示业务维护的要求原文 | 只引用上传成功的附件。数量、格式等可机器校验的条件按规则检查；画面内容由员工对照要求预览核对。上传失败时仅重传失败项 |
| ⑤ 核对与提交 | 一屏展示所选类别、详情、附件预览、门店和联系人，可就地修改 | 必填项缺失就定位该项。切店时刷新档案并重新核对，改类别时重新匹配拍摄要求。提交前再次检查权限及枚举有效性 |
| ⑥ 回执 | 原系统返回单号、状态及「查看报修单」 | 回到原系统处理。网络超时时用本次提交标识查询结果，避免重复建单 |

## 4. 13 个字段如何落单

| 原字段 | 主要取得方式 | 需要员工介入的时机 |
|---|---|---|
| 大区 · 必填枚举 | 按门店档案带出有效大区 ID | 缺映射时从该门店允许的大区中选；无有效项则提示核实门店 |
| 门店编号 · 必填 | 从当前授权门店取编号 | 多店无默认或报其他店时，搜索并点选“编号＋店名” |
| 门店名 · 选填 | 随门店编号带出 | 随门店一起核对，缺失可留空 |
| 门店属性 · 选填 | 读档案，沿用原系统文本或枚举类型 | 缺失可留空，若为枚举只接受有效值 |
| 联系人 · 必填 | 带出门店报修联系人 | 无记录时问“这单现场找谁？”；换班时可改本单联系人 |
| 手机号码 · 必填 | 取所选联系人的号码及国家码，未指定国家码时默认 +86 | 查不到或换人后缺号时再问，按所选国家码校验 |
| 营业时间 · 选填 | 读门店档案 | 摘要中可修改本单时间，空缺跳过 |
| 报修单编号 · 系统生成 | 成功建单后读回 | 无需输入 |
| 报修单状态 · 系统枚举 | 读取原系统状态 | 无需选择，聊天草稿的进度单独显示 |
| 报修类别 · 必填枚举 | 点选带真实类别 ID 的卡片或候选项 | 现象有歧义时先回答判别问题，分类不符时可重选 |
| 门店地址 · 必填 | 读当前门店地址 | 缺失或已搬迁时，只补本单实际地址 |
| 问题照片或视频 · 必填 | 员工上传，关联原附件服务返回的文件标识 | 按当前类别拍摄；购物袋显示专用要求，附件未成功上传时保留草稿 |
| 报修详情 · 必填 | 根据员工口述整理“故障表现、已知原因、实际后果” | 只追问影响受理判断的缺口。原因未知可写“原因待核实”，员工可直接改文案 |

## 6. 接入与试点验收

**上线前准备。** 报修业务负责人提供有效类别字典、易错类别的区分口径及购物袋拍摄要求原文；产品按历史工单频次选卡并维护映射。研发打通授权门店、联系人、文件上传和原系统提单。某类别缺少必要拍摄说明或有效映射时，先保留原表单入口，待配置核实后再开放对应智能卡片。

**先验证能用。** 用同一账号分别在老表单和聊天填不同内容，往返切换应各自恢复。再用真实脱敏样单验证三件事：口述已经包含的信息没有被重复问，后台停用的类别无法提交，断网重试最终只生成一张单。

**再验证是否值得推广。** 在同一批试点门店按报修类别对比两个入口：看从开始填写到成功提交的中位耗时、开始后成功提单的比例，以及已审核单中因错类或附件不合规被退回的比例。若提单变快但购物袋退回率上升，抽查退回单，区分是类别卡适用说明不清，还是上传页的拍摄指引不清，再改对应环节。
