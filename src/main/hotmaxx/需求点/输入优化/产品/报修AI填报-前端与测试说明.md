## 一、产品一页纸

**一句话**：店员在自研 App 里用对话完成报修单填报——AI 预填、人确认、一键提交。

- **本期范围**：只做报修**信息录入**。提交成功后跳「历史报修记录」页（已有页面）看进度，本期不做对话查询。
- **不替换现有流程**：传统表单原样保留，AI 是叠加入口；对话页有一键切回表单的按钮兜底。
- **两条填报路径**：A 自由描述（一句大白话，AI 归类+预填）/ B 高频卡片（点卡=选好类别，最快路径）。
- **核心体验原则**：AI 只预填、人确认（**报修类别明说且唯一命中字典词才直填、其余必须点选**，AI 不代选）；随时可改；中途退出草稿留 7 天；AI 出问题走卡片点选或回表单，绝不耽误报修。
- **灰度两形态**：形态一（当前）＝表单页顶部 AI 入口；形态二＝首次进入即 AI 对话+切回表单兜底。按门店/比例逐步放流。
- **已取消字段**：期望上门时间、影响营业——全链路取消（2026-11-21 产品拍板），对话与表单均不采集，明道云不加控件。

产品完整方案见《[FA.md](FA.md)》。

## 二、页面与入口

| 页面 | 新建/改造 | 要点 |
|---|---|---|
| 服务助手首页 | 已有，不动 | 「我要报修」卡片 +「历史记录」入口保持原样 |
| 报修表单页 | **改造** | 顶部加「AI 智能填报」入口卡（风格与页面统一，整卡可点） |
| AI 对话页 | **新建** | 结构见下 |
| 历史报修记录页 | 已有 | 提交成功后带单号跳转 |

**AI 对话页结构**（自上而下）：

1. 标题栏：页面名 + 「⇄ 传统表单」按钮（随时可退，草稿保留）
2. 状态条：`📍 11522 安徽商之都OK店 ｜ 报修人：白云翔 138****1234 [修改]`（[修改]＝前端本地弹层改报修人/电话，确认后以打字消息发出）
3. 消息区：按 seq 顺序渲染的对话时间线（用户气泡在右、AI 消息在左，卡片消息按类型渲染）
4. 输入区：**只有文本框 + 发送**（没有拍照按钮，语音按钮二期）——拍照入口在 photo_guide 卡内

**入口链路**：首页点「我要报修」→ 表单页 → 点顶部 AI 卡 → 调建会话接口 → 渲染首屏（状态条 + 开场白 + 6 张高频卡）。

交互原型参照：[门店报修-AI交互原型](../原型/门店报修-AI交互原型.html)（数据为演示，行为以本文与接口文档为准）。

## 三、消息类型与渲染规则（10 种）

服务端下发的每条消息都是 `{seq, role, type, data}`，按 seq 追加渲染（已渲染过的 seq 直接跳过，幂等去重）；**用户自己的消息也会随响应回显**（role=user，data 是请求原样），前端渲染成右侧气泡——打字显示文字，点选显示简摘要（如「已选：工程类 - 制冷设备/冷柜」）。

| type | 是什么 | 可交互 | 点击后发什么 | 渲染注意 |
|---|---|---|---|---|
| `status_bar` | 顶部状态条 | [修改] 本地弹层 | 改完以 `text` 发出 | 固定吸顶，不进时间线 |
| `text` | AI 对话气泡 | 无 | — | — |
| `quick_cards` | 高频卡墙（6 张单品卡：冷柜/收银机/照明/空调/招牌/断电） | 每张可点 | `card`（card_id） | 点后整组置灰标记已选 |
| `enum_card` | 类别候选单选卡 | 每项可点 | `enum_pick`（field+value） | **仅限点选**；`preselect` 只是把 AI 首选排第一，不是默认值；value 必须是字典原词，瞎写会被 422 拒；字典为 App 真值三大类 30 项（无「特别紧急」）；mode=grouped 时为两级联动全量卡，mode=full 平铺兜底保留 |
| `photo_guide` | 拍照引导卡 | [拍照上传] | 前端直传明道云（现有上传接口）→ 拼 URL → 自动发 `upload_done` | **1 张即可继续**（need_count 是建议张数，实际 1 张即走）；`tips` 是**纯字符串数组**（按当前类别挑的拍摄建议，如「设备整体」「问题部位特写」），逐条列出；上传流程见 6.5 |
| `system_tip` | 系统提示条 | 无 | — | level 三级配色（info/warn/error），非对话语气 |
| `seg_card` | 二选一卡 | 每项可点 | `seg_pick`（field+value） | **当前报修流程不会下发**（原「期望上门/影响营业」已下线），渲染层保留为通用能力，收到未知 field 按通用逻辑渲染 |
| `phone_confirm` | 电话确认卡 | [用本人号码]/[修改] | `phone`（use_default 或新号码） | 出参始终掩码；**这张卡不一定出现**：员工档案没带出可用手机号（没录入/座机/店内短号）时，服务端只发一条 `text` 要号文案、不发卡——渲染不能假设「轮到电话就有卡」 |
| `confirm_card` | 字段确认单 | 每项可改 + [确认并提交] | 改值→对应手势消息；提交→调 submit 接口（独立接口，**不是** messages） | 两组共 7 项：基础信息 3 项（门店/报修人/日期，系统带出不可改）+ 报修内容 4 项（类别/故障情况/照片/电话，可改）；每项带 source 标记（ai_filled 显示「AI 预填」角标）；missing 数组非空→对应项红色高亮；photos 项的 value 为 `[{name,url}]` 数组（数量=数组长度）；**category 项自带 options**（全量两级联动，形状同 enum_card grouped），重选弹窗优先用它；重选类别→system_tip 提示照片自查（见 6.4） |
| `result` | 结果卡 | [查看报修记录] | — | `{order_no, status, tip}`——提交成功的终点卡；**会进服务端消息档案**，刷新/重进时随会话查询重放回来 |

**轮末不变量（路由层保证）**：每轮响应的最后一定有「当前待办」——跑题、改值、追问之后，下一张当前问题卡一定重发，界面上「现在该干嘛」永远清楚。

## 四、state 与界面状态

每个响应带 `state`，决定界面处于什么模式：

| state | 含义 | 输入框 | 界面动作 |
|---|---|---|---|
| `collecting` | 采集中，等用户回答当前字段 | 可用 | 按 focus（当前在问的字段）给出视觉引导；收到消息正常追加 |
| `confirm` | 确认单挂起等提交 | 可用（打字＝在确认单上改） | 确认单在最后，提交按钮亮 |
| `done` | 已提交成功 | 禁用 | 显示 result 卡 + 跳记录入口；重进自动开新会话（已出单的会话不复用） |
| `fallback` | 降级为卡片向导 | 打字置灰提示，**只拦 text** | 顶部提示「已切换为卡片填报」；五种结构化手势（card/enum_pick/seg_pick/upload_done/phone）照常放行——点选是降级向导的唯一通道，照样能交单 |
| `exited` | 用户主动退出的终态 | — | 本地无对应场景（退出即离开页面；keep 后重进走恢复） |

规则：collecting 必带 focus；**改字段的消息响应里 state/focus 不变**（不回流程）。

## 六、边界与异常全景（本文重点）

### 6.1 会话恢复与退出

| 情况 | 行为 |
|---|---|
| 重新进入 AI 入口 | 统一调建会话接口；有未完成会话→is_resumed=true + 全量消息重放 + 弹「继续上次报修」卡 |
| 弹卡后点【继续】 | 按重放消息渲染，界面停在上次问到的步骤，已答全回显 |
| 弹卡后点【重新开始】 | 建会话接口带 `restart:true`——服务端**一个请求里**先放弃旧会话再建新会话，前端不用先发 exit |
| 弹卡后**什么都不点直接走** | 不发任何请求；草稿留 7 天，下次进来还弹同一张卡 |
| 超过 7 天才回来 | 会话已过期（40401）→ **静默开新会话**，不报错不弹窗 |
| 页面返回（主动退出） | 弹三选项：继续填写 / 存草稿离开（keep，7 天）/ 放弃本次（abandon）；exit 幂等，重复退回 ok |
| 恢复的内容 | 全部——已填字段（以会话查询返回的 `collected` 为准，别把历史确认卡当当前数据）、当前问到哪一步、完整对话消息，**一次性返回**；恢复接口 GET/POST 同义，App 统一走 POST；建议前端懒渲染（先渲染最近 10 轮，顶部「查看更早消息」再展开），本期无翻页接口 |
| 草稿的归属 | 按 (uid, store_no) 存：同店重进恢复现场，换店各开各的 |
| 换设备 / 清缓存 | 恢复不依赖本地存储；本地 session_id 仅用于刷新加速 |

### 6.2 输入

| 情况 | 行为 |
|---|---|
| 输入超长（>500 字） | 前端截断后发送；AI 整理出的故障描述 ≤100 字 |
| 空内容 / 纯表情 / 乱码 | 不推进流程；AI 回「没听清」类话术；连续多轮失败 → 降级向导（阈值见第九节，可配） |
| 字典外说法（如「火箭速度来修」） | 该字段忽略不写，照旧发卡问；其他字段不受影响 |
| 一句话带多个字段 | 说到的**直接预填**并复述；类别**明说且唯一命中字典词才直填**（复述"类别按你说的登记为「xx」"，随后直接 photo_guide、无 enum_card），命中多条或纯推断 → 弹卡点选 |
| 打字「改手机号 / 改电话」不带号 | 服务端**追问**："改成多少？"（update_targets），不甩表单 |
| 打字「改一下分类」 | **直接重发全量类别卡**，不用先改描述 |
| 裸值消解 | 正问电话时用户直接回一串 11 位号码＝给当前问题的答案，直接落值 |
| 用户打字说「提交 / 交单」 | **不代点按钮**：在确认单上→提示点【确认并提交】；没到确认单→提示还缺哪几项 |

### 6.3 对话边界

| 情况 | 行为 |
|---|---|
| 闲聊 / 问进度 | **分型罐头应和 + 拉回**（话术全模板化，LLM 只判意图）；问进度指路「历史报修记录」 |
| 越权（报其他门店） | 拉回，只允许当前门店 |
| 提示词注入（「忽略之前指令…」） | 当普通文本无视，拉回 |
| 连续多轮边界轮（跑题/识别失败） | 切 `fallback`（**仍是 200 正常响应**）：顶部提示已切换卡片填报 + 全量类别卡，照样能交单；单会话 LLM 次数超配额同样是这个降级，**不是错误** |

### 6.4 随时可改

| 情况 | 行为 |
|---|---|
| 采集中打字改字段 | 原地更新，state/focus 不变；回一句确认话术 |
| 确认单上点改 / 打字改 | 改值后**留在确认单**，重发一张新确认单（该字段来源标 user_edited） |
| 确认单上重选类别（唯一例外） | 照片**提示自查不删**：system_tip（level=info）"类别换了——刚才的「现场照片」如果拍的不是现在这个设备，重新传一下；还对得上就直接继续。"；**描述保留**（用户原话）/派生描述按新类别重算；议程无欠账直接回新确认单 |
| 提交后再想改 | 不可改；done 态再发 messages → 42201「本单已提交」；改单走明道云驳回重提（线下流程） |

### 6.5 照片（附件协议）

| 情况 | 行为 |
|---|---|
| 上传流程 | **前端直传明道云**（App 现有上传接口，Agent 侧没有上传接口，旧的 multipart 上传入口已删除、请求即 404）：拿 `serverName` + `key` → 拼 `serverName.replace(/\/$/,"") + "/" + key` 得完整 URL（**不要**再拼 bucket/filePath）→ 自动发 `upload_done`，带 `attachments:[{name,url}]`（name=解码后原文件名保留扩展名；没有 media_id 概念） |
| 张数 | **1 张即可继续**；单会话最多 5 个附件（可配，见第九节），超了 42201 |
| 去重与增量 | 附件按 URL 去重；每轮只传新增的 |
| 假引用 | `m_001`、`blob:...` 这类假 URL 传上去服务端不报错但图片显示不出来——只传真实上传结果 |
| 删除照片 | 确认单 photos 项 [管理] → 已传列表逐张删；按 URL 引用（旧 media_remove/media_id 口径作废），细则以《04-接口调试指南》附件协议为准 |
| 回显 | 以会话查询返回的 `collected.photos`（同结构数组）为准 |
| 按类别差异化拍摄清单与警示（如购物袋袋底必拍） | 二期；本期统一通用引导 |

### 6.6 提交

| 情况 | 行为 |
|---|---|
| 没到确认单就调提交 | 40901 + 提示当前不在确认态；不建单，会话不受影响 |
| 确认单缺必填 | 42201；确认单高亮 missing 字段，缺项服务端已塞回议程 |
| 连点 / 网络重试 | 幂等（order_key = 会话 ID）：只建一单，重复请求返回**同一单号**（上线必测红线） |
| 明道云提交失败 | 50201 + 人话提示，让用户稍后再试；不产生半单 |
| 提交后再进 | 已出单的会话不复用，重进自动开新会话 |

### 6.7 网络与服务异常

| 情况 | 行为 |
|---|---|
| 打字轮响应慢 | 输入区展示「处理中」；请求超时/响应丢失 → 调恢复接口按 seq 补齐（不重不漏） |
| 杀 App / 断网中途断开 | 无需任何处理，直接重进走恢复链路 |
| AI 服务不可用（50301） | 提示稍后重试 / 引导回传统表单 |
| 单会话配额超限（默认 30 次LLM 调用） | **不是错误**：200 + fallback 向导，体验同 6.3 降级 |

### 6.8 隐私

- 手机号**出参一律掩码**（138\*\*\*\*1234），前端任何位置不得出现完整号码；输入新号码走 11 位校验后即掩码展示。
- 类别等枚举全部由服务端下发，前端不自持字典（保证字典改了前端不用发版）。

## 七、前端埋点清单

| 事件 | 触发时机 | 支撑指标 |
|---|---|---|
| session_start | 建会话接口返回成功（含 is_resumed=true） | 填报时长（起点） |
| session_end | 提交成功或主动退出 | 填报时长（终点）、步数 |
| branch_a_input | 会话内第一条 text 消息发出 | 路径占比（含 source=keyboard/voice 维度） |
| branch_b_card_click | 点高频卡 | 路径占比 |
| enum_first_pick | 类别候选卡点选时（记录是否选了排第一位） | **类别识别准确率** |
| fallback_enter | 首次收到 state=fallback | 兜底率 |
| switch_to_form | 点「⇄ 传统表单」 | 转老表单率 |
| session_exit | 调退出接口（带 keep/abandon） | 中途放弃率 |
| draft_resume | 恢复卡片点【继续】 | 续填恢复率 |

事件名与后端埋点表一致；上报通道与参数细则联调时对齐。

## 九、报修相关配置说明

前端/测试一般只读本节即可对上环境；改配置是后端/运维动作。配置优先级：环境变量 > Nacos > .env > 代码默认值；运行参数启动读一次，**改完必须重启**。

### 9.1 链路与接口登记（公共平台）

```text
HotShop App → 公共网关 → Java 转发层(provider-biz-ai-middle) → Python Agent(AgentServerCenter)
```

- 网关按「接口路径 + X-PlatformId」查公共平台登记记录。报修接口须登记两条**通配**：`/agent/repair/*` 的 POST 与 GET 各一条（路径带会话 ID，精确登记覆盖不到；只登记 POST 会让查询报「方法不允许」）。
- 系统 HotShop，平台 ID dev 实测为 10；数据权限关闭、验证 token 不鉴权。生产按实际环境重新登记，不能沿用 dev 记录。
- 新增登记**不立刻生效**：网关每 60 秒刷新一次接口列表；报「未获取到接口信息」先等一个刷新周期，不用重启网关。
- 身份口径：直连后端（本地联调）所有请求带 `X-Uid: <员工ID>`，缺了 40101；经网关（App 正式链路）前端不传 X-Uid，身份由网关 + Java 转发层注入。
- 本地联调 Java↔Agent、Agent↔base-shop 走集群内网直调，不需要登记；Agent 本机连不上内网时用 `scripts/dev_gateway_proxy.py` 进程外代理补网关鉴权。

### 9.2 模型

- 百炼 OpenAI 兼容端点；模型名由 Nacos `LLM_MODEL` 下发，**当前 deepseek-v4.1-flash-1017**，换模型只改 Nacos 不发版。
- 服务永远调真模型：缺 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 直接拒启动，没有静默降级。
- Mock 桩（规则版假模型，`poc/mock_llm_app`）只用于评测与全量场景的确定性回放，不进前端联调与部署。

### 9.3 运行参数（AgentServerCenter `app/config.py`，Nacos/.env 可覆盖）

| 参数 | 默认值 | 含义 |
|---|---|---|
| `llm_quota_per_session` | 30 | 单会话 LLM 次数（成本闸）：超限转卡片向导，照样交单，**不报错** |
| `fallback_after_fails` | 15 | 连续多少轮边界轮（跑题/识别失败）触发降级向导 |
| `photos_max` | 5 | 单会话照片/附件上限 |
| `active_ttl_days` | 7 | 会话留存天数（活跃索引与检查点 TTL 同源）＝草稿保留期 |
| `checkpoint_mode` | memory（dev）/ postgres（生产） | 会话存储后端；memory 模式**后端重启草稿就丢**，放量前必切 postgres |

### 9.4 明道云建单配置（真值全在 Nacos，代码不带环境值）

- 配置项：`MDY_BASE_URL`（实测前缀带 `/api`）、`MDY_APPKEY`、`MDY_SIGN`、`MDY_WORKSHEET_ID`（报修工作表）、`MDY_CATEGORY_WORKSHEET_ID`（分类字典表「报修问题分类分级」）、`MDY_REPORT_SUBMITTER_ID`（报修人成员控件 accountId，对齐 shopApp 固定账号，空=不写）。开真实建单时四项基础配置缺一即拒启动。
