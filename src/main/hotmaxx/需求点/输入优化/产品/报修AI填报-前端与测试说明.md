## 一、产品一页纸

**一句话**：店员在自研 App 里用对话完成报修单填报——AI 预填、人确认、一键提交。

- **本期范围**：只做报修**信息录入**。提交成功后跳「历史报修记录」页（已有页面）看进度，本期不做对话查询。
- **不替换现有流程**：传统表单原样保留，AI 是叠加入口；对话页有一键切回表单的按钮兜底。
- **两条填报路径**：A 自由描述（一句大白话，AI 归类+预填）/ B 高频卡片（点卡=选好类别，最快路径）。
- **核心体验原则**：AI 只预填、人确认（**报修类别必须点选**，AI 不代选）；随时可改；中途退出草稿留 7 天；AI 出问题走卡片点选或回表单，绝不耽误报修。
- **灰度两形态**：形态一（当前）＝表单页顶部 AI 入口；形态二＝首次进入即 AI 对话+切回表单兜底。按门店/比例逐步放流。

产品完整方案见《[FA.md](FA.md)》。

## 二、页面与入口

| 页面 | 新建/改造 | 要点 |
|---|---|---|
| 服务助手首页 | 已有，不动 | 「我要报修」卡片 +「历史记录」入口保持原样 |
| 报修表单页 | **改造** | 顶部加「AI 智能填报」入口卡（风格与页面统一，整卡可点） |
| AI 对话页 | **新建** | 结构见下 |
| 历史报修记录页 | 已有 | 提交成功后带单号跳转 |

**AI 对话页结构**（自上而下）：

1. 标题栏：页面名 + 「⇄ 传统表单」按钮（随时可退，草稿保留）
2. 状态条：`📍 11522 安徽商之都OK店 ｜ 报修人：白云翔 138****1234 [修改]`（[修改]＝前端本地弹层改报修人/电话，确认后以打字消息发出）
3. 消息区：按 seq 顺序渲染的对话时间线（用户气泡在右、AI 消息在左，卡片消息按类型渲染）
4. 输入区：文本框 + 发送 +「＋现场照片」按钮（语音按钮二期）

**入口链路**：首页点「我要报修」→ 表单页 → 点顶部 AI 卡 → 调建会话接口 → 渲染首屏（状态条 + 开场白 + 6 张高频卡）。

交互原型参照：[门店报修-AI交互原型](../原型/门店报修-AI交互原型.html)（数据为演示，行为以本文与接口文档为准）。

## 三、消息类型与渲染规则（10 种）

服务端下发的每条消息都是 `{seq, role, type, data}`，按 seq 追加渲染；**用户自己的消息也会随响应回显**（role=user，data 是请求原样），前端渲染成右侧气泡——打字显示文字，点选显示简摘要（如「已选：工程类 - 制冷设备/冷柜」）。

| type | 是什么 | 可交互 | 点击后发什么 | 渲染注意 |
|---|---|---|---|---|
| `status_bar` | 顶部状态条 | [修改] 本地弹层 | 改完以 `text` 发出 | 固定吸顶，不进时间线 |
| `text` | AI 对话气泡 | 无 | — | — |
| `quick_cards` | 高频卡墙（6 张） | 每张可点 | `card`（card_id） | 点后整组置灰标记已选 |
| `enum_card` | 类别候选单选卡 | 每项可点 | `enum_pick`（field+value） | **仅限点选**；`preselect` 只是把 AI 首选排第一，不是默认值；mode=full 时是全量列表 |
| `photo_guide` | 拍照引导卡 | [拍照上传] | 调上传接口拿 media_id → 自动发 `upload_done` | 按 need_count 与 tips 文字渲染 |
| `system_tip` | 系统提示条 | 无 | — | level 三级配色（info/warn/error），非对话语气 |
| `seg_card` | 二选一卡 | 两个选项 | `seg_pick`（field+value） | 期望上门/影响营业复用同一形态 |
| `phone_confirm` | 电话确认卡 | [用本人号码]/[修改] | `phone`（use_default 或新号码） | 出参始终掩码 |
| `confirm_card` | 10 字段确认单 | 每项可改 + [确认并提交] | 改值→对应手势消息；提交→调 submit 接口 | 每项带 source 标记（AI 预填的显示「AI 预填」角标）；missing 数组非空→对应项红色高亮；重选类别→界面回拍照步骤 |
| `result` | 结果卡 | [查看报修记录] | — | **前端用 submit 响应自行组装**（单号/状态/提示文案），不是服务端消息 |

## 四、state 与界面状态

每个响应带 `state`，决定界面处于什么模式：

| state | 含义 | 输入框 | 界面动作 |
|---|---|---|---|
| `collecting` | 采集中，等用户回答当前字段 | 可用 | 按 focus（当前在问的字段）给出视觉引导；收到消息正常追加 |
| `confirm` | 确认单挂起等提交 | 可用（打字＝在确认单上改） | 确认单在最后，提交按钮亮 |
| `done` | 已提交成功 | 禁用 | 显示 result 卡 + 跳记录入口；重进＝新会话（旧会话已终结，GET 返回 404 属正常） |
| `fallback` | 降级为卡片向导 | 可用但**打字不再经 AI 处理** | 顶部提示「已切换为卡片填报」，点选继续走完，照样能交单 |
| `exited` | 用户主动退出的终态 | — | 本地无对应场景（退出即离开页面；keep 后重进走恢复） |

规则：collecting 必带 focus；**改字段的消息响应里 state/focus 不变**（不回流程）。

## 六、边界与异常全景（本文重点）

### 6.1 会话恢复与退出

| 情况 | 行为 |
|---|---|
| 重新进入 AI 入口 | 统一调建会话接口；有未完成会话→is_resumed=true + 全量消息重放 + 弹「继续上次报修」卡 |
| 弹卡后点【继续】 | 按重放消息渲染，界面停在上次问到的步骤，已答全回显 |
| 弹卡后点【重新开始】 | 先调 exit（abandon）再建新会话，两步串行 |
| 弹卡后**什么都不点直接走** | 不发任何请求；草稿留 7 天，下次进来还弹同一张卡 |
| 超过 7 天才回来 | 会话已过期（40401）→ **静默开新会话**，不报错不弹窗 |
| 页面返回（主动退出） | 弹三选项：继续填写 / 存草稿离开（keep，7 天）/ 放弃本次（abandon） |
| 恢复的内容 | 全部——已填字段、当前问到哪一步、完整对话消息，**一次性返回**；建议前端懒渲染（先渲染最近 10 轮，顶部「查看更早消息」再展开），本期无翻页接口 |
| 换设备 / 清缓存 | 恢复不依赖本地存储；本地 session_id 仅用于刷新加速 |

### 6.2 输入

| 情况 | 行为 |
|---|---|
| 输入超长（>500 字） | 前端截断后发送；AI 整理出的故障描述 ≤100 字 |
| 空内容 / 纯表情 / 乱码 | 不推进流程；AI 回「没听清」类话术；连续 2~3 次 → 降级向导 |
| 字典外说法（如「火箭速度来修」） | 该字段忽略不写，照旧发卡问；其他字段不受影响 |
| 一句话带多个字段 | 说到的（含可推断的影响营业）**直接预填**并复述；类别永远必须点选 |
| 用户打字说「提交 / 交单」 | **不代点按钮**：在确认单上→提示点【确认并提交】；没到确认单→提示还缺哪几项 |

### 6.3 对话边界

| 情况 | 行为 |
|---|---|
| 闲聊 / 问进度 | 一句拉回话术不展开；问进度指路「历史报修记录」 |
| 越权（报其他门店） | 拉回，只允许当前门店 |
| 提示词注入（「忽略之前指令…」） | 当普通文本无视，拉回 |
| 连续 2~3 轮识别失败 | 切 `fallback`（**仍是 200 正常响应**）：顶部提示已切换卡片填报 + 全量类别卡，照样能交单 |

### 6.4 随时可改

| 情况 | 行为 |
|---|---|
| 采集中打字改字段 | 原地更新，state/focus 不变；回一句确认话术 |
| 确认单上点改 / 打字改 | 改值后**留在确认单**，重发一张新确认单（该字段来源标 user_edited） |
| 确认单上重选类别（唯一例外） | 已传照片与描述**作废**，界面回拍照步骤重采 |
| 提交后再想改 | 不可改；打字回「已提交不可改」；改单走明道云驳回重提（线下流程） |

### 6.5 照片

| 情况 | 行为 |
|---|---|
| 上传流程 | 调上传接口拿 media_id → 前端自动发 upload_done；单文件 ≤10MB、单会话 ≤5 张、仅图片/视频 |
| 违规文件（超 10MB / 第 6 张 / 格式错） | 42201 + 人话提示；已传照片不受影响 |
| 删除照片 | 确认单 photos 项 [管理] → 已传列表逐张删（media_remove 消息）；删不存在的 id → 42201 |
| 按类别差异化拍摄清单与警示（如购物袋袋底必拍） | 二期；本期统一通用引导 |

### 6.6 提交

| 情况 | 行为 |
|---|---|
| 没到确认单就调提交 | 40901 + 提示还有哪几项没填；不建单，会话不受影响 |
| 确认单缺必填 | 42201；确认单高亮 missing 字段 |
| 连点 / 网络重试 | 幂等：只建一单，重复请求返回**同一单号**（上线必测红线） |
| 明道云提交失败 | 50302：提示已记录自动重试 + 客服电话；不产生半单 |
| 提交后 GET 会话 | 404 属正常（会话已终结），前端不要当错误弹 |

### 6.7 网络与服务异常

| 情况 | 行为                                                         |
|---|------------------------------------------------------------|
| 打字轮响应慢 | 最长约 x （暂定10） 秒，输入区展示「处理中」；请求超时/响应丢失 → 调 GET 按 seq 补齐（不重不漏） |
| 杀 App / 断网中途断开 | 无需任何处理，直接重进走恢复链路                                           |
| AI 服务不可用（50301） | toast 暂不可用 + 引导回传统表单                                       |
| 当日配额用尽（42901） | 提示「今日 AI 次数已用完」+ 引导切表单；次日自动恢复                              |
| 单会话配额超限 | **不是错误**：200 + fallback 向导，体验同 6.3 降级                      |

### 6.8 隐私

- 手机号**出参一律掩码**（138\*\*\*\*1234），前端任何位置不得出现完整号码；输入新号码走 11 位校验后即掩码展示。
- 类别等枚举全部由服务端下发，前端不自持字典（保证字典改了前端不用发版）。

## 七、前端埋点清单

| 事件 | 触发时机 | 支撑指标 |
|---|---|---|
| session_start | 建会话接口返回成功（含 is_resumed=true） | 填报时长（起点） |
| session_end | 提交成功或主动退出 | 填报时长（终点）、步数 |
| branch_a_input | 会话内第一条 text 消息发出 | 路径占比（含 source=keyboard/voice 维度） |
| branch_b_card_click | 点高频卡 | 路径占比 |
| enum_first_pick | 类别候选卡点选时（记录是否选了排第一位） | **类别识别准确率** |
| fallback_enter | 首次收到 state=fallback | 兜底率 |
| switch_to_form | 点「⇄ 传统表单」 | 转老表单率 |
| session_exit | 调退出接口（带 keep/abandon） | 中途放弃率 |
| draft_resume | 恢复卡片点【继续】 | 续填恢复率 |
| field_edit | 确认单或对话中改字段（带字段名） | AI 预填质量侧写 |
| submit_success / submit_fail | submit 成功 / 失败（422、50302 等） | 完成成功率、卡壳定位 |

事件名与后端埋点表一致；上报通道与参数细则联调时对齐。
