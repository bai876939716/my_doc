# 01 · 接口导入与调试指南

## 一、导入 Apifox（二选一）

**方式 A · URL 导入（推荐，可定时自动同步）**：后端服务起着时，Apifox → 项目 → 设置 → 数据导入 → OpenAPI/Swagger → URL 填：

```
http://<后端地址>:8000/openapi.json
```

**方式 B · 文件导入**：拿本目录的 `apifox-openapi.json` 文件导入同一入口。

> 导入后第一件事：右上角【环境管理】把**前置 URL** 改成后端地址（本地开发 = `http://localhost:8000`；dev 环境 = 届时提供的域名）。**别用默认的占位域名**，否则请求发不到后端。

## 二、调试剧本（按这个顺序调，一次跑通全流程）

所有请求都要带头 **`X-Uid: test001`**（模拟用户身份，生产环境由网关注入；同一 X-Uid = 同一个用户，重进会恢复未完成的会话）。

| 步 | 接口 | 关键入参 | 期待 |
|---|---|---|---|
| 1 | `POST /agent/repair/v1/sessions` | Header X-Uid + body `{"store_no":"11522"}`（**门店编号必填**，入口带入——用户在哪个店点报修就传哪个店） | 返回 session_id + 首屏 3 条消息（状态条/开场白/高频卡片），context 含 store_no/store |
| 2 | `POST .../sessions/{sid}/messages` | `{"type":"text","content":"冷柜不制冷了，鲜奶都下架了，尽快派人来修"}` | 复述 + 类别 Top3 卡；**注意上门/影响已自动预填不再发卡** |
| 3 | 同上 | `{"type":"enum_pick","field":"category","value":"工程类 - 制冷设备/冷柜"}` | 拍照引导 |
| 4 | 前端调用现有明道云上传接口 | 上传真实文件，取返回的 serverName + key | 得到完整原始 URL；Agent 不上传 |
| 5 | messages | `{"type":"upload_done","attachments":[{"name":"现场.jpg","url":"https://b.hotmaxx.cn/file/mdpic/实际文件路径.jpg"}]}` | 电话确认卡（**跳过期望上门/影响营业两张卡**） |
| 6 | messages | `{"type":"phone","use_default":true}` | `state=confirm` + 确认单（注意：确认单在响应 messages 里，详见 03 的说明） |
| 7 | `POST .../sessions/{sid}/submit` | 无 body | `{"order_no":"BX-...","status":"已提交 / 待派单"}` |
| 8 | `GET .../sessions/{sid}` | — | state=done + 全部历史消息（断线重连/刷新就用它） |

## 三、Mock 大脑的触发词（当前后端是规则版 Mock，方便你自测）

| 你说什么（text） | Mock 会返回 |
|---|---|
| 含"冷柜/冷藏/风幕" | 类别候选：制冷设备/冷柜 + 暖通/空调 |
| 含"下架/不敢卖" | 影响营业预填=是 |
| 含"尽快/马上" | 期望上门预填=尽快上门 |
| 含"电话" + 11 位手机号 | 改电话（update 意图） |
| 含"笑话/聊两句/你是谁" | 拉回话术（边界轮，槽位零写入） |

真模型（百炼 Qwen）本周接入后行为一致，联调代码不用改。

## 四、注意事项（联调自查）

- `messages[].seq` 全会话**严格递增**，按它排序渲染，永不重不漏；
- 手机号**出参一律掩码**（`138****1234`），前端不要拼完整号码；
- 错误响应统一结构 `{"code": 6位码, "message": "人话"}`：40401=会话没了（静默重建）、42201=校验失败（缺必填/非确认态提交）、50301=服务异常；
- `POST /sessions` 对同一 X-Uid **同店**重复调用是**安全的**（有未完成会话→is_resumed=true 返回现场；已完成→自动开新会话；**换 store_no 则开新会话，各店互不干扰**）——页面刷新/重进 App 就调它。

## 附件协议（本次更新）

前端上传成功后，使用 `serverName.replace(/\/$/, "") + "/" + key` 拼出完整文件地址；不要重复拼 bucket/filePath。原文件名需要解码并保留扩展名。

向 messages 发送 `upload_done.attachments`，每项仅包含 `name` 与完整 HTTP(S) `url`。不再发送 media_ids；旧 multipart 上传入口已删除（404），请切换调用。

附件按 URL 去重，单会话最多5项；每轮传新增附件。恢复时以 GET 返回的 `collected.photos` 为准；确认卡 photos 项的 value 同样为附件数组，前端按 url 展示缩略图、按 name 展示文件名。重选类别后旧照片清空，以最新 collected 为准，不要把历史确认卡当当前数据。

旧草稿中的模拟图片 ID 不能转换为图片，需重新上传；不能把 m_001/blob:/本地路径传作 url。只传文件引用，照片本体由上传服务保存。当前 memory 模式重启仍会丢失会话。

V3 附件 `{name,url}` 已由真实测试确认可写入；正式 HTTP 建单开关仍受人员与完整字段接入限制，本次不解除该限制。
