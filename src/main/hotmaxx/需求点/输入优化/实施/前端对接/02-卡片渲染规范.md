# 02 · 卡片渲染规范（10 种服务端消息 × 6 种用户手势）

> 核心模型：对话流 = 一串 `messages`，每条 `{seq, type, data}`。type 决定渲染成什么；
> 用户的手势回发到 `POST /messages`，`type` 决定含义。**前端只渲染、回发，不决策**。

## 用户消息（6 种手势）

| type | 附加字段 | 什么时候发 |
|---|---|---|
| `text` | content（≤500字） | 输入框打字/语音转文字后 |
| `card` | card_id | 点高频卡片（开场那 6 张） |
| `enum_pick` | field / value | 点类别单选卡（含确认单上【重选类别】） |
| `seg_pick` | field / value | 点二选一卡（期望上门/影响营业） |
| `upload_done` | attachments:[{name,url}] | 前端上传明道云成功后通知后端 |
| `phone` | use_default 或 phone | 电话确认卡二选一 |

## 服务端消息（10 种卡片）

### 1. `status_bar` 状态条
`{store, reporter, phone_masked}` —— 页面顶部固定条：📍门店 ｜ 报修人 电话 [修改]。只渲染一次（首屏），后续消息里不再出现。

### 2. `text` 文本气泡
`{content}` —— 普通对话气泡（支持 `**加粗**` 简单标记）。所有 AI 话术都是它。

### 3. `quick_cards` 高频卡片墙
`{cards: [{id, icon, title}]}` —— 横向滚动卡片组。**点整卡** → 发 `{"type":"card","card_id":"xxx"}`。点完这张卡墙就完成使命（后端不再重发）。

### 4. `enum_card` 类别单选卡 ⭐核心
`{field, mode(top3|full), options[], preselect}` —— 竖排单选列表；`preselect≥0` 时该项高亮预选（**仅视觉提示，必须点一下才生效**）；mode=full 是降级时的全量列表（可滚动）。点击项 → 发 `{"type":"enum_pick","field":"category","value":"选项原文"}`。

### 5. `photo_guide` 拍照引导
`{need_count, tips:[{text, level(info|warn)}], warning}` —— tips 逐条列出（level=warn 的条目红色）；warning 非空时整卡红色警示（差异化警示二期，本期统一通用引导）。**单张口径：1 张即可继续**（need_count 按最小 1 渲染；单会话上限 5 张）。用户操作：调起相机/相册 → 现有明道云上传接口（取得 serverName + key 拼 URL）→ 发 `{"type":"upload_done","attachments":[{"name":"现场.jpg","url":"完整HTTP(S)地址"}]}`。

### 6. `seg_card` 二选一卡
`{field, question, options:[{value, label}]}` —— 横向两按钮。点击 → 发 `{"type":"seg_pick","field":"同卡片的field","value":"选项value"}`。期望上门和影响营业复用此卡。

### 7. `phone_confirm` 电话确认卡
`{phone_masked, use_default}` —— "用本人号码 138****1234 吗？"。两个动作：`{"type":"phone","use_default":true}` 或 `{"type":"phone","phone":"139..."}`（11 位校验在前端做）。

### 8. `confirm_card` 确认单 ⭐核心
`{groups:[{group_name, items:[{field,label,value,editable,source}]}], missing[]}` —— 10 字段分组平铺；每项可编辑（editable），`source=ai_filled` 的项加"AI 识别"角标；`missing` 非空时高亮缺项。交互：
- 点【确认并提交】→ `POST /sessions/{sid}/submit`（不是 messages！）；
- 改普通字段（描述/电话）→ 发 text 消息（"电话改成 139..."），响应回新确认单；
- 重选类别 → 发 `enum_pick`（field=category）——**注意：只作废已传照片（描述保留），响应里是新拍照引导 + system_tip 作废提示**；
- missing 有内容时提交按钮置灰或提交返回 42201（响应里有缺项提示文案，toast 即可）。

### 9. `system_tip` 系统提示条
`{content, level(info|warn|error)}` —— 非对话语气的居中提示条（降级提示等），按 level 着色。

### 10. `result` 结果卡
`{order_no, status, tip}` —— 提交成功终点卡：大字单号 + 状态 + 【查看报修记录】按钮（跳转已有记录页，带单号）。

## 渲染通则

- 消息列表按 `seq` 升序 append；一轮响应的 messages 逐条插入（可做轻量逐条动画，纯体验加分项）；
- 同一时刻**最后一张"可交互卡片"**是当前操作焦点（配合响应的 focus 字段高亮）；
- 任何卡片都可能在降级（fallback 态）下重发，渲染逻辑不用区分，照常画；
- **每轮响应以"当前待办"收尾**（路由不变量）：用户跑题/改值/追问后，服务端一定重发当前问题卡——界面上"现在该干嘛"永远清楚；
- 降级态五种结构化手势（card/enum_pick/seg_pick/upload_done/phone）照常回发，只拦 text；
- 行为细节：打字"改手机号"不带值 → 服务端追问（text）；裸值（"可以等待安排吧"）会被当前问题吃掉；选项外说法 → 服务端提示并把选项卡递回。

确认卡 `field=photos` 的 `value` 现在是 `[{name,url}]` 数组，不再是“2 张”字符串；展示数量用数组长度，图片用 url，名称用 name。GET 的 collected.photos 返回同结构，用于恢复回显。
