# 03 · 页面流程与状态驱动

## 一、页面结构

```
表单页（现有页面，只加一张入口卡片）
 └── 顶部「AI 智能填报」入口卡片（点击 → 打开对话页，携带 store_no）

对话页（正式版 HTML 全部内容）
 ├── 顶部固定：status_bar（📍门店｜报修人 电话）+ 返回按钮
 ├── 中部滚动：消息流（气泡 + 各种卡片）
 └── 底部固定：输入框 + 发送（无独立 📷 按钮——拍照走 photo_guide 卡内的上传动作）
```

## 二、状态机：服务端 4 态 + 页面本地 2 态

渲染的唯一依据 = 每轮响应的 `state` + `focus`，页面不需要自己记"进行到哪了"。

服务端会返回的 4 种 state：

| state | 页面表现 | 输入框 |
|---|---|---|
| `collecting` | 正常对话；`focus` 说明当前在采哪个字段（photos 时拍照卡即当前焦点） | 可用（打字随时可改已填字段） |
| `confirm` | 消息流末尾是确认单，底栏浮现【✓ 确认并提交】大按钮 | 可用（改字段走口述 text） |
| `done` | 结果卡 + 查看记录按钮 | 停用（提示"已提交"） |
| `fallback` | 降级向导：点选类手势放行、只拦 text，照样能交单 | text 置灰 + 提示 |

页面本地自造的 2 个态（服务端不会返回）：`offline`（连不上后端，显示重试）、`exited`（用户已退出，等待从表单页重进）。

**注意**：`POST /sessions`（建会话）的响应里**没有 state 字段**，只有 messages。按消息推断即可：messages 里有 confirm_card 就是 confirm 态，否则 collecting（正式版 HTML 的 `inferApply` 就是这么做的）。

## 三、五个关键场景

### 1. 进入对话页
永远先 `POST /sessions`（body: `{store_no, restart:false}`）：

- `is_resumed=false`：正常新会话，渲染返回的 messages（首屏三件套：状态条 + 开场白 + 6 张高频卡）；
- `is_resumed=true`：同一个人同一家店有没填完的草稿，服务端把历史消息（含用户气泡回显）都拼好返回了。先弹「继续上次报修？」：继续 → 直接渲染；重新开始 → 再调一次 `POST /sessions` 带上 `restart:true`（一个请求完成放弃+新建，不用先发 exit）。

### 2. 每轮对话
`POST /messages` → 等响应（打字轮最长约 8 秒，期间显示"整理中…"）→ 把 messages 逐条入流 → 按 state/focus 调整底栏。

**请求超时/失败 ≠ 数据丢失**：调 `POST /sessions/{sid}`（会话查询，GET/POST 同义）拿全量消息，按 seq 幂等去重对齐渲染即可。App 统一走 POST——公网网关对同一地址的 GET/POST 登记是互斥的。

### 3. 确认单与提交（state=confirm）
- 确认单出现在本轮响应的 messages 里，会话查询重放时同样在；
- 提交走独立接口 `POST /submit`（仅 confirm 态可提，别的态返回 40901）；
- 提交**响应**只有 `{order_no, status}` 两个字段；**结果卡（result）在服务端消息档案里**——提交成功后调一次会话查询就能拿到，按 seq 去重回放。等不及查询也可以直接用 submit 响应自己组装展示，两种做法正式版都兼容；
- 提交返回 42201：toast 错误 message，缺的项（如照片）服务端已塞回议程并补发引导卡，会话查询对齐即可看到。

### 4. 退出与切回
- 返回按钮 → 三选一弹窗：继续填写（不调接口）/ 存草稿离开（`POST /exit` body `{"mode":"keep"}`，草稿保留 7 天）/ 放弃本次（`{"mode":"abandon"}`）；
- exit 幂等：会话已经没了再退一次也回 ok；
- 已提交的会话退出无副作用（服务端直接忽略）。

### 5. 重进恢复
- 本地存 session_id（localStorage）做加速：重进先用它查会话，查到直接恢复现场（含用户气泡）；
- 查不到（40401，过期或被清）→ 静默重开新会话；
- 已出过单的会话不复用：重进自动开新单（服务端行为，前端无感）。

## 四、前端要做的本地校验（仅这几条）

text ≤500 字；phone 11 位正则（`1` 开头）；上传文件类型 image/\*、单文件 ≤10MB、单会话 ≤5 张。其余（枚举合法性、必填、重复提交、越权）全部由服务端把关，前端只消费错误码（见 04）。

## 五、消息里的用户回显（role=user）

会话查询（GET 重放）和恢复会话时，历史里会带 `role:"user"` 的消息（用户当时发的手势原文）。用它重建用户气泡——完整对话以服务端为准。POST /messages 的响应不含用户条目（那条前端刚发过、自己画过了）。
