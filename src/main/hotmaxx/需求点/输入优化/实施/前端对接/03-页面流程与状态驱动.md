# 03 · 页面流程与状态驱动

## 一、页面结构（对照原型 html）

```
表单页（现有页面，不动）
 └── 顶部「AI 智能填报」入口卡片（点击 → 进对话页）

对话页（新增，全部内容）
 ├── 顶部固定：status_bar（📍门店｜报修人 电话）+【⇄ 切回表单】按钮
 ├── 中部滚动：消息流（气泡 + 各种卡片）
 └── 底部固定：输入框 + 📷 按钮（focus=photos 时高亮引导拍照）
```

## 二、状态驱动：一个状态机，五种状态

**唯一的渲染依据 = 每轮响应的 `state` + `focus`**。前端不需要自己记"进行到哪了"。

| state | 页面表现 | 输入框 |
|---|---|---|
| `collecting` | 正常对话；`focus` 告诉你当前在采哪个字段（photos 时高亮拍照按钮） | 可用（打字随时可改已填字段） |
| `confirm` | 消息流末尾是确认单；确认单下方悬浮【确认并提交】大按钮 | 可用（改字段的口述走 text） |
| `done` | 结果卡 + 跳转记录页按钮；输入框停用（提示"已提交"） | 停用 |
| `fallback` | 降级向导：只点卡不打字（AI 暂时休息，照常能交单） | 置灰 + 提示 |
| `exited` | （主动退出后）无会话态，重进自动开新会话 | — |

## 三、四个关键场景的处理

### 1. 进入对话页
永远先 `POST /sessions`（带 X-Uid）：
- `is_resumed=false`：渲染返回的 `messages`（首屏三件套）；
- `is_resumed=true`：**先弹「继续上次报修？」卡片**，用户确认后渲染 `messages`（历史消息全在里面，包括更早轮次——服务端已拼好）；拒绝则调 exit(abandon) 再 POST 一次 sessions。

### 2. 每轮对话
`POST /messages` → 等响应（打字轮最长 ~8s，转圈提示"整理中…"）→ 把 `messages` 逐条入流 → 按 `state/focus` 调整底栏。**请求超时/失败 ≠ 数据丢失**：调 `GET /sessions/{sid}` 拿全量消息对齐渲染即可（按 seq 幂等去重）。

### 3. 确认单（state=confirm）
- 确认单卡片出现在**本轮响应的 messages 里**（它是挂起载荷，GET 重放时同样在）；
- 提交走独立接口 `POST /submit`；成功后响应 `{order_no, status}`，渲染 result 卡（服务端不会在 messages 里再发 result，前端自己组装展示）；
- 提交返回 42201：toast 错误 message，同时下一轮 GET 对齐（照片缺失时服务端会把 photos 塞回议程、发新的 photo_guide）。

### 4. 退出与切回
- 点【⇄ 切回表单】：调 `POST /exit` `{"mode":"keep"}`（草稿保留 7 天）→ 返回表单页；
- 返回键/手势：弹三选一（继续填写 / 保存草稿离开 / 放弃本次）——分别对应：不调接口、exit(keep)、exit(abandon)。

## 四、前端要做的本地校验（仅这几条）

text ≤500 字；phone 11 位正则；上传文件类型 image/*|video/*、单文件 ≤10MB、单会话 ≤5 个。其余（枚举合法性、必填、重复提交）**全部信任服务端**，前端只消费错误码。
