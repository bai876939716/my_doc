# 04 · 接口调试指南

## 一、导入 Apifox（二选一）

**方式 A · URL 导入（推荐，可定时同步）**：后端服务起着时，Apifox → 项目 → 设置 → 数据导入 → OpenAPI/Swagger → URL 填 `http://<后端地址>:8000/openapi.json`。

**方式 B · 文件导入**：用本目录的 `apifox-openapi.json` 走同一入口。

导入后第一件事：右上角【环境管理】把**前置 URL** 改成后端地址（本地 = `http://localhost:8000`；测试环境 = `https://gateway-dev.hotmaxx.cn`）。别用默认占位域名，否则请求发不出去。

## 二、身份口径（调试前必读）

- **直连后端（本地/联调）**：所有请求带头 **`X-Uid: <员工ID>`**。同一 X-Uid = 同一个用户，重进恢复未完成的会话。缺这个头，五个业务接口一律 `401 / 40101`——服务端故意不兜底（否则所有匿名用户会共用同一条草稿）。
- **经网关（App 正式链路）**：前端**不传 X-Uid**，只带 App 登录 token，身份由网关 + Java 转发层注入。经网关收到 401 是登录态/转发配置问题，找后端查链路。
- 本地后端想开匿名演示：`.env` 设 `ALLOW_ANONYMOUS=true`（仅限本机演示）。

## 三、调试剧本（按顺序调，一次跑通全流程）

以下默认直连本地（`X-Uid: test001`）。本地未配 base-shop 主数据时是演示模式：门店 11522/11551、报修人"白云翔"；配了 base-shop（测试环境）则要用**真实存在的门店编码和员工 ID**（dev 库查无 11522，会退占位店名、报修人退空）。

| 步 | 接口 | 关键入参 | 期待 |
|---|---|---|---|
| 1 | `POST /agent/repair/v1/sessions` | Header `X-Uid` + body `{"store_no":"11522"}`（门店编号必填，入口带入） | `session_id` + 首屏 3 条消息（状态条/开场白/高频卡），context 含 store_no/store |
| 2 | `POST .../sessions/{sid}/messages` | `{"type":"text","content":"店里的空调不凉了，出风口全是常温风，尽快派人来修"}` | 复述 + 类别 Top3 卡（"尽快派人来修"这类催促只进故障描述，不单独采集） |
| 3 | 同上 | `{"type":"enum_pick","field":"category","value":"工程类 - 空调不制冷/热"}` | 拍照引导（value 必须是字典原词，瞎写会被 422 拒；门店自修的类别不拒，见第五节末尾） |
| 4 | 明道云上传接口（前端直传） | 上传真实文件，取 serverName + key | 拼出完整 URL；Agent 侧没有上传接口 |
| 5 | messages | `{"type":"upload_done","attachments":[{"name":"现场.jpg","url":"https://b.hotmaxx.cn/file/mdpic/实际路径.jpg"}]}` | 1 张即过 → 电话确认卡（员工档案无手机号时是一条要号文案，没有卡） |
| 6 | messages | `{"type":"phone","use_default":true}` | `state=confirm` + 确认单（在响应 messages 里） |
| 7 | `POST .../sessions/{sid}/submit` | 无 body | `{"order_no":"BX-...","status":"已提交 / 待派单"}`；重复提交幂等返回同一单号 |
| 8 | `POST .../sessions/{sid}` | 无 body | 全量消息重放（含用户气泡）+ `collected` 已收集字段。刷新/断线对齐都用它。GET/POST 同义，App 统一走 POST |

其他两个接口：

- `POST .../sessions/{sid}/exit`：body `{"mode":"keep"}`（草稿留 7 天）或 `{"mode":"abandon"}`（销毁）。幂等，重复退回 ok；
- `POST /sessions` 带 `{"store_no":"...","restart":true}`：一键"重新开始"——服务端在一个请求里先放弃旧会话再建新的，前端不用先发 exit。

## 四、会话规则（联调时会碰到）

- 草稿按 (uid, store_no) 存：同店重进恢复现场，换店各开各的，互不干扰；
- 已出单的会话不复用：重进自动开新单；
- 出单后（done 态）再发 messages → 42201"本单已提交"；submit 重复调 → 幂等返回原单号；
- dev 当前会话存储是 memory 模式：**后端重启草稿就丢**（生产切 postgres 后无此问题，上线清单既定项）。

## 五、本地起服务与模型

本地给页面联调，起这个入口（比正式入口多一层 CORS，浏览器 file:// 直连才不会预检 405；业务代码零差别，永远不进生产部署）：

```
执行: uv run python -m uvicorn poc.local_demo_app:app --port 8000 --reload
```

然后打开演示版 HTML，左侧环境切「本地 8000」即可。

模型口径：**服务永远调真模型**（缺模型配置直接拒启动，没有静默降级）。当前配置 **deepseek-v4.1-flash-1017**（百炼 OpenAI 兼容端点，Nacos `LLM_MODEL` 可换）。本地 `.env` 要有 `LLM_BASE_URL / LLM_API_KEY`，或从 Nacos 拉。

Mock（规则版假模型，零网络零成本）只在换桩入口 `poc/mock_llm_app:app` 里生效，给评测和全量场景跑确定性用；前端联调一般用不上，但它的触发词对"预期服务端返回什么"有参考价值：

| 你说什么（text） | Mock 会返回 |
|---|---|
| 含"冷柜/冷藏/风幕/冷冻"或"灭火器" | 告知「…」这类需要门店自修、不用报单，回到「说说故障情况」（这些类别不给报单，这句话也不当描述） |
| 含"空调" | 类别 Top3 候选：工程类 - 空调不制冷/热、工程类 - 空调清洗 |
| 含"灯/照明/招牌" | 类别候选：工程类 - 照明灯（1至4个） |
| 含"电话" + 11 位手机号 | 改电话（update 意图，直接落值） |
| 只说"改手机号/改电话"不带号 | 服务端追问要号 |
| 含"笑话/聊两句/你是谁" | 应和 + 拉回话术（边界轮，槽位零写入） |

**门店自修的类别不给报单**（名字带「门店自修」：冷柜、灭火器、仓库门/消防栓门的锁和把手）。高频卡和全量类别卡里都没有它们；真要调试这条分支，直接发 `{"type":"enum_pick","field":"category","value":"工程类 - 灭火器（门店自修）"}`——不会 422，服务端回一条告知「「灭火器」这类需要门店自修，门店自己处理就行，不用报单。还有别的要报的吗？」并把全量类别卡递回来（用户是在卡上点到的，照旧递卡）；类别不落库，流程接着往下走。打字「灭火器过期了」是另一种表现：告知之后不弹类别卡，回到「用一句话说说故障情况」，这句话也不会被当成故障描述。

## 六、错误码表（统一结构 `{"detail":{"code":6位码,"message":"人话"}}`）

| code | 含义 | 前端处理 |
|---|---|---|
| 40101 | 没识别出身份（缺 X-Uid / 网关头没配上） | 提示重新进入；网关链路找后端查 |
| 40401 | 会话不存在或已过期 | 静默重建（重调 POST /sessions） |
| 40901 | 不在确认态就调了 submit | 一般是页面状态不同步，先查会话对齐 |
| 42201 | 校验失败（缺必填/非确认态改值/附件超限/已提交再改） | toast message；缺项服务端已塞回议程 |
| 50201 | 建单链路异常（明道云侧失败） | toast message，让用户稍后再试 |
| 50301 | 服务暂不可用（探活失败兜底） | 提示稍后重试 |

另有 FastAPI 原生参数校验错（`detail` 是数组），按 HTTP 422 处理即可，正常前端不会碰到。

## 七、附件协议（upload_done）

- 前端用现有明道云上传接口直传，拿到 `serverName` + `key` 后拼 `serverName.replace(/\/$/, "") + "/" + key` 得完整地址，**不要**再拼 bucket/filePath；
- `attachments` 每项只有 `name`（解码后的原文件名，保留扩展名）和 `url`（完整 http(s) 地址）两个字段，**没有** media_ids——旧的 multipart 上传入口已删除（404）；
- 附件按 url 去重，单会话最多 5 个，超了 42201；每轮只传新增的；
- 恢复/回显以会话查询返回的 `collected.photos`（同结构数组）为准，别把历史确认卡当当前数据；
- 假引用（`m_001`、`blob:...`）当 url 传，服务端不会报错但图片显示不出来——只传真实上传结果。
