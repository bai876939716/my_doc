## 三条必须先知道的口径

1. **没有 SSE/WebSocket**——每轮对话 = 一次普通 `POST` + 一个 JSON 响应（`state / focus / messages` 三字段），用 fetch/axios 常规写法即可；
2. **前端不持有任何业务状态**——"现在该干什么"永远以服务端响应为准（state+focus 驱动渲染），本地只存 session_id 作加速；
3. **枚举值全部来自服务端**——卡片里的选项、确认单的内容都是响应里带好的，前端不自造字典。
