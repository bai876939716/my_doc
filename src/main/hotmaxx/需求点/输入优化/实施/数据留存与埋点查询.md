# 数据留存与埋点查询（PG · agent 库）

> 一句话：**框架三表管「活着的数据」（会话现场，7 天），归档两表管「永久的数据」（报表核验查这里），活跃索引管「重进恢复」**。不建独立埋点表——服务端指标全部从这两层用 SQL 推导（理由见第六节）。

连接方式（本机）：

```bash
docker exec -it asc-postgres psql -U agent -d agent
```

---

## 一、全景：六张表各管什么

| 表 | 归属 | 谁写 | 留存 | 一句话用途 |
|---|---|---|---|---|
| `agent_session_archive` | 应用 | submit 成功 / abandon 时 | **永久** | 会话摘要——数据核验与报表的主表 |
| `agent_message_archive` | 应用 | 同上 | **永久** | 对话明细——排查、对拍、审计 |
| `agent_active_index` | 应用 | 建会话 / 每轮续期 / 终态清除 | 惰性过期（7 天没动） | 重进恢复入口：uid+门店 → 会话 |
| `checkpoints` | langgraph | 引擎每轮（先存再推） | 活跃期 + 终态后 7 天 | 会话快照（草稿恢复的现场） |
| `checkpoint_blobs` | langgraph | 同上 | 同上 | State 各通道的序列化数据 |
| `checkpoint_writes` | langgraph | 节点执行中 | 同上 | 节点写入的中间记录 |
| `checkpoint_migrations` | langgraph | 启动 setup 时 | 永久 | 框架自己的迁移版本号（不用管） |

会话生命周期（时间线）：

```
建会话 ──每轮交互：检查点先存再推，活跃索引续期 7 天──► 终态
                                                    ├─ submit 成功 → 立即归档(摘要+消息) + 清活跃索引
                                                    │   检查点再留 7 天（GET done 可查），之后回收，归档永存
                                                    └─ abandon → 归档(status=abandoned) + 检查点立即销毁
keep 退出 = 不是终态：只留活跃索引，7 天内重进继续
```

## 二、逐表字段

### 1. `agent_session_archive`（会话摘要）

| 字段 | 类型 | 说明 |
|---|---|---|
| sid | TEXT 主键 | 会话 ID（rp_ 开头，即 thread_id） |
| skill | TEXT | 技能包名（本期恒 repair；报销接入后出现 expense） |
| uid | TEXT | 员工标识（X-Uid；生产为网关注入的用户 ID） |
| store_no | TEXT | 门店编号（入口带入） |
| status | TEXT | **submitted**（提交出单）/ **abandoned**（放弃） |
| order_no | TEXT | 单号；abandon 为 NULL。Mock 模式为 `MOCK-{sid}`，真实建单为明道云单号 |
| category | TEXT | 最终报修类别（如「日常营运用具类 - 冷柜」） |
| llm_calls | INT | 本会话 LLM 调用次数（成本对账；点卡片路径为 0） |
| msg_count | INT | 归档消息条数（2026-11-13 起含用户手势回显 role=user；此前存量行=纯服务端消息） |
| started_at | TIMESTAMPTZ | **会话起点**（建会话时写入 State meta，UTC；时长=archived_at−started_at。2026-11-13 前的存量行为 NULL） |
| resume_count | INT | **被恢复次数**（POST /sessions 命中活跃会话 +1，从活跃索引行带走——续填率口径） |
| branch | TEXT | a=描述路径 / b=卡片路径（路径占比） |
| final_mode | TEXT | normal / fallback（是否降级后完成——降级完成率） |
| archived_at | TIMESTAMPTZ | 归档时刻（= 终态时刻） |

写入时机：submit 接口成功（含幂等命中时的补档，ON CONFLICT 覆盖，重复归档不脏数据）；exit abandon（在销毁检查点**之前**写）。submit 路径归档发生在清活跃索引**之前**（resume_count 要从索引行带走）。

### 2. `agent_message_archive`（对话明细）

| 字段 | 类型 | 说明 |
|---|---|---|
| sid + seq | 主键 | seq 与接口消息序号同源，全会上话单调递增 |
| role | TEXT | **2026-11-13 起含 role=user**（用户手势回显：intake 节点落档，打字原文/点选摘要/上传引用全在档）；此前存量行为纯 server 消息 |
| type | TEXT | 服务端消息 10 种：status_bar / text / quick_cards / enum_card / seg_card / photo_guide / phone_confirm / confirm_card / system_tip / result |
| data | JSONB | 该 type 的完整负载，与接口文档 v2.2 的消息结构逐字段一致 |

### 3. `agent_active_index`（活跃索引）

| 字段 | 类型 | 说明 |
|---|---|---|
| key | TEXT 主键 | `rp:active:{uid}:{store_no}`（一人多店各开各会话） |
| sid | TEXT | 指向活跃会话 |
| expires_at | TIMESTAMPTZ | 每轮交互刷新为 now()+7 天；**过期即失效**（get 时惰性判定，后台清理回收行） |
| resume_count | INT | 该会话被恢复的次数（归档时随摘要行带走） |

技巧：`expires_at - 7 天 ≈ 最后活跃时刻`（下文查询用到）。

### 4. 框架三表（langgraph 自管，只读不手工改）

| 表 | 关键字段 |
|---|---|
| `checkpoints` | thread_id / checkpoint_id / parent_checkpoint_id / checkpoint(JSONB) / metadata(JSONB) |
| `checkpoint_blobs` | thread_id / channel / version / blob(BYTEA)——State 通道值 |
| `checkpoint_writes` | thread_id / checkpoint_id / task_id / channel / blob |

GET 会话、断点恢复、幂等判断（meta.order）都从这三表还原 State。**没有时间列**（框架如此），所以「会话内耗时」从这里也算不出。

## 三、留存与清理规则

| 规则 | 值 | 改法 |
|---|---|---|
| 活跃索引 / 检查点 TTL | 7 天滑动（每轮续期） | `.env` 的 `ACTIVE_TTL_DAYS`，改完重启 |
| 终态后检查点保留 | 7 天（之后清理线程回收，GET 按 40401 过期） | 同上 |
| 归档两表 | 永久（无清理） | 量级估算：一单 ≈ 1 行摘要 + 约 20 行消息；灰度几百单完全无压力 |
| 清理线程 | 启动首扫 + 每 30 分钟一轮 | 间隔常量在 `app/core/pgstore.py` |

## 四、日常查询手册（复制即用）

```sql
-- ① 今日/近 7 天提交与放弃（漏斗第一层）
SELECT status, count(*) FROM agent_session_archive
WHERE archived_at >= current_date - 6 GROUP BY status;
SELECT date(archived_at) AS 天, status, count(*) FROM agent_session_archive
WHERE archived_at >= current_date - 6 GROUP BY 1, 2 ORDER BY 1;

-- ② 会话清单：近 7 天按门店
SELECT store_no, count(*) FILTER (WHERE status='submitted') AS 提交,
       count(*) FILTER (WHERE status='abandoned') AS 放弃
FROM agent_session_archive WHERE archived_at >= current_date - 6
GROUP BY store_no ORDER BY 提交 DESC;

-- ③ 单号反查会话（对账明道云用：导出单号清单）
SELECT sid, uid, store_no, order_no, category, archived_at
FROM agent_session_archive WHERE order_no LIKE 'BX-%';   -- Mock 单换 'MOCK-%'

-- ④ 某会话完整对话重放（role=user 行为用户手势回显——原话/点选/上传全在档）
SELECT seq, type, left(data::text, 100) AS 内容
FROM agent_message_archive WHERE sid = 'rp_xxxx' ORDER BY seq;

-- ⑤ 进行中的草稿（活跃会话现状；最后活跃 = expires_at 减 7 天）
SELECT sid,
       split_part(key, ':', 3) AS uid,
       split_part(key, ':', 4) AS store_no,
       expires_at - interval '7 days' AS 最后活跃
FROM agent_active_index ORDER BY 最后活跃 DESC;

-- ⑥ LLM 成本对账（总调用次数 / 均次）
SELECT count(*) AS 会话数, sum(llm_calls) AS 总调用,
       round(avg(llm_calls), 1) AS 均次
FROM agent_session_archive WHERE status = 'submitted';

-- ⑦ 类别分布（近 30 天提交单）
SELECT category, count(*) FROM agent_session_archive
WHERE status='submitted' AND archived_at >= current_date - 29
GROUP BY category ORDER BY 2 DESC;

-- ⑧ 消息类型分布（卡片曝光量级，服务端视角）
SELECT type, count(*) FROM agent_message_archive GROUP BY type ORDER BY 2 DESC;

-- ⑨ 库存体检：检查点会话数与归档行数
SELECT (SELECT count(DISTINCT thread_id) FROM checkpoints) AS 检查点会话数,
       (SELECT count(*) FROM agent_session_archive) AS 归档会话数,
       (SELECT count(*) FROM agent_message_archive) AS 归档消息数;

-- ⑩ 填报时长（分钟：平均/最长；2026-11-13 前的存量行 started_at 为 NULL，自动排除）
SELECT round(avg(extract(epoch from (archived_at - started_at)) / 60.0)::numeric, 1) AS 平均分钟,
       round(max(extract(epoch from (archived_at - started_at)) / 60.0)::numeric, 1) AS 最长分钟,
       count(*) AS 样本数
FROM agent_session_archive
WHERE status = 'submitted' AND started_at IS NOT NULL;

-- ⑪ 过程指标一览（提交单：续填率 / 降级完成率 / 卡片路径占比 / 均 LLM 次数）
SELECT round(avg((resume_count > 0)::int)::numeric, 2)         AS 续填率,
       round(avg((final_mode = 'fallback')::int)::numeric, 2)  AS 降级完成率,
       round(avg((branch = 'b')::int)::numeric, 2)             AS 卡片路径占比,
       round(avg(llm_calls)::numeric, 1)                       AS 均LLM次数,
       count(*)                                                AS 单数
FROM agent_session_archive WHERE status = 'submitted';

-- ⑫ 类别识别准确率（AI 首选被点中率：Top3 卡首位 vs 用户点选值；只统计走了 Top3 卡的点选）
WITH picks AS (
  SELECT p.sid, p.seq, p.data->>'value' AS picked,
         (SELECT c.data->'options'->>0
          FROM agent_message_archive c
          WHERE c.sid = p.sid AND c.role = 'server' AND c.type = 'enum_card'
            AND c.data->>'mode' = 'top3' AND c.seq < p.seq
          ORDER BY c.seq DESC LIMIT 1) AS top1
  FROM agent_message_archive p
  WHERE p.role = 'user' AND p.type = 'enum_pick' AND p.data->>'field' = 'category'
)
SELECT count(*) AS top3点选数,
       count(*) FILTER (WHERE picked = top1) AS 首选命中,
       round(avg((picked = top1)::int)::numeric, 2) AS 准确率
FROM picks WHERE top1 IS NOT NULL;
```

## 五、指标总账：每个指标用什么查

服务端指标全部从归档两表推导（查询编号=第四节），前端行为类走 App 埋点通道：

| 指标 | 口径 | 用什么查 | 状态 |
|---|---|---|---|
| 提交量 / 放弃率 | 归档表 status 维度 | SQL ①② | ✅ |
| **填报时长** | archived_at − started_at | SQL ⑩ | ✅（存量老行 NULL 自动排除） |
| **续填率** | 提交单中 resume_count>0 的占比 | SQL ⑪ | ✅ |
| **降级完成率 / 卡片路径占比** | final_mode / branch 维度 | SQL ⑪ | ✅ |
| LLM 成本 | llm_calls 汇总 | SQL ⑥⑪ | ✅（token 级细账在模型网关侧） |
| 类别分布 | 摘要 category | SQL ⑦ | ✅ |
| **类别识别准确率**（AI 首选被点中率） | Top3 卡首位 = 用户点选值 | SQL ⑫ | ✅（2026-11-13 手势落库解锁） |
| **完整对话审计** | 用户原话重放 | SQL ④ | ✅（role=user 行即用户手势回显） |
| 渗透率 / 转老表单率 | 入口行为 | 前端 12 埋点（触发时机表在《报修AI填报-前端与测试说明》） | 前端联调时挂，走 App 通道，不进本库 |
| 驳回率 | 明道云工单被驳回占比 | 明道云侧（视图「被驳回」已有） | 后续查询工具或定期人工对账 |

~~唯一剩余缺口=用户手势落库~~ **已落地（2026-11-13）**：引擎 intake 节点把每个外部手势写成 role=user 消息进 State（恒为本轮第 1 条，seq=进轮前 seq_counter+1）；POST 响应按 role 过滤只回服务端消息（契约不变），GET 刷新对齐与建会话恢复带用户回显；终态归档自动落 role=user 行；demo 删掉 localStorage 补气泡补丁（乐观渲染按 anchor+1 记 seq 去重，清缓存/换设备对话也不丢）。

## 六、为什么不建独立埋点表

服务端不建 `event` 表，指标从归档两表推导，理由三条：**提交即归档是同一次写库**，不存在埋点上报丢失/乱序/重复；查询即 SQL，不用维护上报链路和第二套存储；归档表本身就是数据核验的真值。用户手势（原话、点选、点的是第几个候选）已随 role=user 落库全覆盖（见第五节落地记录）；行为类指标（渗透/转老表单）属于前端埋点通道，不在本库。
