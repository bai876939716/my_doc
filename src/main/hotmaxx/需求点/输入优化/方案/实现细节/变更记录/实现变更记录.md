# 实现变更记录

## 2026-11-12 真机联调日：引擎三刀

### 1. 确认单去 interrupt 化（结构性变更，最大一刀）

- **变更**：confirm 从 `interrupt()` 挂起改为**普通节点**——确认单消息直接落 State，"等待确认"是数据不是控制流：`meta.confirm_pending`（confirm 置位；ask / fallback 清位；submit 成功或校验失败清位；建单失败保持）。提交：POST /submit 由接口层注入**内部手势** `{"type":"submit"}` 经入口路由直达 submit 节点（HTTP 六种消息 type 契约不变，外部无法伪造 submit）。图内 confirm→submit 边删除，改 confirm→END。
- **删除的补丁**：seq 预留块（routes）、挂起载荷合并读取（_round_messages）、Command(resume) 通道。
- **契约影响**：六接口对外契约 v2.2 零变化；seq 恢复连续单调（无预留空洞）。
- **影响文档**：图节点设计（confirm/submit 节点与挂起语义章节作废）；会话管理与草稿恢复（"interrupt 挂起"相关表述作废，检查点机制本身不变）；State设计（Meta.confirm_pending 含义）；技术方案 §5。diagrams 01/02 已随代码更新（AgentServerCenter/diagrams/）。
- **判别法则（备忘）**：interrupt 适用于"人的答复是**正在执行的节点**的计算输入"（工具审批/AI产出人改后同节点续用/跨天审批）；表单确认是"轮与轮之间的等待"，天然走 ask→END 模型。

### 2. 路由不变量：每轮以下一个待办收尾

- **变更**：议程非空时，update / 边界轮处理完一律路由 ask **重发当前问题卡**（repick_category 例外：自带类别卡）；议程空回确认单。用户任何绕路（跑题/改值/追问）后，屏幕最底下永远是当前待办。
- **影响文档**：图节点设计（路由表）、场景走查（"边界轮 END 收束"口径作废）。

### 3. 类别重选只作废照片、描述保留

- **变更**：category 的 OnChange invalidates `["photos","detail"]` → `["photos"]`。理由：描述是用户对故障的原话，换类别分类不改变故障本身；旧口径（场景 C"重选类别照片/描述作废重问"）的描述部分废除。B 路径免描述的 branch 跳过分支随之删除。
- **影响文档**：技能包设计 / 技能包实例（OnChange 声明）、场景走查 C 场景。

### 4. 提示词业务隔离

- **变更**：`app/core/llm.py` 的 SYSTEM_BASE 收敛为**业务无关协议壳**（纪律/意图/修改语义/输出骨架；测试锁定零业务词）。报修业务（角色/直填规则/示例/字典）全量移入 `repair/prompts.py`，直填规则**由槽位声明自动生成**。拼装顺序=业务段在前、协议壳收尾。验证：模型对拍 plus/flash 双 10/10（此前各 9/10）。
- **已知债（重构窗口）**：category_candidates 键名偏业务（应为 enum_candidates）；ALLOWED_DELTA 字段白名单仍在 core。
- **影响文档**：提示词工程（SYSTEM_BASE 全文与拼装章节——以技能包 prompts.py 为新真值）。

### 5. 行为新增（真机联调产出）

- 越界应和：joint_extract 输出加 `reply`（仅边界意图，≤30 字；空则罐头拉回兜底）。
- update 无值追问：`update_targets`（模型报想改字段→按字段追问；改类别→重发全量类别卡）。
- 手机号正则兜底：update 意图下模型漏抽号码时，代码从原话正则恢复。
- 降级向导：免描述（branch=b）；前端降级态放行五种结构化手势、只拦 text。
- OnChange 作废时发 system_tip 明说（"刚才的修改让「现场照片」作废了…"）。
- **影响文档**：接口文档场景示例、前端与测试说明边界异常表、测试方案 S 条目——均列入"文档对齐"欠账。
