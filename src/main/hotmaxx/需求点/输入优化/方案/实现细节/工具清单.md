# 工具清单（内部）

> 一句话：**引擎伸手可及的全部能力清单**——工具名、干什么、靠什么、守什么规矩、怎么顶替。对外向其他团队索要的接口见《[依赖接口清单.md](依赖接口清单.md)》——门店信息由前端传入、日期服务端生成、手机号走依赖接口，均不在本清单。
> 测试见《[测试方案.md](测试方案.md)》。主文档：[../技术方案.md](../技术方案.md)

## 一、报修包工具（本期，4 个）

| # | 工具 | 干什么 | 依赖 | Mock 顶替 |
|---|---|---|---|---|
| 1 | `get_phone` | 按查 uid → 手机号（+姓名，用于报修人默认值） | 员工手机号接口（见依赖清单 #1） | 返回写死的 13800001234 / 白云翔 |
| 2 | `get_category_dict` | 类别树 + 拍摄清单（Redis 缓存 1h，miss 回源） | 类别字典导出（依赖清单 #4） | 返回 dict_sources 示例 |
| 3 | `upload_media` | 照片/视频上传 OSS → media_id（本体不进 State） | OSS 凭证（依赖清单 二-1） | 返回 m_001 序列号 |
| 4 | `create_repair_order` | 明道云建单，**order_key=会话ID 幂等** | 明道云建单接口（依赖清单 #3） | 返回 BX-20261105-0007 |

**查询（报修记录页）**：不设独立工具，前端直连"报修单查询"接口（依赖清单 #2），服务端按用户过滤——不经过 Agent。

**门店 / 报修日期**：前端传入（POST /sessions 带门店编号）+ 服务端取当天，无工具。

## 二、统一规矩

| 类别 | 规矩 | 工具 |
|---|---|---|
| 查询类 | 只读；建会话时调一次 | #1 |
| 字典类 | Redis 缓存 1 小时、miss 回源；**回源函数是全系统唯一碰数据源的代码**，换源只改它 | #2 |
| 上传类 | 本体进 OSS，State 只存 media_id；单文件 ≤10MB、单会话 ≤5 个 | #3 |
| 提交类 | order_key=会话ID，重复调用返回同一单号；**上线前必须实测**（测试方案 §四） | #4 |
| 识别类（预留） | 云服务按次计费；结果永远当候选过闸，不直接入库 | 报销期 OCR / ASR |

全局：所有工具进程内直调（ToolProvider）；独立服务化时换 MCP 适配器，引擎零改动；每个真实实现配 Mock 顶替位，集中在 `app/skills/repair/tools.py`——**Mock 清单 = 上表右列，Mock 端到端 = 拿假数据跑通全部四个**。
