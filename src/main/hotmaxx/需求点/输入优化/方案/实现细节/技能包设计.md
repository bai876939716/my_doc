# 技能包设计（总体）

>  字段怎么采、选项从哪来、话术怎么说、单子怎么提、特殊规矩有哪些，全部是数据和规则，没有流程代码**；
> 

---

## 一、技能包是什么

五件套：

| 件 | 装什么 | 例子（报修） |
|---|---|---|
| ① 字段 schema | 每个字段的类型、必填、选项来源、校验、联动规则 | 9 个槽位的声明 |
| ② 字典源 | 枚举/树/下拉的选项从哪来、怎么缓存 | 类别字典（明道云） |
| ③ 话术模板 | 开场/追问/拉回/报错的全套文案 | 13 组 |
| ④ 工具 | 带出、上传、提交（幂等） | 4 个 |
| ⑤ 钩子 | 特殊业务规则 | 类别必点选 等 3 条 |


## 二、槽位类型系统

任何表单字段最终都归入十种类型之一，每种类型自带"怎么问、发什么卡片、过什么闸"——新业务给字段标上类型就能用：

| 类型 | 采集策略 | 卡片形态 | 报修用例 | 报销用例（推演） |
|---|---|---|---|---|
| `context` 带出 | 工具带出不问 | 状态条 | 门店/报修人/日期 | 申请编号 / 大区等只读项 |
| `enum` 枚举 | 挂 MustPick 的（类别）：Top3 必须点选（唯一例外=字面直填：原话唯一命中字典词→规则直填+复述）；低风险的：说到的直接 ai_filled，没说到才问 | 单选卡 | 报修类别 | 费用项目 / 付款公司 / 是否有发票 |
| `tree` 树筛选 | 名字 → 树匹配 Top3 路径 → 点选 | 路径确认卡 | — | 所在部门 / 一级部门 |
| `text` / `money` / `date` | LLM 抽取整理 / 格式校验 | 文本 / 键盘卡 | 故障描述 | 付款事由 / 费用金额 / 起止时间 |
| `media` 附件 | 上传 + 清单规则校验 | 拍照引导卡 | 现场照片 | 发票影像 |
| `subgroup` 字段组 / `subtable` 子表 | 逐项或整组确认 / 行卡片 | 组卡 / 行卡列表 | — | 收款人四件套 / 费用明细多行 |
| `computed` 计算 | 程序算，不问不抽 | 确认单展示 | — | 期间天数 / 大写金额 |

类型是滚雪球的资产： 算是业务沉淀

## 三、引擎读哪些声明（11-18 审计#5 之后的口径来源）

字段级（`Slot`）——采集与闸：`type / required / ask / dict_source / card / max_len / literal_fill / fill_from_text / evidence / aliases / predict / llm_writable / secret / detector / admit / display`；话术：`ask_talk`（+`_top3` / `_no_default`）、`reject_talk`、`literal_talk`；流程：`gesture`（带值手势写本槽）、`ask_on_card_path`（快捷卡与降级路径免问）、`hooks`（`MustPick / OnChange / DefaultFill / Derive / SubmitCheck`）；引导：`guide_tool / guide_from / guide_default`。

包级（`SkillDef`）——`context_tool` / `submit_tool`（TOOLS 里的函数名）、`summary_slot`（归档摘要列取哪个槽）、`boot_params`（入口参数名；`uid` 例外，它是协议键）、`open_talk`、`quick_cards`。

引擎侧不留业务名：`tests/test_neutrality.py` 两条腿把关——AST 扫 `app/core/*.py` 的字符串常量（业务词零命中，归档表两个列名长期豁免），以及拿一个与报修无一字重叠的报销假技能包跑完整趟。线上协议形状（`enum_card`、`photo_guide`、`<槽位名>_masked`、`<槽位名>_confirm`）属前端契约，去业务化不动它们。
