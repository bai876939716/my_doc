# 心屿 — 用户发一条消息的全链路解析（含真实代码路径）

> 场景：用户在 App 里给角色「祁深」发了一句话："你今天过得怎么样？"

---

## 全景总览

```
用户手机
   ↓ Hermes 长连接（非 HTTP POST）
soul-haven-short-chat-service — Hermes Sub Handler
   ↓ Rolling Flush
ShortChatRollingFlushAiOrchestrator.runAfterFlushCommitted()
   ├─ 推占位消息（status=GENERATING） → Hermes → App 显示"正在输入..."
   ├─ 异步：意图识别（是否触发星梦邀请）
   ├─ LLM 调用（阻塞等待完整响应）
   │   ShortChatWangSuRollingLlmClient.generate()
   │   → GenerateTextService.generate()
   │   → AgentRun → qwen3-max
   ├─ AI 机审 + Guardrail 过滤
   ├─ 切分为多段 + 写 DB
   ├─ 推分片消息 → Hermes → App（延时推送模拟打字机）
   └─ 旁路：publishReadyEventIfNeeded() → RocketMQ

RocketMQ → MemorySummaryProcessor.handleSummaryReadyEvent()
   → MemoryManagementHttpClient.addMemory(infer=true)
   → PolarDB（事实提取 + ADD/UPDATE/NONE）
   → 写 tb_memory_summary_task
   → 若积累 5 条 → mergeMemories（滚动合并）
   → 异步：用户画像提取
```

## 第一层：消息如何进来（Hermes 长连接，不是 HTTP POST）

**重要纠正**：短对话消息 **不走 HTTP POST** 接口，走 Hermes 长连接订阅。

```
BFF (soul-haven-web-service)
  ShortChatSessionController   → 只负责 GET 会话详情 / 置顶 / 删除
  ShortChatMessageController   → 只负责 GET 单条消息详情 / 举报
```

```
soul-haven-web-service
└── controller/shortChat/
    ├── ShortChatSessionController.java    GET /short-chat/api/v1/session/detail 等
    └── ShortChatMessageController.java    GET /short-chat/api/v1/message/detail 等
```

**用户发消息的真实路径**：App → Hermes 长连接 → `soul-haven-short-chat-service` 内的 Hermes Sub Handler → 触发 Rolling Flush。

**打字机效果的真实实现**（不是逐字符流式，是分片延时）：

```
① 占位消息（status=GENERATING） → 立即推 → App 显示"●●●"（AI 正在输入）
② LLM 返回完整文本 "今天还好啦，就是想到你可能还在熬夜..."
③ 切成 2~3 段（ShortChatAiReplySplitUtil）
④ 第 1 段 → 立即推（status=NORMAL），App 显示第一段文字
⑤ 第 2 段 → 延时 800ms 入队（ShortChatAiDelayQueueService），定时后推送
```

## 面试追问（基于真实代码）

**Q：打字机效果是流式输出吗？**

不是。LLM 调用（`GenerateTextService.generate()`）是**阻塞等待完整响应**。拿到全文后，`ShortChatAiReplySplitUtil.splitAiReplyContent()` 将文本切成 2~5 段，计算每段的 `sendTime`（加上模拟延迟），状态为 `WAITING_PUSH` 的段放入 `ShortChatAiDelayQueueService`，到时间再推。用户看到的"打字机效果"是延时分片推送，不是真·流式。

**Q：记忆总结用的触发条件是什么？**

查 `tb_soul_haven_short_chat_rolling_wait_log` 表，找 `ai_status=1`（AI 成功回复）且 `is_summarized=0`（未总结）的记录。当未总结的 Rolling 批次积累到 `triggerRoundCount`（配置值，默认 40 轮），且当前批次无对应的 `idempotencyKey` 记录，才投递 RocketMQ 事件。幂等键格式：`short_chat_summary_ready:{userId}:{saveId}:{sessionId}:{startCursor}:{endCursor}`。

**Q：占位消息是什么？**

用户消息到来后，在 LLM 调用之前，先往 DB 写一条 `status=GENERATING(1)`、`content=""` 的消息（`buildPlaceholder()` L1097），立即推给 App。App 展示"正在输入气泡"。LLM 完成后，`UPDATE` 这条消息填入真实内容，并写入真正的分片消息。若 LLM 失败，占位消息状态更新为 `FAILED(3)` 并退款。
