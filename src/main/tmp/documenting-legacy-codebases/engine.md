# 采集图引擎

描述对象:app/core/engine.py(降级协同 app/core/degrade.py)。

引擎是一张 LangGraph 状态图:业务差异全部由技能包声明注入,引擎只认协议形状。全流程只有 extract 一个节点调 LLM;点选轮零 LLM。图没有用 interrupt 挂起:「等用户确认」是黑板上的数据(confirm_pending 标记位),不是控制流。每个节点返回局部更新:槽位、议程、meta 整体覆盖(先拷贝再改),消息走按序号合并的 reducer。

## 节点与路由

八个节点,两条路由规则:

- intake(恒为入口):把用户手势落档为 role=user 消息(审计、指标、前端回放的唯一依据);建会话轮与内部 submit 手势不落档。
- 入口路由:intake 之后按 incoming 类型分流。context 为空是建会话轮,去 load_context;type=submit 去 submit(只有 /submit 接口能注入这个内部手势);type=text 去 extract;其余(点卡、点选、上传、带值手势)去 update。
- load_context(建会话轮):调技能包声明的带出工具,初始化全部槽位与议程,下发首屏三件套(状态条、开场白、快捷卡),本轮即结束。
- extract(打字轮):先问降级判定(fallback 粘性模式或会话配额耗尽则整轮委托规则脑),否则调一次 LLM 联合抽取,产出意图加字段增量加枚举候选,落黑板。
- update:写侧核心。结构化手势走各自处理器(卡片直填、点选过字典白名单、附件合并去重、带值手势按槽位声明认领);打字轮按意图分三条管线(边界、update、provide),全部过闸门后才写槽。
- update 后路由(不变量:每轮以下一个待办收尾):挂起未解除则直接收尾;update 意图在挂起时同样直接收尾;议程空了去 confirm(重发确认单),不空去 ask(发下一个问题);边界轮连续次数达阈值去 fallback。
- ask:议程首项按槽位声明的卡片形态发问(文本纯文字、附件带引导卡、枚举分 Top3 卡、分组卡、平铺卡、确认默认值卡五种形态);发新问题即回到采集态。
- confirm:先跑 DefaultFill 钩子(条件成立且空值时填系统默认),组确认单下发,置 confirm_pending。
- submit:幂等守卫(出过单原号返回)加全量重校验(必填、字典、长度、识别器、附件数)加包级 SubmitCheck,全过才调建单工具;失败保留确认单可重试。
- fallback:降级为卡片向导,零 LLM,描述槽免问,点完照样走到确认与提交。

## 六道闸门(打字值准入)

引擎对模型产出的每个字段值按槽位声明的闸序逐道检查,任何一道不过就不落库:长度(truncate 截断放行或 len 拒收)、字典白名单(enum)、识别器全匹配(detector)、原话印证(attest:系统正问这个字段、或值的原词出现在用户原话里、或用户点名了字段、或命中证据词;四者其一才算数,防模型替用户拍板)。字段白名单由槽位的 llm_writable 声明拼出:不在白名单的增量直接丢弃。意图白名单之外的意图一律按闲聊处理。

另有一条零 LLM 的字面直填通道(literal_fill):用户原话唯一命中某字典槽的选项词时直接入槽并复述;多命中(真两义)或没命中(纯推断)照旧发卡。

## 失败与降级

降级判定只有两个来源:会话已进入 fallback 粘性模式,或本会话 LLM 调用数达到配额。降级轮交给规则脑:有确定性识别器的字段照常听懂(原话点名字段或正等这个值时,识别器命中即可写);听不懂就明说并拉回,连续边界轮计数加一。点选轮永远不受降级影响。LLM 网关自身失败两次也按边界轮兜底,交给同一套计数,连败到阈值进 fallback。

## OnChange 钩子

槽位改值时(首填不触发):声明的 invalidates 槽位清值并塞回议程(重问);reset_defaults 只清系统派生值(用户写的保留,确认时按新值重算);hints 只提示自查不作废。被作废与被提示都会以系统提示对用户明说。

## 已知边界(代码内自认的债)

运行参数直读全局配置而非由技能包注入(代码注释标了待办);一轮只处理首个修改目标,多目标复合修改要等状态机扩展;这些都是行为现状,不是承诺。
