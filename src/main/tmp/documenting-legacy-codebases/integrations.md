# 外部集成

描述对象:app/core/llm.py、mingdao.py、employee_client.py、store_client.py、nacos.py、pgstore.py。

五个外部系统,全部为出站调用(服务不监听任何外部回连)。

## 百炼大模型(LLM)

方向:出站 HTTPS(OpenAI 兼容端点,温度零、关思考链、超时三十秒、自控重试一次)。用途:打字轮的联合抽取(意图、字段增量、枚举候选、应和半句)。失败行为:两次失败按边界轮兜底,计入连续失败,连败进降级向导;会话级配额超限后整轮不再调用。唯一性:全流程唯一调模型点,换模型只改网关子类。

## 明道云(HAP v3 开放接口)

方向:出站 HTTPS,固定头鉴权(Appkey 加 Sign,静态凭据非动态签名)。协议怪癖(实测结论,代码注释记档):响应恒 HTTP 200,成败看 body 的 success 与 error_code;超时按阶段拆(连接十五秒兜慢握手,实测首连可达六点八秒)。

四个用途:建单(新建行,是否触发派单工作流可配)、单号回查(建单后回读自动编号,失败用行 id 兜底)、分类字典真值(翻页拉全量分类表组树,进程内 TTL 一小时、后台刷新、失败退旧值)、大区字典(拉报修表结构读 Dropdown 内嵌选项)。失败行为:建单业务失败回错误码、保留确认单可重试;字典回源失败退最近成功值或静态兜底,绝不静默清空。附件:前端先直传明道云,服务端只存 name 加 url 引用,建单时原样写入(旧 media_ids 协议已删除)。

## base-shop 主数据(内网 Java 服务)

方向:出站 HTTP,内网直调无鉴权(同 Java 间调用惯例),超时五秒。三个端点:门店信息按编号查、门店大区(父组织名)按编号查、员工档案按员工 ID 查(X-Uid 即员工 ID;接口是 POST 但参数走 query string,无请求体)。失败行为:未配置(地址空)全退 Mock 演示值;已配置但查无或异常,门店退占位名、报修人退空、手机号退空,不拿 Mock 冒充,不挡报修流程。

## Nacos 配置中心

方向:出站 gRPC(需通 8848 与 9848 两端口)。用途:启动时读一份扁平 YAML 注入配置(不覆盖已有环境变量),支持 MSE 鉴权或用户名密码鉴权。失败行为:启用状态下连不上或内容不合法,启动直接拒绝(fail-fast,不静默跳过)。

## PostgreSQL

方向:出站,psycopg 连接池(一至十连接,autocommit、关预编译语句防池化串台)。用途:检查点(langgraph 框架管理)、活跃索引、终态归档(见 data-model.md)。失败行为:启动时未连上不阻止进程起,就绪探针保持 503 不接流量,转绿时建表并启动清理线程;运行中池异常由未处理异常兜底统一 503。

## 信任边界

服务自身零鉴权,身份完全信任 X-Uid 头;该头必须由网关/转发层以认证结果替换注入,绝不能透传客户端可伪造的值(接口层已强制:缺失一律 401)。手机号对外只出掩码(唯一实现在掩码模块),明文只存在于服务端黑板与明道云建单写入。
