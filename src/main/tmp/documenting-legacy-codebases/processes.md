# 端到端业务过程

描述对象:一次报修会话跨 api 层、引擎、技能包、外部系统的完整流转。图源在 diagrams/ 目录(文本即源,渲染是派生物);仓库自带两份引擎结构图(diagrams/ 目录),本页补的是跨层时序与状态视角。

## 过程一:首次报修(打字路径,典型全程)

前端带门店编号调建会话;网关注入的 X-Uid 过身份闸;注册表在同一人同店的活跃索引里查不到,生成随机会话 id、登记索引、注入建会话轮;引擎调带出工具(uid 查员工档案、门店编号查门店主数据与大区),初始化七个槽位与议程(故障情况、报修类别、现场照片、联系电话四项),下发首屏三件套。用户打字描述故障:入口校验后落档,extract 调一次 LLM(流程状态一行加脱敏后的槽位快照加三引号包裹的原话),产出意图 provide 加故障描述增量;过闸(长度或截断、原话印证)写入,复述已填字段;下一待办是类别:模型有候选就发 Top3 卡(永不自动入槽),没把握发全量卡。用户点选类别:零 LLM,过字典白名单直接写入,OnChange 清掉系统默认描述并按需提示照片;接着问照片(拍摄清单按类别挑),前端直传明道云后回传附件引用,合并去重校验上限后写入;最后问电话:档案有可用默认号就发一键确认卡,没有就开口要(裸号码过识别器加原话印证双闸)。议程清空,confirm 组确认单(手机号全程掩码)。用户点提交:引擎全量重校验加包级校验(照片至少一张),调建单工具(幂等四元组缓存、按 rowId/key 反查写入明道云、回查单号),出结果卡;接口层归档、清活跃索引;重进即新单。见 diagrams/sequence-first-repair.mermaid。

## 过程二:快捷卡路径(最快全程)

用户开场直接点「冷柜不制冷」:卡片值直填类别、切卡片路径分支(描述槽免问,确认时由默认描述兜底:类别短名加「详见现场照片」);剩照片与电话两问,点选上传零 LLM,全程可零次模型调用走到确认提交。

## 过程三:确认态改值

确认单上用户打字「电话改成 139…」:模型判 update 只报该字段;识别器闸加挂起解除;复述已更新,确认单静默重挂(不再念「信息齐了」)。只点名不给值(「改下类别」)则轻量挂起:本轮以追问收尾,下一轮裸值按挂起目标消解。任何成功写入即解除挂起。

## 过程四:降级与兜底

连续跑题或识别失败累计到阈值,或会话 LLM 配额耗尽:切换卡片向导(描述槽免问、议程里可点选的照发),此后打字轮交给规则脑(有确定性识别器的字段照常听懂),零模型调用照样能走完确认与提交;配额与降级的拉回话术在确认态有专门变体(对着确认单指路而不是对着待办卡)。

## 会话状态机(对外口径)

外部可见四态:collecting(议程非空,最后一屏是当前问题卡)→ confirm(确认单展示中)→ done(已出单,锁死);任意采集/确认时刻可进 fallback(向导接管,议程清空后仍回 confirm)。内部不变量:每轮以下一个待办收尾,用户绕多远的路都不会迷路。见 diagrams/state-session.mermaid。
